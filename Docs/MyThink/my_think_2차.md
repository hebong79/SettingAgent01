\*\* 기존방식(1번 시뮬레이터 방식) \*\*



1\. 시뮬레이터에서 주차장을 구현한다.

2\. 시뮬레이터에서 바닥면 ROI를 생성한다.

3\. SettingAgent에서 floor\_ROI 로딩한다.

4\. 바닥면 3D 육면체 생성, 육면체 앞면 중앙을 설정한다.

5\. 주차면 전체 LPD를 이용 번호판 Box를 생성( + 점유영역 생성)

6\. 번호판 박스 중심으로 센터라이징을 한다.

7\. SQLite DB와 보관 및 Setup\_Result. json 생성.

&#x20;  → 이때 ROI 매핑이 의미가 없다. 시뮬레이터에서 미리 만든다.



\*\* 새로운 방식 - 리얼카메라 + 시뮬레이터(언리얼) \*\*

\* 핵심 : 주차면위의 차량을 마우스로 클릭하여 차량의 3D육면체를 생성.

&#x20; - 3D육면체 바닥면을 기준으로 주차면을 생성한다.



1\. 프리셋을 먼제 웹 UI에서 생성(메모리에 보관)하고 

&#x20; - 프리셋은 카메라에서 물리적으로 생성하지 않고 프로그램적(ptz좌표로만 이동)으로만 생성한다.

2\. 차량을 마우스로 클릭하여 3D육면체를 생성

&#x20; - 주차면 인덱스도 생성하여 리스트에 추가한다.

3\. 3D육면체 바닥면을 기준으로 주차면을 생성한다. 

&#x20; - 2D ROI생성 + 3D 육면체 정보도 저장

4\. 전체 슬롯id 기준으로 주차면 매핑을 해야 한다.  

&#x20; - slot\_id, cam\_id, preset\_id, preset\_slotidx

5\.  주차면 육면체 활성 

&#x20; - 차량의 육면체 이므로 정확하지는 않다. 

&#x20; - 2.5 \* 5m( 도로는 2 \* 6m) 바닥 주차면에 맞춰야 한다. ( 3D 시뮬레이터의 경우 )

&#x20; - 시작점 주차면을 그려주면 나머지는 갯수에 맞게 자동으로 그린다. (loop 학습후 결정론적으로 그리기)

6\. 점유역역은 차량 3D육면체가 점유영역이다. 

6\. LPD 번호판 검출

7\. 번호판 중심으로 센터라이징을 한다.

8\. SQLite DB와 보관 및 Setup\_Result. json 생성.
