## 1. 왜 만들었나 — 리더의 누락 인정 (핵심)

마스터 지적: **"처음 ROI는 수동으로 그리는 방법이 없다. 그래서 미리보기를 클릭할 수 없다."**

리더는 이 세션 첫 질문에서 이미 "시뮬레이터가 강제로 바닥 주차면을 그려 JSON에 저장한다"는 사실을 들었음에도,
**quad(사다리꼴)가 이미 존재한다는 전제 위에만** 직전 L3 작업(정면 1개 자동생성 + 지면격자 확산)을 두 라운드
쌓았다. **"주차면 1개만 손으로 그리면 된다"는 L3의 출발점이 실제로 가능한지 한 번도 검증하지 않았다.**

리더가 직접 실증한 결과, `web/index.html`의 `place-*` 버튼 전수(`delete`/`edit`/`gidx`/`msg`/`open`/`save`)에
`add`·`draw`가 **없었고**, `web/app.js`의 캔버스 드래그 kind 6종(`detResize`/`detMove`/`detVertex`/
`vpdResize`/`vpdMove`/`floorVertex`) 중 파일 ROI(`state.placeRoi` = PtzCamRoi.json의 `parking_spaces`)를
**생성**하는 것은 0개였다.

결론: **L3는 Unity 시뮬레이터에서만 동작한다**(시뮬레이터가 파일을 대신 써주므로). 리얼카메라·신규
주차장에서는 목록이 비어 → 선택 불가 → 미리보기 불가 → 전 기능 도달 불가. 자동화 실패 시의 안전망으로
설계한 "수동 1개 그리기"가 정작 리얼 환경에 없었다. 이번 작업은 그 공백을 메운다.

## 6. 발견·수정된 결함

### D-1(중) — 파일 존재 + 대상 cam/preset 부재 → 저장 영구 불가 (수정 완료)
**원인**: `create` 첨부 조건이 `state.placeRoiFileMissing`(GET이 404) **하나뿐**이었다. 파일이 존재하면
이 값이 항상 `false`라, 파일에 없는 cam/preset(주차면 0개인 기존 파일, 또는 `data/Place01`의 cam2:p3 같은
신규 프리셋)에는 골격이 영원히 안 붙었다 — **현재 운영 데이터에서도 실제로 막히는 시나리오였다.**

**수정**: 판정 근거를 "404 하나"에서 "파일에 그 키가 실재하는가"(`state.placeRoiFileKeys`, `loadPlaceRoi`에서
스냅샷)로 옮기고, 골격 없이 보낸 요청이 `applied:false`로 오면 **1회만** 재시도(루프 없음, 테스트로 봉인)한다.
회귀 방지: 골격은 `needsPlaceSkeleton(key)`가 참일 때만 만들어 붙이므로, **파일에서 이미 로드된 키에는
붙지 않는다** — 기존 저장 경로(자동보정·목록 편집)에 "라이브 미시작 시 저장 거부"라는 새 실패 조건이 생기지 않는다.

**실행 원문 재확인**(QA 수정 라운드, in-process 서버): `{"cameras":[]}`에서 cam1:p1 저장 시
`create` 없음 → `applied:false`/파일 무변경, `create` 첨부 → `applied:true` + 파일에 카메라/프리셋/PTZ
3종 + 면 1개 실제 기록. 이어서 cam1:p3(기존 카메라 + 새 프리셋)도 성공.

**구현자 자기 정정**(태도 기록): D-1 재현 시나리오를 처음 돌렸을 때 전부 `f²≤0`으로 실패했으나, 원인은
**구현자 자신의 테스트 러너 설정에 `minDepthEdgePx` 등이 누락**된 것이었고 제품 결함이 아니었다. 실제
값(`minDepthEdgePx:250` 등)으로 맞추자 정상 성공했다. 잘못된 중간 관측으로 R2(원근 사다리꼴 한계)를
확대 주장하지 않기 위해 경위를 그대로 남겼다.
