## 2. ① 실측 — 인계서 §0-1 의 전제가 틀렸다

### 2-1. PI 정밀도 붕괴는 분산이 아니라 `2:1` 한 프리셋 집중

| 프리셋 | 재현(EB) | 재현(PI) | 정밀도(PI) | quad(PI) |
|---|---|---|---|---|
| 1:1 | 7/10 | 7/10 | 0.7000 | 10 |
| 1:2 | 8/14 | **11/14 ↑** | 0.9167 | 12 |
| 1:3 | 0/2 | 0/2 | — | 0 |
| **2:1** | 6/7 | 6/7 | **0.2857** | **21 (거짓 15)** |
| 2:2 | 3/8 | **0/8 ↓** | — | ~3 |

전체 재현율 24/41 은 **동일하지만 구성이 바뀐다**(1:2 +3, 2:2 −3). 거짓 22개 중 **15개가 `2:1` 단독**.

### 2-2. ★ 붕괴 메커니즘 = `refScore` 기준선 이동

`rows` 게이트는 `paint.score >= refScore * 0.94` 이고 `refScore` = **baseScore argmax 후보의 `paint.score`**(`bayGrid.ts:682-699`). 분모를 PI 로 바꾸면 그 argmax 가 **진짜 행 → 가짜 행**으로 옮겨간다.

| 프리셋 | refScore(EB) | refScore(PI) | 문턱 EB→PI |
|---|---|---|---|
| 1:1 | 1.55850 (ci=0, **진짜 7/7**) | 1.61270 (ci=6, **가짜 0/3**, depth **99.31m**) | 1.46499 → 1.51594 |
| **2:1** | **1.40079 (ci=0, 진짜 6/6)** | **1.02679 (ci=5, 가짜 0/4)** | **1.31674 → 0.96518 (−27%)** |
| 2:2 | 0.97460 (ci=1, 진짜 3/3) | 1.26071 (ci=6, **가짜 0/2**) | 0.91612 → 1.18507 |

`2:1` 은 문턱이 27% 내려앉아 가짜 6개가 한꺼번에 통과하고, `2:2` 는 반대로 문턱이 올라 **진짜 3/3 이 비율탈락**한다(재현율 3→0).

**→ 인계서 §0-1 의 「상대비 참 0.7164 < 잡음 0.7238 이라 원리적으로 판별 불가」는 분자·분모가 둘 다 움직이는 값을 비교한 것이었다.** 상대비가 판별 불가인 게 아니라 **기준선이 후보 의존이라 문턱 자체가 이동**한다.

### 2-3. ★ 진짜 행의 `paint.score` 는 분모에 비트 불변, 가짜만 부푼다

`2:1`(프레임 `e33628e921c2` 동일):

| ci | 라벨 | quads EB→PI | paint.score EB→PI |
|---|---|---|---|
| 0 | 진짜 6/6 | 6→6 | **1.40079 → 1.40079 (비트 동일)** |
| 4 | 진짜 6/6 | 6→6 | **1.35754 → 1.35754 (비트 동일)** |

## 3. ★★ 마스터 지적의 코드 검증 — **현재는 개별 독립이 아니다**

> 마스터: *"현재 주차면 한개 한개 독립적으로 만드는게 맞는지 확인해줘. 결과 이미지는 주차면 1개생성하고 임의의 갯수를 한번에 만드것 같다. 근본이 흔들리면 안된다."*

`bayGrid.ts:219-247` `buildAtPhase`:
```ts
const w = opts.slotWidthM;      // 규격 폭 2.5m
const depth = opts.slotDepthM;  // 규격 깊이(단일값)
for (let k = kFrom; k <= kTo + 1; k++) {
  const a = phase + k * w;                                   // ← 등간격 복제
  near.push(projectToPixel(pointAt(fr, a, 0), model));
  far .push(projectToPixel(pointAt(fr, a, depth), model));
}
```

실제 동작:
1. **근변선(front line) 하나**를 고른다 — 행 전체의 기준
2. 그 선 위에 **규격폭 2.5m 등간격 격자**를 `phase` 하나만 맞춰 깐다
3. **깊이도 규격 단일값**을 전 칸에 동일 적용
4. 도색 지지 있는 칸을 남기되, **내부 구멍은 증거 없이 보간해 채운다**(`filledIndices`, `bayGrid.ts:385-390`)

**→ 마스터 관측이 정확하다.** 자유도는 `front line` + `phase` + `run 범위` **셋뿐**이고, 개별 면은 자기 폭·자기 깊이·자기 각도를 갖지 못한다.

**정정 1건**: 「임의 갯수를 한번에」는 **21회차에 이미 빠졌다**(`rowExtentMode:'evidence'`, `bayGrid.ts:365-398`). 칸 수는 도색 증거가 정한다. 남은 문제는 **개수가 아니라 형상 복제**다.

**정직하게 남길 사실**: 21회차 Phase 0 에서 **개별 독립(A안 — 분리선 쌍으로 면 닫기)을 측정으로 기각**했다(정밀도 상한 0.35~0.46 · 재현율 상한 0.39~0.56, 원인은 **행당 오검출 분리선 32개**). 즉 현재 코드는 *"개별 독립이 옳지만 아직 못 만든 것"* 이 아니라 ***"개별 독립을 시도했다가 측정으로 되돌린 상태"*** 다.

### ★★ 오염 함정 (설계 제약으로 못 박음)

| 필드 | 검출 경로 사용 | 사유 |
|---|---|---|
| `faceSlot` · `presetId` | **금지 — 채점 전용(R1)** | 「이 차는 몇 번 면에 있다」는 **정답지**. 쓰면 18회차 「`expectedBays` 가 정답지에서 왔다」와 같은 오염 |
| `pos`(월드 3D) | **직접 사용 금지** | 실카에는 없다. 실카 차량검출은 **이미지 박스**만 준다 → 시뮬 전용 치트가 되고 마스터의 *"실카도 동일 조건"* 지시 위반 |
| `visible` | **판단 필요** | Unity 가 가림을 판정해 준 값 — 공짜로 얻는 셈 |
| `rotY` · `prefabId` 치수 | 강등 후 사용 가능 | 투영해 이미지 박스로 만든 뒤 그 박스만 검출에 넘긴다 |

**설계 원칙**: 실카에서 실제로 얻는 형태(이미지 박스 + LPD)를 **인터페이스로 먼저 정하고**, 시뮬 `car.list` 는 **그 형태로 강등**해서 공급한다. 강등 투영은 `projectTruth`(`sceneTruth.ts`)와 동형이므로 재발명하지 않는다.

**따라서 착수 전 상한은 두 갈래로 재야 한다**: ⓑ-1 **오라클 상한**(`faceSlot` 까지 사용 — 도달 불가 천장, 참고용) vs ⓑ-2 **전이 가능 상한**(이미지 박스 + 방위만 — **진짜 목표선**). 둘이 크게 벌어지면 차량 증거는 「시뮬에서만 되는 것」이고 그 사실이 결론이다.

## 7-c. ★★ 격자 폐기는 정책 순응이 아니라 **산술 결과**다

설계자 개정안(`docs/20260730_180519_...설계.md` 「【개정 R2】」)의 핵심 계산. A안이 기각된 진짜 이유는 정확도가 아니라 **면 1개당 필요한 독립 관측 수**였다:

| 방식 | 면 1개당 필요 관측 | 성공률 | 뷰 A 실측(p=0.769) |
|---|---|---|---|
| A안(분리선 **쌍**) | 2개 | `p²` | 4~5/10 |
| 격자(위상 1개) | 1개(**행당**) | `p` | 6/10 |
| **경계 1개 + 규격 폭** | **1개(좌·우 아무거나)** | **`1−(1−p)²`** | **0.9467** |

**규격 치수로 닫기가 허용된 순간, 격자가 제공하던 유일한 구조적 이점(`p²` 회피)이 격자 없이 더 잘 얻어진다.** 좌·우 둘 중 하나만 있으면 닫히므로 격자보다도 높다.
→ **격자의 잔여 자리는 없다. 폐기한다.** 「채점용 관계 prior」로 남기는 것도 하지 않는다 — 등간격 정렬에 가점을 주면 「이웃이 붙어야 내가 산다」가 되어 **복제의 부드러운 형태**가 된다(21회차가 같은 이유로 행 조각 자동병합을 거부한 선례). 기존 `bayGrid.ts` 는 `engine:'lattice'` **회귀 전용**으로 보존하되 산출 경로에서 제외한다.

## 7-d. 완전 개별 알고리즘 2안 (상보 관계 — 경쟁 아님)

**안 1 — 경계앵커 닫기**(권고): 분리선 1개 → 좌/우로 닫아 면 후보(×v방향 2). **인덱스·위상·창 없음.**
- **판별의 급소 = 「예측변 도색지지」** — 두 변 중 하나는 관측(자기충족), **다른 하나는 규격 폭으로 예측**되므로 예측변만 채점하면 **순수 검증량**이다. A안은 둘 다 관측이라 정보가 0 이고, 격자는 둘 다 예측이라 구분이 없다. 참 경계에서 2.5m 떨어진 곳엔 다음 참 경계(도색)가 있지만, **차체 모서리에서 2.5m 엔 도색이 있을 이유가 없다.**
- **★ 사전 반증(정량)**: 규격 닫기 허용은 A안의 유일한 기하 필터를 없앤다. 골든 분리선 384개 × 2 × 2 = **후보 1536개**. 정밀도 0.70 이려면 총산출 ≤58 → **생존율 3.8% 이하(26배 필터)** 가 필요. 못 거르면 정밀도 **~0.09**. **이게 안 1 의 생사다.**

**안 2 — 차량앵커 닫기**: 차량 1대 → 접지 → 면 1개. 구조적으로 이미 개별 독립이고 후보 수가 `O(차량 수)`(씬 24대)라 자릿수가 다르다. 표적은 **가림 13면**(재현율 천장 28/41 돌파의 유일 경로). 차량 3경로는 접지 정확도순 **세그 &gt; LPD &gt; VPD**(VPD 박스는 방위를 안 줘 반칸 어긋남 위험이 크다), 도입 비용은 역순.

**안 1 = 빈 면·도색 선명 / 안 2 = 점유·가림** — 두 안이 서로의 사각을 덮는다. 예비 안 3(면 템플릿 슬라이딩)은 「격자 없는 격자」 위험이 커서 둘 다 탈락 시에만.
