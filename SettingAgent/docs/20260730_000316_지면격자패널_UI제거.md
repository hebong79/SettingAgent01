# 지면 격자(자동 바닥 ROI) 패널 — 뷰어 UI 제거

- 날짜: 2026-07-30
- 브랜치/워크트리: `worktree-remove-groundgrid-ui` (`.claude/worktrees/remove-groundgrid-ui`)
- 요청: 마스터 — "이미지의 부분을 UI에서 제거해줘" + "다른 곳에 영향을 미치는지 조사"
- 범위: **뷰어(web/) UI 만**. 서버·MCP·RPC·DB 경로는 1줄도 건드리지 않았다.

---

## 1. 무엇을 제거했나

| 파일 | 제거 내용 |
|------|-----------|
| `web/index.html` | `<section>` "지면 격자 (자동 바닥 ROI)" 전체(안내문·열/행/열시작 입력·미리보기·결과 확인함·승인 후 적용·`#gg-msg`·`#gg-table`)와 그 위 설계 주석. 상단 오버레이 토글 **`#roi-auto` (자동ROI)** |
| `web/app.js` | `setGgMsg` · `setGgGate` · `ggRefSpace` · `renderGgSelectionInfo` · `ggBody` · `renderGgTable` · `ggPreview` · `ggApply` · `drawAutoRoi`, 상태 `state.autoRoi`, `drawRoiOverlay` 의 `drawAutoRoi(ctx)` 호출, `bindEvents` 의 `gg-preview/gg-apply/gg-confirm/roi-auto` 리스너 4개, `renderPlaceSelectionInfo` 안의 `renderGgSelectionInfo()` 동기화 호출 2곳 |
| `web/app.css` | `.gg-warn`(게이트 경고 강조), `.gg-help`(패널 안내문). `.an-manual-help` 는 단독 선택자로 남김 |
| `test/groundGridPanelUi.test.ts` | 패널 UX 봉인 테스트(무반응 게이트·승인 문구)를 폐기하고 **제거 회귀 가드**로 재작성 |

### `#roi-auto` 토글을 같이 뺀 이유
`state.autoRoi` 를 채우는 유일한 경로가 `ggPreview`(패널의 미리보기)였다. 패널이 사라지면 이 토글은
**켜도 영원히 아무것도 그리지 않는 죽은 체크박스**가 된다. 내 변경으로 고아가 된 코드라 함께 제거했다
(기존 데드코드 정리가 아니라 이번 변경의 직접 파생분).

## 2. 남긴 것 (의도적)

- **서버 라우트 그대로**: `POST /capture/ground-grid/bootstrap` · `POST /capture/ground-grid/apply` · `GET /capture/ground-grid`
  (`src/api/groundGridRoutes.ts`, `src/ground/*`) — 삭제하지 않았다.
- **RPC/MCP 그대로**: `src/rpc/methods.ts` 의 격자 메서드 3종(bootstrap/apply/조회)과 `src/rpc/services/roiAuto.ts`.
  → 자동 바닥 ROI 생성은 **에이전트(MCP)에서는 여전히 가능**하고, 사람이 쓰는 화면에서만 사라졌다.
- `PtzCamRoi_auto.json` · `ground_grid.json` · 백업(`.bak`) 규약, `POST /capture/slots/load-roi`(‘ROI 파일 로딩’ 버튼) 전부 불변.

## 3. 영향도 분석 (다른 곳에 미치는 영향)

### 3-1. 영향 없음이 확인된 곳

| 대상 | 판정 근거 |
|------|-----------|
| 서버/DB/MCP | `web/` 밖 파일 변경 0. `replaceSlotSetup` 호출자 3곳(`capture/Finalizer.ts`·`capture/roiDbLoad.ts`·`tools/migrateToSettingDb.ts`) 불변 — 테스트로 봉인 |
| 끊긴 DOM 참조 | `web/*.js` 의 모든 `$('id')` 를 `index.html` id 집합과 대조 → **없는 id 0개**(main 기준선과 동일). 초기화 시 `null.addEventListener` 류 사고 없음 |
| 다른 오버레이 | `drawRoiOverlay` 에서 `drawAutoRoi` 한 줄만 빠짐. 점유·파일ROI·검출·그리기·육면체·차량육면체·마스크 순서 그대로 |
| 주차면 선택 사슬 | `renderPlaceSelectionInfo` 는 패널 동기화 호출만 빠지고 선택·삭제버튼 동작 동일. `placeDrawWiring`(40 tests)·`viewerDisplayReset`·`dbViewSourceSwitch`·`manualTableMarkup` 전부 green |
| `.an-manual-help` | `manualTableMarkup.test.ts`(‘첫 번째 .an-manual-help’ 봉인) green — 선택자 분리 해제해도 규칙 유지 |
| `roimaker.js` | 지면격자 언급은 주석 1줄뿐(동작 무관) |

### 3-2. 사용자에게 남는 변화(알아야 할 것)

1. **사람이 UI 로 자동 ROI 를 만들 수단이 없다.** 주차면 자동 생성은 이제 MCP/RPC(에이전트) 경로 전용이다.
   화면에서는 ‘면 그리기’(캔버스 4점) 수동 경로만 남는다.
2. 프리셋 저장 시 나오는 경고 문구 중 **"…지면격자 미리보기가 실패합니다(프리셋 PTZ 확인)"**(app.js `savePresets` 계열)와
   주차면 검증 실패 문구 **"…지면격자에서 거부될 수 있습니다"** 는 **그대로 뒀다** — 가리키는 대상이 서버 게이트라
   여전히 참이지만, 화면에 미리보기 버튼이 없으므로 사람이 즉시 취할 행동이 없는 문구다. 문구 정리를 원하면 별도 요청 바람.
3. 되돌리려면: 이 브랜치의 diff 를 revert 하면 패널·토글·전용 렌더가 그대로 복원된다(서버는 애초에 안 건드렸으므로 즉시 재작동).

## 4. 검증

| 항목 | 결과 |
|------|------|
| `npx tsc -p tsconfig.json --noEmit` | 오류 0 |
| `node --check web/app.js` | 파싱 OK |

| `vitest run` 전체 | **3442 passed / 2 failed** — 실패 2건은 아래 사유로 **이번 변경과 무관** |
| UI 관련 파일 5종 재실행 | 69 passed |

### 실패 2건의 정체(정직 보고)
`test/placeRoiRuntimeInvariants.test.ts`, `test/roiDbLoad.test.ts` — 둘 다 **런타임 데이터 파일**
`data/Place01/PtzCamRoi.json` 을 직접 읽는다. 워크트리는 HEAD 커밋본을 체크아웃하는데, **커밋된 그 파일에는
`points: []`(빈 4점) 주차면이 들어 있다.** 마스터의 main 작업트리에는 그 파일이 미커밋 수정 상태(정상값)라
같은 두 테스트가 main 에서는 통과한다(실측 확인).
→ 코드 결함이 아니라 **커밋된 운영 데이터의 상태 문제**다. 필요하면 main 의 현재 `PtzCamRoi.json` 을 커밋해
기준선을 맞추면 워크트리에서도 통과한다.

### 하지 못한 검증
헤드리스 브라우저(puppeteer/playwright)·jsdom 이 이 저장소에 없어 **실제 브라우저에서 화면을 띄운 확인은 못 했다.**
대신 이 저장소의 관례대로 소스텍스트 봉인 테스트 + DOM 참조 대조로 갈음했다. 마스터가 뷰어를 새로고침해
① 패널이 사라졌고 ② 상단 토글에 ‘자동ROI’ 가 없고 ③ 콘솔 에러가 없음을 한 번 봐주면 완결된다.

## 5. 메인(main) 작업트리 적용 — 화면에 실제로 반영한 절차

마스터 실측: "갱신해도 메인에서는 보이지 않는다". 원인은 **뷰어 서버가 main 체크아웃의 `web/` 을 서빙**하는데
제거는 워크트리 브랜치에만 있었기 때문이다. 게다가 main 작업트리에는 **미커밋 WIP(도색선 자동검출 패널,
`autoPaint.js`·`#roi-autopaint`·`ap-*`)** 이 같은 3개 파일에 얹혀 있어 `git merge` 는 쓸 수 없었다
(HEAD 는 같은 `ae704d4` 라 ff 대상이지만, 작업트리 미커밋 변경을 덮어쓰게 된다).

적용 방법: 브랜치 diff 를 `git apply --3way` 로 얹고 충돌 4곳을 **WIP 를 살리는 쪽**으로 손수 해소했다.

| 충돌 지점 | 해소 |
|-----------|------|
| `state.autoRoi` / `state.autoPaint` 선언 | autoRoi 삭제 · autoPaint 유지 |
| `drawRoiOverlay` 의 `drawAutoRoi`/`drawAutoPaint` 호출 | drawAutoRoi 삭제 · drawAutoPaint 유지 |
| `drawAutoRoi` ↔ `drawAutoPaint` 함수 인접 | drawAutoRoi 함수만 삭제 |
| 토글 배선 · 패널 배선 | `roi-auto`/`gg-*` 배선만 삭제 · `roi-autopaint`/`ap-*` 배선 유지 |

WIP 쪽에 남은 부수 정리(내 제거로 문장이 거짓이 되는 것만):
- `.gg-help` 는 **삭제하지 않았다** — 도색선 패널 안내문이 이 클래스를 쓰고 있다. 주석만 '패널 안내문 공용'으로 고쳤다.
  (`.gg-warn` 은 쓰는 곳이 없어져 삭제)
- 도색선 패널 주석·안내문의 "위 '지면 격자' 와는 근거가 다르다", "격자 자동 주황과 구분" → 격자 언급 제거
- `autoPaint` 코드의 `// ggPreview 의 roi-auto 규약과 동일` 주석 → 규약 문장으로 대체

**main 작업트리는 커밋하지 않았다** — 마스터/다른 세션의 도색선 WIP 가 같은 파일에 섞여 있어 내가 임의로 커밋하면
그 WIP 까지 함께 들어간다. 커밋 시점·범위는 마스터가 정한다. 깨끗한 이력은 브랜치(`worktree-remove-groundgrid-ui`)에 있다.

검증(main 체크아웃): `npx vitest run` → **287 files / 3651 tests 전부 통과**(도색선 WIP 테스트 포함),
`node --check web/app.js` OK, DOM 참조 대조 0건.
정적 서빙은 `Cache-Control: no-store`(viewer/routes.ts) 이므로 **서버 재시작 없이 새로고침만으로** 반영된다.
