# 부트스트랩 주차면 자동화 — "첫 번째 사각형"도 손으로 안 그리기

작성일: 2026-07-27
선행 문서: `20260727_202948_자동_바닥ROI_생성_설계.md`
질문: **"수동으로 하는 첫 주차면도 자동으로 못 그리나? (차량 3D 육면체 / 노면 도색선 / 차량크기+선 조합)"**

---

## 0. 문제를 다시 정의하면 — 필요한 건 "사각형"이 아니라 **스칼라 1개**

선행 문서에서 부트스트랩에 필요한 값은 `f, n, d` 였다. 그런데 이미 두 개는 드로잉 없이 나온다:

| 값 | 출처 | 드로잉 필요? |
|---|---|---|
| `f` (초점거리) | `focalFromZoom(zoom, fovBaseV)` — `fovBaseV` 는 `packages/lens-calib` 산출 | ❌ 불필요 |
| `n` (지면 법선) | PTZ tilt → `n = [0, cos t, sin t]` (`groundModel.ts:505` 의 역) | ❌ 불필요 |
| **`d` (카메라 지상고)** | ??? | ⚠️ **이것 하나만 남는다** |

**즉 "첫 주차면 그리기"의 실체는 미터 스케일 1개를 정하는 것이다.**
사각형 4점(8개 숫자)을 찍는 이유는 오직 `d` 하나를 얻기 위해서다. 이건 명백히 과잉이고, 그래서 자동화 여지가 크다.

> `d` 만 있으면 되는 이유: 지면평면은 `n·X = d` 로 완결된다. `n` 을 알면 남는 건 원점거리 `d` 뿐이다.
> 그리고 `d` 는 **프리셋 불변량**(카메라는 안 움직인다) — 카메라당 딱 한 번 정하면 끝이다.

**결론: 시야에 실치수가 알려진 물체가 하나라도 있으면 `d` 가 나오고, 드로잉은 0이 된다.**

## 1. 마스터가 제시한 3가지 아이디어 — 각각의 판정

### ① 차량 3D 육면체로 바닥면 그리기 → ❌ **부트스트랩 불가 (순환 의존)**

기대되는 아이디어지만, **이 저장소의 구현이 이미 답을 갖고 있다.** `contact.ts:60` 의 입력 시그니처:

```ts
export interface CuboidBuildInput {
  slotPolysPx: Px[][];   // "이 프리셋의 주차면 폴리곤. yaw prior 의 유일한 근거"
  ground: GroundModel;   // f, n, d 가 이미 있어야 한다
  ...
}
```

육면체는 **지면모델과 주차면 폴리곤을 입력으로 받는다.** 우리가 만들려는 것을 이미 요구하므로 순환이다.

더 결정적인 것은 `contact.ts:7` 의 주석이다:

> 위치(X,Y) = 관측 · yaw = **슬롯 prior** · L = **항상 prior**(뒤 접지선은 원리적으로 안 보인다)

**차량 전장(L)은 원리적으로 관측 불가**다. 차량으로 스케일을 잡으면 폭(W)에만 의존해야 하는데,
승용차 폭은 1.70~1.90m로 편차 ±6%, SUV/경차까지 섞이면 ±15%다.
`d` 가 ±15% 틀리면 5m 깊이 주차면이 4.2~5.8m가 되어 격자가 무너진다.

**판정: 부트스트랩 소스로 쓰지 말 것. 다만 §3의 교차검증기로는 훌륭하다.**

---

### ② 노면에 그려진 실제 주차면 선을 보고 그대로 그리기 → ★★★ **최상의 소스 (미구현)**

이게 원리적으로 가장 강력하다. 노면 도색선 하나로 **필요한 것 전부**가 나온다:

| 얻는 것 | 방법 |
|---|---|
| 방위 θ | 선 방향 → 소실점 |
| 원점 (u₀, v₀) | 선의 실제 위치 (선행 문서 §4에서 "이미지 증거 없이 원리적 불가"라던 그 2 DOF) |
| 스케일 `d` | **인접 구획선 간격 2.5m 가 알려진 metric 길이** → `buildGroundPlane` 이 그대로 소비 |
| f 교차검증 | 직교 두 소실점 → `focalFromVPs` |

특히 **원점 2 DOF 를 정면으로 해결하는 유일한 소스**다. `groundModel.ts:550` 주석이 지목한
"이미지 증거(노면 도색) 없이는 검출 불가"의 바로 그 증거다.

구현 개요(전부 결정론):
```
1. 프리셋 스냅샷 → 그레이스케일 → 지면 영역만 마스킹(지평선 아래 + 차량 마스크 제외)
2. LSD(Line Segment Detector) 또는 Hough → 선분 후보
3. 흰색 필터: 선분 양쪽 대비 프로파일이 "밝은 띠"(폭 10~15cm 상당) 인가
4. 방향 클러스터링 → 두 직교 선분군 (깊이변군 / 폭변군)
5. vanishingPoint() 재사용 → v1, v2   ← 신규 수학 0줄
6. 폭변군 인접 간격의 최빈값 = 2.5m 로 스케일 고정 → d
7. 선 교점 격자 → 원점·피치 확정
```

5번에서 **기존 `estimateGroundVPs` / `buildGroundPlane` 을 그대로 쓴다.** 신규 코드는 1~4번(영상처리)뿐이다.

**취약점(정직하게):** 도색 마모, 눈/젖은 노면, 그림자 경계선, 차량이 선을 가림, 야간 조명.
→ 이걸 완화하는 것이 §2의 **시간 누적**이다.

---

### ③ 차량 + 보이는 선 조합으로 가상 ROI → ★★ **좋은 보완, 단독 정본은 아님**

차량이 서 있으면 그 차가 선을 가리지만, 동시에 **"여기가 슬롯이다"라는 강력한 증거**이기도 하다.
차량이 빠지면 선이 드러난다. 그래서 이 둘은 경쟁이 아니라 **시간상 상보관계**다.

- 차량 있음 → 슬롯 **점유 위치**(원점 힌트) 관측
- 차량 없음 → 슬롯 **선**(방위·피치·스케일) 관측

같은 프리셋을 며칠 누적하면 두 증거가 모든 슬롯에 대해 번갈아 쌓인다. 이것이 §2의 핵심이다.

## 2. 이 프로젝트가 이미 갖고 있는 최강 소스 — **번호판**

마스터가 언급하지 않았지만, **실전에서 가장 실용적인 답은 번호판**이다. 이유:

1. **실치수가 법으로 고정** — 한국 번호판 520×110mm (구형/소형 335×155mm).
   두 규격은 종횡비 4.73 vs 2.16 으로 **결정론적으로 구분 가능**하다(임계 3.0).
2. **이미 수집하고 있다** — LPD discovery 가 매 입출차마다 판 OBB 를 뽑는다. 신규 수집 인프라 0.
3. **지면모델에 의존하지 않는다** — 순환 없음. 차량 육면체와 결정적으로 다른 점.
4. **도색선과 달리 마모되지 않는다.**

### 번호판 → `d` 유도 (닫힌 형태, 결정론)

```
판 quad(4점, 실치수 기지) + f
        ↓ 평면 pose 추정 (IPPE — 4 공면점 닫힌해, RANSAC 불필요)
   판 중심 3D 점 X_p  (카메라 좌표, meter)
        ↓ 지면은 판보다 h_p 만큼 아래 (n 은 하향 법선)
   d = n·X_p + h_p
```

`h_p` = 번호판 중심의 지상고 ≈ **0.50m** (승용차 0.45~0.60, 화물차는 더 높음 → 클래스별 분리).

**오차 분석:** `h_p` 를 ±0.08m 로 보면, 카메라고 6m 기준 `d` 오차 ≈ **1.3%**.
슬롯 깊이 5.0m 로 환산하면 ±6.5cm — 격자가 충분히 성립한다.
게다가 **판 수십~수백 개를 누적해 median** 을 쓰면 개별 차량 편차가 상쇄된다.

### 부수 산출
- 판 중심을 `h_p` 만큼 내리면 **지면점**이 된다 → 여러 슬롯의 판 → 직선적합 → **방위 θ**
- 그 직선 위 2.5m 위상 적합 → **원점 (u₀, v₀)** (도색선만큼 강하진 않지만 성립)

**즉 번호판 하나로 `d`, `θ`, `(u₀,v₀)` 가 전부 나온다. 드로잉 0, 실측 0, 신규 검출기 0.**

## 3. 권장 아키텍처 — 증거 융합 + 계층 폴백

단일 소스에 걸지 않는다. **모든 소스가 같은 `d` 를 내는지 서로 대조**하는 구조가 정답이다.

```
                    ┌──────────────── 스케일(d) 후보 ────────────────┐
  ① 노면 도색선 간격 2.5m ──┐                                        │
  ② 번호판 실치수 520mm ────┼──→  median + 상호편차 검사  →  d 확정  │
  ③ 카메라고 줄자 실측 ─────┘         (편차 >10% → 경고·미채택)      │
                    └────────────────────────────────────────────────┘
                                        ↓
       f = focalFromZoom(zoom, fovBaseV)     n = [0, cos t, sin t]
                                        ↓
                                  GroundModel(auto)
                                        ↓
   ④ 차량 육면체 접지 footprint ──→ **교차검증** (footprint 폭이 1.8m 근처로 나오는가?)
                                        ↓
                              지면 격자(θ, u₀, v₀, 피치)
                                        ↓
                                프리셋별 바닥 ROI 자동 생성
```

### 폴백 계층 (위에서부터 시도, 실패 시 강등 — 프로젝트의 "강등 철학" 준수)

| 계층 | 소스 | 드로잉 | 실측 | 정확도 | 가용성 |
|---|---|---|---|---|---|
| **L0** | 노면 도색선 | 0 | 0 | ★★★ | 도색 상태 의존 |
| **L1** | 번호판 누적 | 0 | 0 | ★★☆ | **항상** (LPD 있으면) |
| **L2** | 카메라고 실측 + PTZ | 0 | 줄자 1회 | ★★☆ | 항상 |
| **L3** | 주차면 1개 수동 드로잉 | **1개** | 0 | ★★★ | 항상 (최종 안전망) |

**L1(번호판)을 1차 구현 대상으로 권한다.** 이유: 수집 인프라가 이미 있고, 신규 영상처리 코드가 0줄이며,
지면모델 순환이 없고, 도색 상태와 무관하다. L0(도색선)은 정확도는 최고지만 영상처리 신규 구현이 필요하다.

**L3 는 반드시 남긴다.** 자동이 실패하는 프리셋(판 미검출 + 도색 마모)이 존재할 수 있고,
그때 "조용히 틀린 격자"보다 "수동 1개"가 옳다.

## 4. 시간 누적 — 자동화를 실용 수준으로 올리는 결정타

단발 프레임으로 판단하면 어느 소스든 흔들린다. **같은 프리셋을 며칠 관측하면 문제가 대부분 사라진다.**

| 순간 상태 | 얻는 증거 |
|---|---|
| 슬롯 비었음 | 도색선 노출 → θ, 피치, 원점 |
| 차량 주차 | 번호판 → `d`, 슬롯 점유 위치 |
| 차량 이동 중 | 배경 median 갱신 (그림자·오염 제거) |

- **배경 median 누적**: 차량·보행자·그림자가 씻겨나가고 **도색선만 남은 깨끗한 노면 영상**이 만들어진다.
  이 median 배경에 LSD 를 걸면 단일 프레임 대비 검출률이 크게 오른다.
- **`d` 후보 누적 median**: 개별 차량 `h_p` 편차, 개별 판 검출 오차가 상쇄된다.
- **점유 blob 누적 히스토그램**: "차가 자주 서는 자리"가 슬롯 위치의 독립 증거가 된다.

정밀수집이 이미 프리셋을 순회하며 스냅샷을 찍고 있으므로, **누적 저장 테이블 하나만 추가**하면 된다.

## 5. 결정론 유지

새로 들어오는 것이 영상처리(LSD/Hough)와 pose 추정(IPPE)인데, 둘 다 결정론화 가능하다:

1. **IPPE 는 닫힌해** — RANSAC 불필요, 반복 없음. 같은 입력 → 같은 출력.
2. **LSD 는 결정론적 알고리즘**이다(난수 없음). 단, 라이브러리 스레드 수에 따라 선분 **순서**가 달라질 수 있으므로
   출력을 `(angle, x, y)` 로 **정렬**한 뒤 소비할 것.
3. **선분 클러스터링은 k-means 금지**(초기값 난수). 각도 히스토그램 최빈값 기반 결정론 분할을 쓸 것.
4. **누적 median 은 결정론** — 단, 누적 프레임 집합이 `d` 를 바꾸므로 **"학습 스냅샷"을 버전으로 동결**한다.
   운영 중에 누적이 계속 `d` 를 갱신하면 그건 비결정론이다. 갱신은 명시적 트리거로만.
5. **`round5` / 골든 해시** — 선행 문서 §5와 동일.

## 6. 정직한 한계

1. **차량 전장은 영원히 관측 불가** (`contact.ts:7`). 차량 기반 스케일은 폭에만 의존 → 부트스트랩 부적격.
2. **도색이 전혀 없는 주차장**(비포장·실내 무도색)에서는 L0 불가 → L1/L2 로 강등.
3. **번호판이 한 번도 안 잡히는 프리셋**(원경·역광·통행로 전용)은 L1 불가 → L2/L3.
4. **경사 지면**은 모든 소스가 같이 틀린다. `metricErr`·프리셋 간 `dDevRel` 이 이를 노출하므로 **침묵하지는 않는다.**
5. **판 종류 오분류**(520 vs 335) 시 `d` 가 ~1.5배 틀린다. 종횡비 게이트 + 누적 median 으로 방어하되,
   단일 판으로 `d` 를 확정하는 경로는 만들지 말 것.
6. **자동으로 잘 나왔는지 사람이 최종 승인**하는 UI를 반드시 둔다. 자동화의 목적은 드로잉 제거지 검수 제거가 아니다.

## 7. 실행 순서 제안

| 단계 | 내용 | 검증 기준 |
|---|---|---|
| **B-1** | 기존 `PtzCamRoi.json` quad 에서 `d` 를 뽑고, 같은 프리셋 판 검출로 `d` 를 독립 계산 → **두 값 대조** | 상대편차 < 5% 면 번호판 경로 성립 증명. **여기가 첫 관문** |
| **B-2** | 판 누적 테이블 + median `d` 산출 (L1 구현) | 프리셋 간 `dDevRel` < 10% (기존 검사 재사용) |
| **B-3** | 판 지면점 → 직선적합 θ + 2.5m 위상적합 원점 | 자동 격자가 판 중심을 100% 포함 |
| **B-4** | 배경 median 누적 + LSD 도색선 (L0 구현) | 도색선 유도 격자 vs 판 유도 격자 IoU ≥ 0.9 |
| **B-5** | 차량 육면체 footprint 교차검증기 | 자동 격자 하에서 차량 폭 추정치가 1.7~1.9m 범위 |
| **B-6** | 웹 UI: 소스 선택(L0/L1/L2/L3) + 승인 버튼 | 실카 스냅샷 육안 확인 |

**B-1 이 결정적이다.** 이미 정답(시뮬레이터 quad)이 있는 상태에서 번호판만으로 `d` 를 맞출 수 있는지
**공짜로 검증**할 수 있다. 여기서 5% 안에 들어오면 이 설계 전체가 성립하고, 안 들어오면 `h_p` 가정부터 재검토한다.

## 8. 이 작업을 서브에이전트로 분할할 수 있는가 (코워크 전략)

**답: 구간에 따라 갈린다. 전부 나누면 오히려 느리고 부정확해진다.**

### 8-1. 병렬이 이득인 구간

**① 독립 증거원 검증 — 최적 적용점**
L0(도색선) / L1(번호판) / L2(PTZ+실측) 이 각각 `d` 를 산출하는데,
**세 경로가 서로를 모르는 상태에서 뽑아야 교차대조가 의미를 갖는다.**
한 에이전트가 순차로 하면 앞의 결과가 뒤를 오염시킨다(앵커링). **독립성이 목적 그 자체**라 팬아웃이 원리적으로 옳다.

```
A: 기존 PtzCamRoi.json quad → d (기준값)
B: 번호판 실치수 520mm → IPPE → d      ← A를 모름
C: PTZ tilt + fovBaseV + 실측 → d       ← A,B를 모름
D: 도색선 간격 2.5m → d (가능한 프리셋만) ← A,B,C를 모름
        ↓ 배리어(반드시 모아야 함 — 대조 자체가 목적)
   4개 값 상호편차 검사 → 5% 이내면 경로 성립
```

**② 적대적 반증** — 산출된 `d` 를 서로 다른 실패 모드로 공격(관점이 달라야 커버가 된다):
- `h_p=0.5m` 가정이 SUV/화물 혼재 시 무너지는가
- 판 종류(520 vs 335) 오분류 시 1.5배 오차 시나리오
- roll≠0 인데 `n=[0,cos t,sin t]` 로 세운 오차량
- 경사 지면에서 `metricErr` 가 실제로 반응하는가

**③ 프리셋·카메라별 실측 스윕** — 데이터가 완전히 분리되어 무손실 병렬.

### 8-2. 병렬이 손해인 구간

**기하 설계 자체.** `f, n, d, θ, u₀, v₀` 는 강하게 얽혀 있어, 각자 일부만 본 에이전트는
**자신있게 틀린 결론**을 낸다. 이 문서의 핵심 판단(차량 육면체 순환 의존 · 전장 관측 불가 ·
원점 2 DOF 한계)은 전부 여러 파일을 **한 맥락에서 겹쳐 봤기 때문에** 나왔다. 쪼개면 손실이다.

**B-1 도 손해다.** 결론이 "편차 몇 %" 라는 숫자 하나라 조율 비용이 산출보다 크다. 단일로 끝내는 게 맞다.

**그리고 진짜 병목은 사고량이 아니다** — 실카 스냅샷 확보, 육안 확인, 줄자 실측은 에이전트를 늘려도 안 빨라진다.

|---|---|---|
| `parkagent-dev` B모드 | 설계→구현→검증→문서, **순차 4인 팀** | 실제 코드 구현 |

|---|---|

필요 판 크기 역산: 1px 노이즈에서 `d` 오차 5% 이내를 원하면 **판 높이 ≥ 49px**(폭 ≈ 230px), 2% 이내면 **≥ 77px**.
실측 프리셋(판 높이 13~35px)은 전부 미달.

### 9-4. 다음 실험 — 원인이 제거 가능하다 (개념 정리 포함)

#### (a) 용어 — "지면모델(GroundModel)"이란

**"이 카메라가 이 프리셋에서 주차장 바닥면을 어떤 기하로 보고 있는가"를 숫자 3개로 압축한 것.**

| 값 | 의미 | 단위 |
|---|---|---|
| `f` | 초점거리 — 이 zoom 에서 1m 가 몇 px 로 보이는가 | px |
| `n` | **지면의 하향 단위법선**(카메라 좌표) — 바닥이 어느 방향으로 누워 있는가 | 무차원 |
| `d` | **카메라 지상고** — 바닥면이 카메라에서 얼마나 떨어져 있는가 | m |

`n` 과 `d` 를 합치면 평면 방정식 **`n · X = d`** 하나가 된다. 이게 있으면 `project.ts` 의 두 함수로 **왕복**이 성립한다:

```
픽셀 (x,y) ──backprojectToGround──▶ 지면점 X (미터)    X = d·m/(n·m),  m = K⁻¹p
지면점 X   ──projectToPixel──────▶ 픽셀 (x,y)
```

**두 번째 방향이 자동 ROI 생성의 전부다** — 바닥 2.5×5m 사각형을 화면 4점으로 내리는 것.

> ⚠️ **지면모델은 "카메라 위치"가 아니다.** `groundModel.ts:4` 가 명시하듯 Unity `camera` 블록
> (position/eulerAngles/fov)에 의존하지 않는다. 필요한 건 오직 **카메라 자신을 원점으로 봤을 때 바닥이 어디 있는가**
> 뿐이다. 그래서 세계좌표를 못 주는 실카메라에도 그대로 적용된다(설계 C3).

#### (b) "판 수직 구속"이란

실패한 B-1 은 번호판을 **공중에 떠 있는 임의의 평면 조각**으로 취급했다 — 회전 3 + 위치 3 = **자유 6DOF**.
판이 위아래로 얼마나 기울었는지(면외 회전)를 알려면 **짧은 변(13~17px)** 을 봐야 하고, 거기서 조건수가 무너진다.

**번호판은 물리적으로 지면에 수직**이다(차량 앞범퍼에 세워 부착). 이 사실을 방정식에 넣으면:

- **판의 세로 방향 = 지면 법선의 반대(위쪽)** → `n` 을 이미 아니까 **공짜로 확정**
- **판의 가로 방향 = 수평면 안의 어떤 방향** → 남는 회전 미지수는 **방위각 ψ 하나**

**회전 3 → 1, 총 6DOF → 4DOF.**

#### (c) 진짜 이득은 자유도 감소가 아니라 **정보원 이동**

| | 자유 6DOF (실패) | 수직 구속 4DOF |
|---|---|---|
| 방위각 ψ | 짧은 변 필요 | **긴 변의 기울기**(45~116px 에 걸쳐 잼) |
| 깊이 Z | 짧은 변에 강하게 의존 | **긴 변의 길이** ÷ cos ψ |
| 짧은 변(13px) | **주정보원** | 검증용 보조 |

긴 변에서 각도를 재면 1px 오차가 `1px/60px ≈ 1°`, 길이 오차는 `1.7%`.
오차 전파가 **`1/h²`(짧은 변 제곱) → `1/w`(긴 변 1승)** 으로 바뀐다. **예측 `d` 오차 ~2%.**

#### (d) 정직한 대가

1. **판이 완전히 수직은 아니다**(범퍼 각도·경사 주차). 다만 **위아래 기울기는 긴 변 길이에 거의 영향이 없다**
   — 가로폭을 단축시키는 건 수직축 회전뿐이라 이 가정은 생각보다 강건하다.
2. **판이 거의 옆에서 보이면**(ψ→90°) 긴 변이 극단 단축되어 조건수가 다시 나빠진다 → 단축 심한 판은 배제.
3. **`h_p`(판 중심 지상고 ≈0.5m) 가정은 구속과 무관하게 남는다.**

**B-1b(다음 실측): 판 수직 구속 pose 로 재측정.** 통과하면 L1(번호판) 경로가 살아나고,
실패하면 L1을 접고 **L0(노면 도색선)** 로 간다 — 도색선은 지면 위에 있어 이 문제가 원리적으로 없다.

### 9-6. B-1b 가 남긴 미해결 항목 (다음 실측 대상)

1. **preset 2 의 계통적 재투영 잔차** — 판이 가장 큰데(115px) RMS 가 가장 나쁘다(3.5~6.6px).
   무작위 노이즈면 이렇게 프리셋 단위로 뭉치지 않는다. **`n` 자체가 preset 2 에서 틀렸을 가능성**
   (roll ≠ 0 등)이 가장 유력하다. 검증법: `n` 을 2DOF 자유로 풀어 RMS 최소화 → 필요한 tilt/roll 보정량을 본다.
   보정량이 작은데 RMS 가 급감하면 원인은 판 모델이 아니라 `n` 이다.
2. **표본 확대** — 13개로는 median 의 표준오차가 크다. 시간 누적(§4)으로 프리셋당 수십 개 확보 후 재판정.
3. **결합 추정(joint fit)** — 현재는 판마다 독립으로 풀고 median 을 냈다. 올바른 추정기는
   **한 프리셋의 모든 판이 같은 `d` 를 공유**하고 `h_p` 는 사이트 상수라는 제약을 건 동시 최적화다.
   개별 median 보다 훨씬 강건해진다.
4. **ψ 의 프리셋 간 정합** — 월드 방위로 환산 시 preset1 353.8° / preset2 359.5°(5.7° 차, 양호),
   preset3 은 87.1°(약 90° 차) — **다른 주차열을 보고 있을 가능성**. 격자 원점·방위 설계에 직접 영향.

### 9-7. 판정

- **설계 전체는 살아 있다.** 핵심 전제(`d` 프리셋 불변 · PTZ tilt 로 `n` 유도)가 실측으로 확인됐다.
- **L1(번호판)은 현재 형태로는 불가.** 자유 6DOF pose 는 판이 49px 이상 높게 보일 때만 성립.
- **버릴 것은 설계가 아니라 판 pose 추정 방식.** B-1b 로 재시도한다.
- **트랙 A가 완벽하므로 L3(수동 1개) 경로는 지금 당장 구현 가능**하다 — 자동화가 늦어져도 선행 문서의
  "1개 그리면 전 프리셋 자동"은 이미 성립한다.

## 10. 요약

- **첫 주차면 드로잉의 정체는 "미터 스케일 `d` 하나"** — 사각형 4점은 그걸 얻기 위한 과잉 입력이다.
- **차량 육면체는 부트스트랩에 못 쓴다** — 지면모델을 입력으로 요구(순환)하고, 전장은 원리적으로 관측 불가.
- **노면 도색선이 원리적 최강** — `d`, θ, 원점을 전부 준다. 특히 기존 코드가 "검출 불가"로 명시한 원점 2 DOF 를 유일하게 해결. 단 영상처리 신규 구현 필요.
- **번호판이 실전 최적** — 실치수 법정 고정, 이미 수집 중, 지면모델 순환 없음, 신규 검출기 0. **1차 구현 권장.**
- **시간 누적이 결정타** — 배경 median 이 도색선을 드러내고, 판 median 이 스케일을 안정시킨다.
- **수동 1개 경로(L3)는 안전망으로 유지** — 자동 실패 프리셋에서 조용히 틀리는 것보다 낫다.
- 첫 검증: **B-1 — 기존 quad 의 `d` vs 번호판 유도 `d`, 편차 5% 이내.**
