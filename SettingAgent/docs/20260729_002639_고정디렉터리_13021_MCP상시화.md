# SettingAgent 2번째 인스턴스(13021) — 임시 워크트리 → **고정 디렉터리** 상시화

_작성: 2026-07-29 00:26:39 · 대상: `SettingAgent-13021/` (신규, gitignore) · 선행 문서: `20260729_000246_독립서버_13021_MCP연결_격리환경.md`_

## 1. 배경 / 목적

선행 작업에서 2번째 SettingAgent(13021)를 **임시 워크트리** `.claude/worktrees/feat-standalone-mcp` 에 띄우고 MCP `setting13021` 로 연결했다.
그 구성의 치명적 약점은 **등록 경로가 워크트리 안**이라는 것 — 세션 종료 시 워크트리를 삭제하면 MCP 등록이 죽은 설정이 된다(선행 문서 §6·§8).

이번 작업의 목표는 선행 문서 §8-1안 채택:

> **워크트리가 아닌 고정 디렉터리에 config 사본을 두고 거기서 기동 — 경로가 안 죽는다.**

성공 기준:
1. 워크트리를 지워도 살아남는 **영구 경로**에서 13021 이 기동한다.
2. 소스는 **메인 체크아웃과 공유**되어 코드 수정이 재기동만으로 반영된다(사본 소스의 노후화 없음).
3. 설정·DB·저장물은 **완전 격리**된다.
4. MCP 가 13021 을 문다는 것이 **차동 검증**으로 실증된다.

## 2. 설계 — "그림자 인스턴스(shadow instance)"

핵심 판단: SettingAgent 의 런타임 자원 경로는 **전부 cwd 상대**다. 따라서 *cwd 만 갈아끼우면* 소스를 복제하지 않고도 상태를 분리할 수 있다.

근거(코드 확인):

| 자원 | 해석 방식 | 위치 |
|------|-----------|------|
| 설정 파일 | `loadToolsConfig(path = 'config/tools.config.json')` — cwd 상대 | `src/config/toolsConfig.ts:419` |
| DB·저장물 | `new Repository(tools.store.dataDir)` / `new SaveStore(saveDir, reportsDir)` | `src/index.ts:50-51` |
| Place ROI·기준프레임·지면격자 | `join(tools.store.dataDir, …)` | `src/index.ts:71,151-154` |
| 뷰어 정적자산 | `root: resolve(viewer.staticDir)` — cwd 상대 | `src/viewer/routes.ts:191` |
| MCP 대상 포트 | `baseUrl: http://localhost:${cfg.server.port}` | `src/mcp/server.ts:31-35` |

**모듈 상대 경로(`import.meta.url`/`__dirname`)로 자원을 찾는 코드는 SettingAgent/src 전체에 0건**이다.
(`src/mcp/server.ts:248` 의 `import.meta.url` 은 CLI 진입점 판별용이지 경로 해석이 아니다.)

→ 그러므로 **소스는 정션으로 공유하고, 상태 디렉터리만 실제 사본**으로 두는 구성이 성립한다.

### 2.1 디렉터리 구조

```
ParkAgent/SettingAgent-13021/          ← 고정 디렉터리(gitignore). 이 경로가 곧 cwd
├── src         → 정션 → ParkAgent/SettingAgent/src      (소스 공유 · 노후화 없음)
├── web         → 정션 → ParkAgent/SettingAgent/web      (뷰어 공유)
├── node_modules→ 정션 → ParkAgent/node_modules          (네이티브 재빌드 회피)
├── package.json / tsconfig.json       (사본 — `npm --prefix … run mcp` 에 필요)
├── config/                            (사본 — server.port = 13021)
├── data/                              (사본 + DB 스냅샷)
├── save/ · reports/ · logs/           (신규 빈 디렉터리 — 이 인스턴스 전용 산출물)
└── start.cmd                          (기동 스크립트: cd /d %~dp0 후 tsx src/index.ts)
```

정션이므로 **Node 는 realpath 로 메인 소스를 로드**한다. 소스 내부의 상대 import·`node_modules` 탐색은 메인 기준으로 정상 해석되고, `process.cwd()` 는 프로세스 속성이라 그림자 디렉터리 그대로 유지된다 — 이 비대칭이 이 구성이 성립하는 이유다.

### 2.2 워크트리 방식 대비

| | 임시 워크트리(구) | 고정 디렉터리(신) |
|---|---|---|
| 경로 수명 | 세션 종료 시 소멸 → MCP 등록 사망 | **영구** |
| 소스 최신성 | 브랜치 분기 시점에 고정 → 머지 필요 | **메인과 항상 동일**(재기동만) |
| 디스크 | 전체 체크아웃 사본 | 상태 디렉터리(~16MB)만 |
| 소스 수정 | 워크트리에서 별도 편집 가능 | **불가**(메인을 고쳐야 함) — 의도된 제약 |

> **스코프를 local → project 로 바꾼 이유(실측 사고):** 처음엔 선행 문서대로 `-s local`(`~/.claude.json`)로 등록했고 `claude mcp list` 에서 `✔ Connected` 까지 확인했다.
> 그런데 **수 분 뒤 등록이 통째로 사라졌다** — 실행 중이던 Claude 세션이 자기 **시작 시점**의 설정을 `~/.claude.json` 에 다시 써 내리면서 외부 CLI 의 편집을 덮은 것으로 보인다.
> 즉 **세션이 떠 있는 동안의 `claude mcp add -s local` 은 소실될 수 있다.** 파일 스코프인 `.mcp.json`(project)은 세션이 재작성하지 않으므로 안전하다.
> 대신 project 스코프는 세션 시작 시 **1회 승인**이 필요하다(`⏸ Pending approval`).

`npm --prefix` + `--silent` 는 선행 문서와 동일한 이유로 **필수**다(§5 함정 참조).

## 5. 함정 — 반드시 지킬 것

1. **cwd 를 안 잡으면 옆 세션 서버를 조작한다.** `tsx SettingAgent-13021/src/mcp/server.ts` 를 다른 cwd 에서 실행하면 config 를 못 찾아 기본값(`toolsConfig.ts:408` → **13020**)으로 조용히 붙는다. 오류도 경고도 없다. 반드시 `npm --prefix` 또는 `start.cmd` 를 쓸 것.
2. **`--silent` 없으면 MCP 가 깨진다.** npm 배너(`> parkagent-setting@0.1.0 mcp`)가 JSON-RPC 스트림을 오염시킨다.
3. **소스는 이 디렉터리에서 수정할 수 없다.** `src`·`web` 은 정션이라 여기서 고치면 **메인이 고쳐진다**. 코드 변경은 메인(또는 워크트리)에서 하고, 13021 은 재기동으로 따라간다.
4. **`config/` 는 자동 동기화되지 않는다.** 메인 `tools.config.json` 에 새 키가 추가되면 이 사본에도 반영해야 한다(포트만 다르게 유지).

## 9. 남은 사항

- **`Unity RPC 연결 실패` 오류 문구 오기(§4.4 A2)** — SettingAgent 서버 연결 실패인데 메시지가 "Unity RPC" 로 나온다. 공용 RPC 클라이언트의 라벨 하드코딩으로 보이며 **이번 변경과 무관한 기존 결함**이다. 진단을 오도할 수 있으므로 별건 수정 대상으로 남긴다(삭제·수정하지 않음).
- **`PARKAGENT_TOOLS_CONFIG` 환경변수 오버라이드**(선행 문서 §8-2안)는 여전히 미적용. 채택하면 §5-1 의 cwd 함정 자체가 사라지지만 소스 변경이라 별도 설계·유닛테스트가 필요하다.
