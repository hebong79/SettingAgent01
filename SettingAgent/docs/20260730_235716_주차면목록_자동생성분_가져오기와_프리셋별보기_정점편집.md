# 주차면 목록 — 검출결과 교체 · 프리셋별 보기 · 클릭 선택과 4정점 편집

_2026-07-30~31 · 브랜치 `main`(마스터 지시: 현재 브랜치·워크스페이스에 추가)_

## 0. 요청과 결과

**요청(마스터).** UI에 **프리셋별 생성된 주차면 리스트**를 만들고 **추가·수정·삭제 버튼**을 두어
**자동 생성된 리스트를 리스트 박스에 넣고 선택 삭제**가 가능해야 한다. 그리고 **생성된 주차면 박스는
선택해 4꼭지점을 잡아 크기 조절**이 가능해야 한다.

**먼저 확인한 것 — 요청의 상당 부분은 이미 있었다.** 없는 것만 만들었다.

| 요청 항목 | 기존 상태 | 이번 작업 |
|---|---|---|
| 주차면 리스트 박스 | **있음**(`#slot-list`, 행 클릭 = 선택) | 유지 |
| 추가 | **있음**(`면 그리기` — 캔버스 4클릭) | 유지 |
| 수정 | **있음**(`#place-edit` 전역 번호 변경) | 유지 |
| 삭제 · 선택 삭제 | **있음**(`#place-delete`, 선택 면 1개 / `이 프리셋 전체삭제`) | 유지 |
| 4꼭지점 크기 조절 | **있음**(`#place-edit-vertex` 토글 + 정점 드래그) | **선택하면 자동으로 열리게** 변경 |
| **프리셋별** 목록 | **없음** — 전 프리셋을 전역 번호순 **평면 목록**으로만 표시 | **`이 프리셋만` 필터 신설**(기본 켜짐) |
| **자동 생성분을 목록에 넣기** | **없음** — 자동검출 결과는 **시안 오버레이 그림**일 뿐 선택·편집·삭제 불가 | **[검출] 이 목록을 교체**(+ `[검출결과로 교체]` 버튼) |
| **캔버스에서 면 클릭 선택** | **없음** — 선택은 목록 행 클릭뿐 | **면 안쪽 클릭 = 선택 + 핸들 열림** |

## 1. 왜 자동 생성분이 목록에 없었나 (설계 배경)

도색선 자동검출(`roi.auto.detect`) 결과는 `state.autoPaint` 에 담겨 **가산 오버레이(시안)로만** 그려졌다.
정본(`PtzCamRoi.json`)을 덮어쓰는 `roi.auto.apply` 는 **마스터 별도 승인 사항이라 UI에 노출하지 않는다**는
규약이 있었기 때문이다(패널 주석에 명시). 그 결과 자동으로 만든 면은 **보이기만 하고 손댈 수 없었다.**

이번 작업은 그 규약을 깨지 않는다:

- 가져오기는 **메모리(`state.placeRoi`)에만** 넣는다. 파일·DB 를 쓰지 않는다.
- 파일 확정은 **기존 `저장`**(PtzCamRoi.json)이 그대로 담당한다 — 확정 지점이 하나로 유지된다.
- 되돌리기는 기존 `되돌리기`(1단계)와 `삭제`가 그대로 받는다.
- `roi.auto.apply` 는 **여전히 미배선**이다.

## 2. 변경 내용

### 2-1. `[검출]` 이 목록을 **교체**한다 (마스터 추가 요청 2026-07-31)

> *"검출버튼을 누르면 UI의 주차면 리스트는 모두 지워지고 새로 생성된 것만 리스트에 추가한다."*

`도색선 자동검출` 의 **[검출]** 성공 직후 `replaceListWithAutoDetect({auto:true})` 가 돌아
**지금 보고 있는 `cam:preset` 의 목록을 비우고 검출 결과로 채운다**. 같은 동작을 손으로 다시 하려면
목록 툴바의 **[검출결과로 교체]**(구 `검출결과 가져오기`)를 쓴다 — 되돌린 뒤 재적용용이다.

**판단이 필요했던 3가지(전부 의도적):**

1. **범위는 현재 `cam:preset` 하나뿐이다.** 검출은 그 화면에서만 이뤄지므로, 다른 프리셋의 수작업을
   검출 한 번으로 지우지 않는다(`clearPresetSpaces` 가 그 키만 비운다).
2. **검출 결과가 0면이면 아무것도 지우지 않는다.** "검출 실패로 기존 목록을 잃는 것"이 훨씬 나쁘다.
   빈 결과는 스냅샷·삭제보다 **앞에서** 끊고, 기존 면수를 문구에 적어 알린다.
3. **[검출 + 채점]에는 적용하지 않는다.** 채점은 자동 결과를 **수동 정본과 비교**하는 기능이라,
   그 수동 목록을 지우면 비교 기준 자체가 사라진다. `mode === 'detect'` 일 때만 교체한다.

- 파괴이므로 기존 관용구 그대로 **되돌리기 1단계**를 남긴다(`snapshotPlaceRoi` → 교체 → `sealPlaceRoiUndo`)
- **파일·DB 무접촉** — 확정은 기존 **[저장]**
- 교체 후 첫 면이 **선택 + 정점 편집 ON + 바닥 표시 ON** → 바로 크기 조절로 이어진다
- 문구에 `교체 N면 / 기존 M면 제거 / #첫번호` 를 그대로 적는다(조용한 파괴 금지)

**순수 로직** `web/placeDraw.js` **`importAutoQuads(placeRoi, key, quads)`** → `{placeRoi, added, skipped, firstIdx}`
- **끝 append**(`appendPlaceSpace` 위임) — 남은 면 번호를 흔들지 않는다
- **같은 4점(소수 5자리)은 건너뛴다** — 교체 경로에서는 비우고 넣으므로 사실상 방어용이다
- 4점이 아닌 입력은 무시(`skipped` 로 계수)

### 2-1b. 캔버스에서 면을 **클릭해 선택** (마스터 추가 요청 2026-07-31)

> *"마우스로 생성된 주차면 박스를 클릭하면 선택이 되어 크기 조절이 가능해야 한다."*

`web/placeDraw.js` **`hitTestPlaceSpace(placeRoi, key, pt)`** → 전역 idx | null (판정은 `core.pointInQuad` 위임).
오버레이 `mousedown` 에서 **정점 히트테스트 바로 뒤**에 둔다.

- ★ **순서가 계약이다**: 핸들은 면 안쪽에도 걸쳐 있으므로 면 선택이 먼저 오면 **핸들을 잡을 수 없다**(크기 조절이 죽는다)
- 그리는 중(`state.placeDraw`)에는 건너뛴다 — 그때의 클릭은 '점 찍기'다
- `#roi-floor` 가 꺼져 있으면 건너뛴다 — 그려지지 않는 것을 집게 하면 '보이지 않는 선택'이 된다
- 겹친 면은 **배열 뒤쪽(= 위에 보이는 것)** 을 고른다
- 이미 선택된 면을 다시 눌러도 선택이 풀리지 않는다(아래 해제 분기로 흐르지 않게 끊는다)

### 2-2. `이 프리셋만` 필터 (신규, 기본 켜짐)

- `web/core.js` **`buildFlatSlotRows({..., onlyKey})`** — 지정 시 그 키만 남긴다. 미지정이면 **종전 동작 그대로**
- ★ **거르더라도 전역 번호는 다시 매기지 않는다.** 걸러 보인다고 번호가 바뀌면 목록의 번호와
  `수정`(번호 변경)·DB 매칭이 어긋난다
- 빈 목록 문구가 구분된다: `"1:2 에 주차면 없음 — '면 그리기' 또는 '검출결과로 교체'(전체 12면)"`
  → "이 프리셋에 없는 것"과 "아예 없는 것"을 혼동하지 않는다

### 2-3. 선택 = 크기 조절의 시작

`selectPlaceSpace()` 가 선택 시 **`#place-edit-vertex` 를 켠다**(기존엔 `면 그리기` 직후에만 켜졌다).
바닥 표시(`ensureFloorVisible`)는 이미 켜고 있었다 — 표시·히트테스트가 둘 다 `#roi-floor` 를 요구하기 때문이다.
토글 자체는 남아 있어 원치 않으면 끄면 된다(안전장치 유지).

## 3. 사용법 (정보수집/제어 탭 → 우측 `주차면 목록 · 편집`)

1. `도색선 자동검출` 패널에서 **[검출]** 실행 → **목록이 검출 결과로 교체**되고 첫 면이 선택된다
   (되돌리려면 **[되돌리기]**, 다시 적용하려면 **[검출결과로 교체]**)
2. 목록 행을 클릭하거나 **화면의 면을 직접 클릭**하면 선택되고 **4정점 핸들이 바로 열린다** → 드래그로 크기·모양 조절
3. 필요 없는 면은 선택 후 **[삭제]**(1개) 또는 **[이 프리셋 전체삭제]**
4. **[저장]** 을 눌러야 `PtzCamRoi.json` 에 기록된다. 그 전이면 **[되돌리기]** 로 직전 파괴를 되돌릴 수 있다
5. 다른 프리셋 것도 함께 보려면 **`이 프리셋만`** 체크를 끈다

## 4. 검증

- **유닛테스트 신규 29케이스**(`test/placeListImportAuto.test.ts`) — 값으로 검증:
  번호 부여·기존 번호 불변·**중복 건너뛰기**·프리셋 간 동일 좌표는 중복 아님·4점 아닌 입력 무시·
  빈 입력 불변·소수 5자리 저장 / 필터의 **전역 번호 불변** / **교체 조합**(다른 프리셋 불변·1..N 연속) /
  **히트테스트**(면 안·빈 곳·겹침 시 위쪽) / 결선 봉인(**클릭 순서 계약**·**0면 보호**·채점 제외)
- **전체 회귀**: `tsc --noEmit` exit 0 · vitest **298파일 3809 green**
- 실행 중인 13020 서버가 새 정적 자산을 서빙함을 확인(`replaceListWithAutoDetect`·`hitTestPlaceSpace`·`검출결과로 교체` 응답 포함)

### 검증되지 **않은** 것 (은닉 금지)

- **브라우저 육안 확인은 마스터 몫**이다. 이 저장소에는 DOM 자동화(playwright/jsdom)가 없어
  드래그·클릭 상호작용을 자동으로 재현할 수 없다. 순수 로직은 값으로, 결선은 소스 봉인으로 지켰다.
- **자동검출 결과의 품질은 이 작업의 범위가 아니다.** 교체는 서버가 낸 quad 를 그대로 옮길 뿐이며,
  22회차 기록대로 `rows` 경로에는 오검출이 남아 있다 — **교체 뒤 눈으로 보고 지우는 것이 전제**다.
- 교체 후 **`저장`까지 하면 정본이 바뀐다**(그 지점은 종전과 동일한 기존 경로다).

## 5. 영향도 분석

| 대상 | 판단 |
|---|---|
| `buildFlatSlotRows` 기존 호출부 | `onlyKey` **옵션**이라 미지정 시 반환이 종전과 동일. 기존 테스트 무변경 통과 |
| 자동검출 패널(`roi.auto.*`) | **무변경**. 결과 shape 을 읽기만 한다(`autoPaintViewFor`·`autoQuadItems` 재사용) |
| 정본·DB | 교체 단계에서는 **무접촉**. 파일 쓰기는 기존 `저장`(PUT place-roi) 한 곳뿐이고 그 경로는 무변경 |
| `roi.auto.apply` | **여전히 미배선**(정본 보호 규약 유지) |
| 서버 코드 | **0줄 변경** — 이번 작업은 전부 뷰어(web)와 순수 모듈이다 |
| 전역 번호 체계 | 끝 append + 필터 시 번호 유지 → `수정`(번호 변경)·`삭제`(1..N 재압축)·DB 매칭 규약 불변 |
| 오버레이 렌더 | 교체된 면은 **파일 ROI 와 같은 초록 레이어**로 그려진다(자동 시안 레이어와 별개). 두 레이어가 겹쳐 보일 수 있으므로, 정리 후에는 `도색선` 토글을 끄는 것이 읽기 쉽다 |

### 주의 (운영)

1. **[검출]은 이제 파괴적이다.** 그 프리셋의 목록이 통째로 바뀐다 — 손으로 맞춰 둔 면이 있고 아직 저장 전이라면
   검출을 누르기 전에 **[저장]** 하거나, 누른 뒤 **[되돌리기]**(1단계)로 복구한다.
2. **다른 세션과 같은 작업트리**(main)에서 작업했다. 22회차 세션의 미커밋 변경과 파일이 겹치지는 않는다
   (그쪽은 `메모/`·`.claude/`·`config/`·`src/tools/`).
3. **메모(`메모/memo.md`) 기록은 이 커밋에 넣지 않았다** — main 작업트리의 memo.md 에 22회차 세션의
   미커밋 91줄이 들어 있어, 파일째 커밋하면 그 세션의 미완 작업까지 함께 커밋된다. 그쪽이 커밋한 뒤 잇는다.
