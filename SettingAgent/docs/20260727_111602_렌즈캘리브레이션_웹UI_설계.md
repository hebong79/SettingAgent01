## 2. 목표 / 비목표

### 목표 (성공기준 — 검증 가능)
1. 정밀수집 페이지에서 **뷰어가 선택 중인 카메라 소스**에 대해 캘리브레이션을 **시작**할 수 있다.
2. 진행 중 **진행바(%)**, **로그(LOG) 라인 누적**, 현재 단계 메시지가 실시간(1s 폴)으로 갱신된다.
3. **정지** 버튼으로 중단되고, 중단·실패·완료 어느 경로로 끝나도 **카메라는 원 PTZ 로 복귀**한다.
4. 완료 시 **판정 요약 메시지**(줌별 잔차·게인·채택/기각)와 산출표가 표시된다.
5. 생성된 표는 `data/lens_calibration.json` 에 **`enabled:false` 로 저장**되고, 별도 **[적용]** 버튼을 눌러야 활성화된다.
6. 유닛테스트 green + `tsc --noEmit` 0 + 기존 테스트 회귀 0.

### 비목표 (이번에 하지 않는 것)
- 곡면율 시차 보정 (별건 — 2026-07-25 결론).
- `sourceRegistry` 핫리로드. **표 적용은 서버 재시작이 필요**하며 UI가 그 사실을 문구로 알린다(조용한 무동작 금지).
- 시뮬레이터 캘리브레이션 (구조적으로 무의미 — 시뮬은 자기 표로 렌더).
- `realLensVerify.ts` 삭제 (CLI 는 그대로 둔다. 커밋 대상 아님).

## 4. 서버 — `LensCalibrationJob` (신규 `src/calibrate/LensCalibrationJob.ts`)

### 4.1 상태

```ts
type LensCalibState = 'idle' | 'running' | 'stopping' | 'done' | 'error' | 'aborted';
type LensCalibMode  = 'full' | 'verify' | 'distortion';

interface LensCalibStatus {
  state: LensCalibState;
  mode: LensCalibMode | null;
  sourceId: string | null;
  done: number; total: number;            // 진행바
  message: string;                        // 현재 단계 (예: "zoom 8000 · 클릭 (+480, +0)")
  startedAt?: string; endedAt?: string;
  logs: Array<{ seq: number; at: string; level: 'info'|'warn'|'error'; text: string }>;
  result?: LensCalibResultSummary;        // 완료 시에만
  error?: string;
}
```

### 4.2 로그(LOG) 전달 방식 — **폴 + seq 증분**

- SSE/WebSocket 을 쓰지 않는다. 이 저장소의 모든 잡 UI(`/capture/status`·`/discover/status`·`/calibrate/status`)가 폴 방식이고, 폴러 라이프사이클(`pollPlan`)·재연결 처리가 이미 검증돼 있다. 로그 한 줄 때문에 새 전송 채널을 도입하는 것은 과설계다.
- 잡은 **링버퍼 500줄**을 들고, `GET /calibrate/lens/status?sinceSeq=N` 이 **N 초과분만** 반환한다. 클라는 받은 줄을 DOM 에 append 하고 마지막 seq 를 기억한다. 폴 1회당 전송량이 O(신규줄)이라 긴 스윕(112 클릭 × 수 줄)에서도 부담이 없다.
- `sinceSeq` 미지정이면 **전체 버퍼**를 준다(새로고침·탭 재진입 복구).
- 500줄 초과 시 오래된 줄부터 버리고, 버려진 순간 `logsTruncated: true` 를 켠다(**조용한 유실 금지**).

### 4.3 진행률 — 엔진 `onProgress` 그대로

`CalibrationRunner` 의 `onProgress({done,total,message,sample})` 를 그대로 받아 상태에 반영한다.
- `message` 있으면 → `status.message` 갱신 + **로그 1줄**.
- `sample` 도착 → `done` 증가. 샘플이 `usable:false` 면 **`warn` 로그 1줄**(사유 `reason` 포함) — 실패를 숨기지 않는다.
- 진행바 % = `total>0 ? round(done/total*100) : 0` (기존 `discoverView` 와 동일 식).

### 4.4 정지

- `stop()` → `AbortController.abort()` + `state='stopping'`. 엔진은 각 타깃 루프 진입 시 `signal.aborted` 를 검사해 `throw` 하고, **`finally { goHome() }`** 가 원 PTZ 로 복귀시킨다(엔진 기존 보장).
- 복귀 완료 후 `state='aborted'`. 즉 **정지 직후 즉시 idle 이 되지 않는다** — 카메라가 아직 귀환 중이기 때문. UI 는 `stopping` 동안 진행바를 유지하고 "정지 중(카메라 복귀)" 를 표시한다.

### 4.5 카메라 포트 조립 — `makeHucomsPort(src, deps)`

`realLensVerify.ts` 의 검증된 조립(재시도 포함)을 서버 모듈로 이식한다. 새로 설계하지 않고 **동작이 확인된 코드를 옮긴다**.

- `config.cameraSources` 에서 `id === sourceId && kind === 'hucoms'` 인 항목을 찾아 `HucomsClient` 생성.
- `getPtz`/`waitSettle`/`setCenter`/`goPtz`/`snapshotGray`(sharp greyscale raw) 구현.
- 일시 fetch 실패 4회 재시도(`withRetry`) — 실카 슬루 중 간헐 실패는 실측된 정상 현상.
- **sim 소스면 400** `"시뮬레이터는 렌즈 캘리브레이션 대상이 아닙니다"`.

> `RealPtzSource` 를 재사용하지 않는 이유: `RealPtzSource` 는 **뷰어 좌표계(정규화·도·배율)** 로 말하고 보정을 이미 적용한다. 캘리브레이션은 **네이티브 단위(px·centidegree·zoompos)** + **보정 우회(rawAim)** 가 필수다(엔진 주석 §1). 뷰어 소스를 통해 재려 하면 "재려는 대상을 보정 너머로 재게" 된다. 따라서 `HucomsClient` 직결이 옳다.

### 4.6 결과 영속화

| 모드 | 산출 | 저장 |
|---|---|---|
| `full` | `CameraCalibration`(zoomHfov·centeringGain) | `data/lens_calibration.json` 의 해당 `id` 항목에 **`enabled:false` 로 upsert**. 기존 항목의 `enabled` 는 덮어쓰지 않고 **false 로 강등**(새 표는 검증 전) |
| `verify` | `VerifyReport` | **파일 미변경**. 상태·로그로만 보고 |
| `distortion` | `DistortionRunResult` + `verifyDistortion()` A/B | A/B `adopt` 일 때만 `lensDistortion` 을 항목에 기록(그래도 `enabled:false`). `reject` 면 파일 미변경 + 사유 로그 |

- 원본 전문은 `data/lens_calib_result_<sourceId>.json` 에 항상 저장(감사용) → `GET /calibrate/lens/result`.
- 숫자 영속화는 프로젝트 규약대로 **소수점 최대 5자리**(`stringify5`). 엔진 `toJSON()` 이 이미 2/3/5자리로 반올림하지만, 파일 writer 경로에서 `stringify5` 를 통과시켜 규약을 단일화한다.
- **`replaceX` 식 DELETE+INSERT 금지** 규약과 같은 맥락: 다른 카메라 항목은 절대 건드리지 않는 **키 단위 upsert**.

### 4.7 동시성

- 자기 자신 중복 시작 → **409**.
- `PtzCalibrator`·`PlateDiscoveryJob`·`CaptureJob` 중 하나라도 running 이면 → **409** `"다른 잡이 카메라를 사용 중입니다"`. 캘리브레이션은 카메라를 수십 분 점유하므로 겹치면 양쪽 다 오염된다.
  - 구현: 잡 생성 시 `isBusy: () => boolean` 콜백들을 주입(서버 조립 지점에서 배선). 잡이 다른 잡의 클래스를 import 하지 않는다(의존 역전).

## 5. REST 라우트 (신규 `src/api/lensCalibRoutes.ts`)

`registerDiscoverRoutes` 패턴 — 얇은 진입점, zod 검증, 기존 라우트 불변·가산.

| 메서드 | 경로 | 바디/쿼리 | 응답 |
|---|---|---|---|
| POST | `/calibrate/lens/start` | `{ source: string, mode?: 'full'\|'verify'\|'distortion' }` (기본 `full`) | `{ ok, started, mode, total }` · 409 중복/점유 · 400 소스 오류 |
| POST | `/calibrate/lens/stop` | — | `{ ok, state }` |
| GET | `/calibrate/lens/status` | `?sinceSeq=N` | `LensCalibStatus`(logs=증분) |
| GET | `/calibrate/lens/result` | `?source=id` | 저장된 결과 전문 · 404 |
| POST | `/calibrate/lens/apply` | `{ source: string, enabled: boolean }` | `{ ok, enabled, restartRequired: true }` |

- 서버 등록은 **의존성 주입 시에만**(가산): `if (deps.lensCalib) registerLensCalibRoutes(...)` — 헤드리스 보존.
- 뷰어 컨텍스트 alias(`/viewer/api/...`)는 **만들지 않는다**. 정밀수집 UI 는 `/calibrate/*`·`/discover/*` 를 이미 절대경로로 호출하고 있다(app.js 실측) → 같은 규약을 따른다.

### 5.1 ★ 가드 테스트 등록 필수

`test/viewerPtzSyncCoverage.test.ts` 는 app.js 에 등장하는 **모든 라우트를 분류표에 강제 등록**시킨다. 누락 시 테스트가 실패한다.

- `MOVES_CAMERA['/calibrate/lens/start'] = 'CalibrationRunner 스윕 — goPtz/setCenter 로 카메라 점유(종료 시 원위치 복귀)'`
- `NO_MOVE`: `/calibrate/lens/stop`(중단 신호만), `/calibrate/lens/status`, `/calibrate/lens/result`, `/calibrate/lens/apply`(파일 IO)
- 잡 종료 시 프론트는 `syncPtzAfterJob(null)` 호출 — discPoll 과 동일. (엔진이 원위치 복귀시키지만 UI의 `state.ptz` 기준은 갱신돼야 한다.)

### 6.2 확인 대화상자

`full` / `distortion` 은 카메라를 길게 점유하므로 시작 시 `confirm()` 1회:
> `real-camera-2 를 약 25~40분간 점유하며 팬·틸트·줌을 반복 이동합니다. 진행할까요?`

`verify` 는 짧으므로(3줌×6클릭 ≈ 3분) 확인 없이 시작. — 소요 예상치는 모드별 격자 크기에서 산출한 값이며 **추정임을 문구에 명시**한다(실측 근거: 2026-07-26 verify 실측 ≈3분).

### 6.3 `core.js` 순수 헬퍼 — `lensCalibView(status)`

`discoverView` 미러. **브라우저 DOM 자동화가 이 저장소에 없으므로**(반복 확인된 사실), UI 로직의 검증 가능한 부분은 전부 순수함수로 뽑아 vitest 로 덮는다.

```js
export function lensCalibView(status) {
  // → { percent, label, startDisabled, stopDisabled, applyVisible, polling, tone }
}
```

| state | percent | label | start | stop | polling |
|---|---|---|---|---|---|
| idle | 0 | `idle 0/0` | 활성 | 비활성 | ✗ |
| running | done/total | `running 34/112 (30%)` | 비활성 | 활성 | ✓ |
| stopping | 유지 | `정지 중 — 카메라 복귀` | 비활성 | 비활성 | ✓ |
| done | 100 | `완료 — <판정>` | 활성 | 비활성 | ✗ |
| aborted | 유지 | `중지됨` | 활성 | 비활성 | ✗ |
| error | 유지 | `실패 — <사유>` | 활성 | 비활성 | ✗ |

`applyVisible` = `state==='done' && mode==='full'`(또는 distortion adopt).

### 6.4 폴링

`discPoll` 구조를 그대로 미러 — `pollPlan(state)` 재사용, `running|stopping` 에서만 폴, 타이머는 단일 변수 `lensPollTimer` 에 소유권 집중(2026-07-24 세션에서 확인된 "타이머 소유 단일 지점" 규칙).

### 6.5 완료 메시지

- `verify`: `판정 PASS · 최악 잔차 2.4px · 대응 17/18` + 줌별 표(잔차·적용게인·필요게인). 미측정 줌은 **사유와 함께** 표시(저조도/무늬부족).
- `full`: `표 생성 완료 · 화각 12점 · 게인 12점 · 건너뜀 2줌(사유…)` + `[이 표 적용]` 버튼 노출 + **"적용은 서버 재시작 후 반영됩니다"** 안내.
- `distortion`: `A/B adopt|reject · 권고 …` + 줌별 OFF→ON 잔차. reject 사유를 그대로 보여준다(2026-07-25 결론처럼 reject 가 정상 결과일 수 있다).

| 대상 | 영향 | 근거 |
|---|---|---|
| `packages/lens-calib` | **없음** (무변경) | 엔진은 이미 `onProgress`·`signal`·`goHome` 을 제공 |

| `realLensVerify.ts` (CLI) | 무변경·유지 | 커밋 제외 도구. 포트 조립 로직은 **복사 이식**(CLI 를 서버 모듈에 의존시키지 않는다 — .gitignore 파일이므로) |

### 드러내야 할 트레이드오프
1. **표 적용에 서버 재시작이 필요하다.** 핫리로드를 넣으면 `sourceRegistry` 를 재조립해야 하고 스트림 어댑터(ffmpeg)까지 얽힌다 — 요청 범위 밖이며 위험 대비 이득이 작다. 대신 UI가 재시작 필요를 **명시**한다.
2. **full 모드는 25~40분 카메라 점유**다. 정밀수집·센터라이징과 동시 실행 불가(409). 짧게 확인만 하려면 `verify`(≈3분)를 쓰라고 UI 가 안내한다.
3. **`full` 결과가 기존 `enabled:true` 를 false 로 강등**한다. 새로 잰 표를 사람이 검증하기 전에 자동 적용하지 않는다는 원칙(설계서 20260725 §10)의 귀결이지만, 실행 직후 조준 보정이 꺼진 상태가 된다는 뜻이기도 하다 → 시작 확인창과 완료 메시지 양쪽에 명시한다.
