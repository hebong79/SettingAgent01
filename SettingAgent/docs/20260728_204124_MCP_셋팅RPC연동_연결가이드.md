## 0. 왜 필요했나

RPC 평면(13020 `/rpc`)을 만들었지만 **MCP 클라이언트에서는 쓸 수 없었다.**

| 경로 | Unity 13110 제어 | 셋팅 13020 제어(70 메서드) |
|---|---|---|
| HTTP 직접(curl·스크립트·Claude Code 셸) | ✅ | ✅ |
| **MCP 도구**(Claude Desktop·Codex 등) | ✅ `unity_rpc` | ❌ **통로 없음** |

셸이 없는 MCP 클라이언트는 HTTP 를 직접 부를 수 없다. 즉 "셋팅을 외부에서 제어한다" 는 목적이 **LLM 클라이언트에 한해 미달** 상태였다.

---

## 1. 무엇을 했나

### 1-1. MCP 도구 2개 추가 (`src/mcp/server.ts`)

| 도구 | 역할 |
|---|---|
| `setting_rpc_catalog` | 13020 메서드 목록 + 메타(mutating·destructive·requiresCamera·stability·preconditions·note·available). `filter` 로 이름 부분일치 검색 |
| `setting_rpc` | 13020 메서드 호출. `unity.` 접두어를 붙이면 시뮬레이터로 전달 |

**메서드 70개를 개별 도구로 등록하지 않았다.** 범용 프록시 2개인 이유:

- 카탈로그가 자기 설명적이라 LLM 이 읽고 판단할 수 있다(파괴적인지·선행조건이 뭔지).
- RPC 메서드가 늘어도 **이 파일은 바뀌지 않는다** — 기존 `unity_rpc` 와 동일한 설계.
- 도구 70개는 클라이언트 컨텍스트를 크게 먹는다.

도구 설명에 두뇌가 판단해야 할 것을 명시했다(테스트로 고정):
- `destructive:true` 는 `confirm:true` 필요, 사용자가 명시 요청했을 때만 호출
- 오류 코드 의미 — **`-32001`(BUSY, 재시도 가능) vs `-32005`(CONFLICT, 재시도 무의미)**
- 호출 전 `setting_rpc_catalog` 로 확인할 것

### 1-2. `CRpcClient` 에 옵셔널 헤더 (`src/clients/CRpcClient.ts`)

`viewer.controlToken` 이 설정된 서버에서는 변이 메서드가 403 이 된다. MCP 가 `x-viewer-token` 을 실을 수 있도록 `headers?` 를 추가했다. **미지정 시 기존 동작 그대로**(Unity 호출자 무영향 — 테스트로 고정).

신규 클라이언트는 만들지 않았다. 우리 `/rpc` 규약이 Unity 와 동형이라 **같은 클라이언트를 재사용**한다.

### 1-3. ★ 실제 결함 수정 — MCP 진입점 경로가 틀려 있었다

`config/llm.config.json` 이 `node dist/mcp/server.js` 를 가리켰다. 그런데 `tsconfig.json` 이 `rootDir: "."` 이라 **빌드 산출물은 `dist/src/mcp/server.js`** 다.

즉 **빌드를 해도 그 경로에는 파일이 없어 MCP 가 뜨지 않는다.** 이 설정을 소비하는 코드가 아직 없어(MCP 클라이언트 미구현) 드러나지 않았을 뿐이다.

→ `llm.config.json` · `llm.config.example.json` 두 곳을 `dist/src/mcp/server.js` 로 수정하고, **설정↔산출 경로 정합을 테스트로 고정**했다(tsconfig 의 `outDir`/`rootDir` 에서 기대 경로를 계산해 대조).

## 2. 연결 방법

### 2-1. Claude Code (CLI)

```bash
# 빌드 없이(개발 중 권장)
claude mcp add parkagent -- npx tsx d:/Work/Parking3D/AgentVLA/ParkAgent/SettingAgent/src/mcp/server.ts

# 빌드본으로(운영)
cd d:/Work/Parking3D/AgentVLA/ParkAgent/SettingAgent && npm run build
claude mcp add parkagent -- node d:/Work/Parking3D/AgentVLA/ParkAgent/SettingAgent/dist/src/mcp/server.js
```

> Claude Code 는 셸이 있으므로 MCP 없이 `curl` 로도 RPC 를 쓸 수 있다. MCP 는 "도구로 노출" 이 필요할 때 쓴다.

### 2-2. Claude Desktop

`claude_desktop_config.json` 에 추가:

```json
{
  "mcpServers": {
    "parkagent": {
      "command": "npx",
      "args": ["tsx", "src/mcp/server.ts"],
      "cwd": "d:/Work/Parking3D/AgentVLA/ParkAgent/SettingAgent"
    }
  }
}
```

### 2-3. Codex

Codex 도 stdio MCP 를 지원하므로 동일한 `command`/`args`/`cwd` 를 자기 설정 형식에 넣는다.

### 2-4. 공통 전제

- **13020 서버가 떠 있어야 한다**(`npm start`). MCP 서버는 stdio 로 뜨지만 `setting_rpc` 는 13020 HTTP 를 호출한다.
- `cwd` 는 반드시 `SettingAgent` — `loadToolsConfig()` 가 `config/tools.config.json` 을 상대경로로 읽는다.
- 서버 미기동 시에도 **크래시하지 않는다** — `ok:false` + 연결 오류 메시지를 돌려준다(테스트로 고정).

## 3. 사용 흐름 (LLM 관점)

```
1) setting_rpc_catalog { filter: "place" }
   → place.space.add(mutating) · place.space.delete(destructive) · place.revert(destructive) …

2) setting_rpc { method: "slot.list" }
   → 슬롯 24건, lpd 23, centered 23

3) setting_rpc { method: "plate.pickAt", params: { cam:1, preset:1, point:{x:0.52,y:0.48} } }
   → quad · confidence · slotId 후보

4) setting_rpc { method: "place.space.add", params: { camId:1, presetIdx:1, points:[…] } }
   → idx 부여 · backupFile 반환(되돌릴 수 있다)

5) 파괴적 작업은 confirm 필요
   setting_rpc { method: "slot.roi.load" }                 → -32602 confirmRequired
   setting_rpc { method: "slot.roi.load", params:{confirm:true} } → 실행
```

## 4. 검증

### 4-1. 유닛테스트 — `test/mcpSettingRpc.test.ts` 14 green

`InMemoryTransport` 로 실제 MCP 클라이언트를 서버에 물려 프로토콜 그대로 검증한다.

| 그룹 | 고정하는 계약 |
|---|---|
| 도구 노출 | 신규 2개 등록 + **기존 5개 회귀 0** · 설명에 `destructive`/`confirm:true`/`-32001`/`-32005` 포함 · `filter` 파라미터 존재 |
| `setting_rpc` 위임 | **13110 이 아니라 13020** `/rpc` 로 감 · 봉투·params 전달 · **오류 code 를 detail 로 보존**(두뇌가 BUSY/CONFLICT 구분) · 연결 실패 시 크래시 없음 |
| `setting_rpc_catalog` | 전체/필터 · `totalBeforeFilter` 보고 · `GET /rpc/catalog` 호출 |
| `CRpcClient` 헤더 | 주입 시 실림(callRpc·getCatalog 양쪽) · **미지정 시 기존과 동일**(하위호환) |
| 진입점 경로 정합 | `llm.config` args == tsconfig 산출 경로(위 결함 재발 방지) |

## 6. 남은 정리 후보 (하지 않았음)

| 항목 | 왜 안 했나 |
|---|---|
| `camera_req_img` / `camera_req_move` 가 `unity_rpc` 와 기능 중복 | 편의 도구로 쓰이고 있을 수 있어 **임의로 제거하지 않았다**. 제거는 마스터 판단 |
| 카탈로그 기반 **도구 70개 자동 등록** | 컨텍스트 비용이 크고, 범용 2개로 목적이 달성된다. 필요해지면 착수 |
| MCP **클라이언트** 구현(`llm.config.mcp` 를 실제로 소비) | 이번 범위 밖. 현재 `AgentRuntime` 은 판정·자문 전용이고 tool-calling 루프가 없다 |
