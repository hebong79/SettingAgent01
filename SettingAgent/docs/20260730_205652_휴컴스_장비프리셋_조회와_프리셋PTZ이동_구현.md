# 휴컴스 카메라 장비 프리셋 조회 + 프리셋/PTZ 이동 (정보수집 페이지 PTZ 제어)

_2026-07-30 · 브랜치 `worktree-feat-hucoms-preset-ptz` · 워크트리 `.claude/worktrees/feat-hucoms-preset-ptz`_

## 0. 요청과 결과

**요청(마스터).** 휴컴스 카메라의 API로 프리셋 정보를 가져와 UI에 출력하고, 프리셋 이동 또는 PTZ 이동 형태로
구현한다(PTZ 값 UI 표시). 적용 위치는 **정보수집 페이지의 PTZ 컨트롤 부분**.

**결과.** 정밀 수집·제어 탭이 공유하는 우측 **PTZ 제어** 패널에

1. **장비 프리셋 목록**(카메라 장비에 저장된 프리셋 — `EV1`…) 표시,
2. **프리셋 이동**(선택 프리셋으로 물리 이동) + **PTZ 절대 이동**(기존 기능 유지),
3. **PTZ 값 표시** — 기존 뷰어 좌표에 더해 **장비 원시 PTZ**(`panpos/tiltpos/zoompos`) 줄 추가

를 붙였다. 실카 2대(192.168.0.153/154)에서 라이브로 확인했다(§5).

## 1. 먼저 확인한 사실 — “휴컴스 API에는 프리셋 **조회**가 없다”

문서와 장비를 모두 실측했다. 이 절이 설계의 전제다.

| 확인 대상 | 결과 |
|---|---|
| `HTTP_API_Hucoms_V1.22.pdf` §8.4 `preset_control.cgi` | `setpreset` / `gopreset` / `clearpreset` **셋뿐** — 목록·이름·PTZ 조회 명령 없음 |
| 실측 probe `action=getpreset·getpresetlist·getpresetname·getpresetinfo` | 전부 **HTTP 204 빈 응답**(= 알 수 없는 액션) |
| 실측 probe `preset.cgi`·`presetname.cgi`·`preset_name.cgi`·`ptzpreset.cgi` | 전부 **404** |
| `capabilityptz.cgi?action=getPTZ` | `PresetSupported = Yes` (지원한다는 사실만, 목록은 없음) |
| **ONVIF** `GetPresets`(`/onvif/device_service`) | **동작한다** — 토큰 `001`… + 이름 `EV1`… 반환 |

→ **목록 조회는 ONVIF 로만 가능하다.** 그래서 “목록만 ONVIF, 이동은 종전 Hucoms `gopreset`”으로 갈랐다.
이동 경로를 새로 만들지 않은 이유: 기존 Hucoms 이동 경로에 **정착(슬루 정지) 대기·PTZ 실측·패킷 로그**가 이미
붙어 있고 실카에서 검증돼 있다. 이동 경로를 둘로 늘리면 그 자산이 반씩 갈린다.

### 1-1. 장비가 **주지 않는 것**(은닉 금지)

`GetPresets` 응답의 `PTZPosition` 은 **전 프리셋이 x=0 / y=0 / zoom=0** 이다(cam1·cam2 동일).
즉 **프리셋별 PTZ 값은 API 로 알 수 없다.** 그래서 UI 는 프리셋의 PTZ 를 추정하지 않고,
**이동한 뒤 `getptzfpos` 로 실측한 값만** 표시한다(“미측정” → 이동하면 라벨에 실측 PTZ 가 붙는다).

### 1-2. 미설정 슬롯 판정(장비 quirk)

장비는 저장 여부와 무관하게 **255칸을 전부** 돌려준다. 실측한 미설정 칸의 `Name` 은
**“3자리 번호의 첫 글자가 제어문자(0x0A)로 바뀐” 형태**였다 — `021 → "\n21"`, `100 → "\n00"`, `254 → "\n54"`.
반면 **설정된 칸은 `"EV1\n"` 처럼 개행이 뒤**에 온다. 이 비대칭이 유일한 판별 근거다.

> **한계**: 사용자가 프리셋 이름을 **번호의 뒤 두 자리와 똑같이**(예: 21번을 `"21"`) 지어 두면 미설정으로 오판한다.
> 장비가 저장 여부 플래그를 주지 않으므로 이름 말고는 근거가 없다. (실측 필터 결과: cam1 = **24개**)

## 3. 동작 계약

### GET `/viewer/api/presets?source&cam` — 읽기(카메라 무이동)

```json
{ "presets": [ { "token": "001", "name": "EV1", "number": 1 }, … ], "count": 24 }
```

- 장비 프리셋 개념이 없는 소스(시뮬레이터)는 **501 `DEVICE_PRESETS_UNSUPPORTED`**.
  빈 목록으로 위장하지 않는다 — “프리셋 0개인 카메라”와 구분되지 않기 때문이다.
- 조회 실패(인증 거부 등)는 **502 + 장비가 준 사유 문자열** 그대로.
- `number` 가 없는 항목(비수치 토큰)은 UI 에서 **선택 불가**로 표시된다(= Hucoms `gopreset` 에 넣을 수 없다).

### POST `/viewer/api/preset/goto` `{source,cam,number}` — 변이(물리 이동)

```json
{ "ok": true, "number": 3, "ptz": { "pan": -131.22…, "tilt": -30.91…, "zoom": 20.22… },
  "native": { "pan": 4877, "tilt": 1611, "zoom": 8998 }, "settled": true }
```

- 게이트는 **`/move` 와 완전히 동일**하다: `viewer.allowMove:false` → 403, `controlToken` 불일치 → 403.
- `number` 는 1~255(Hucoms 규격) — 벗어나면 400이며 **소스는 호출되지 않는다**.
- **`settled:false`** = 장비가 멈춘 것을 확인하지 못했다(값이 이동 중일 수 있다). UI 가 그대로 알린다.
  프리셋의 목표 PTZ 를 모르므로(§1-1) “목표 근접”이 아니라 **“정지 확인”**으로 판정한다.

### GET `/viewer/api/ptz` — 기존 라우트에 `native` 가산

```json
{ "ptz": { "pan": -109.65…, "tilt": -12.10…, "zoom": 18.42… }, "native": { "pan": 7034, "tilt": 2760, "zoom": 8155 } }
```

`native` 는 **지원 소스에서만** 붙고, 원시값 조회가 실패해도 **뷰어 PTZ 응답을 깨뜨리지 않는다**
(표시·대조용이지 제어 근거가 아니다). 시뮬레이터 응답은 **종전과 바이트 동일**.

> 원시값이 왜 필요한가: 뷰어 좌표(`-180~180 / -90~90 / 1~36`)는 환산값이라 장비 OSD·로그·API 문서와 대조가 안 된다.
> 실측 대조 예 — OSD `70/27/x35` ↔ 원시 `panpos 7034 / tiltpos 2760`(centidegree) / `zoompos 8155`.

## 4. UI 사용법 (정보수집 = 정밀 수집 탭 · 우측 PTZ 제어 패널)

1. **소스**를 실카(`real-camera-1/2`)로 선택 → 장비 프리셋 블록이 열리고 **목록이 자동 조회**된다(무이동).
2. 프리셋 선택 → **[프리셋 이동]** → 이동 완료 후 **현재 PTZ**(뷰어 좌표)와 **장비 원시** 줄이 갱신되고,
   그 프리셋의 라벨에 실측 PTZ(`— P 8245 / T 2098 / Z 12686`)가 붙는다.
3. **PTZ 이동**은 기존 ‘절대 이동’(pan/tilt/zoom 입력 → [이동])과 방향 패드를 그대로 쓴다.
4. **[목록 불러오기]** 는 장비에서 목록을 다시 읽는다(카메라를 움직이지 않는다).

- 시뮬레이터 소스에서는 블록과 원시 PTZ 줄이 **숨는다**(장비 프리셋 개념이 없다).
- **순회(Touring) 중**에는 프리셋 이동 버튼이 잠긴다(기존 수동 이동과 동일 규칙).
- 실측 PTZ 라벨은 **세션 메모리에만** 남는다 — 파일·DB 에 아무것도 쓰지 않는다.

- 외부 제어자용 **RPC 메서드**(`cam.device.preset.*`)는 만들지 않았다. 요청은 UI 였다.

## 6. 영향도 분석

### 6-1. 회귀 없음의 근거

| 대상 | 판단 |
|---|---|
| `CameraSource` 구현체(`SimulatorSource`·`RpcCameraSource`·`CameraposSource`) | 추가한 3개 메서드가 **전부 optional** — 구현 무변경, 컴파일·동작 영향 0 |
| `GET /viewer/api/ptz` 기존 소비자(`realCamCapture.ts`·`app.js`·RPC `cam.getPtz`) | 응답에 **키 하나 추가**(가산). 기존 필드·값 불변, 미지원 소스는 종전과 동일 JSON |
| `RealPtzSource` 기존 경로(`move`/`snapshot`/`centerOnPoint`/`streamMjpeg`) | 코드 무변경. 생성자에 **6번째 optional 인자**만 추가(기존 4곳의 호출부 전부 그대로 컴파일) |
| ONVIF 클라이언트 | **지연 생성** — 장비 프리셋을 조회하지 않으면 소켓 하나 열리지 않는다. 시뮬 환경 영향 0 |
| 정본·DB | **무접촉** — `camerapos.json`·`PtzCamRoi.json`·`setting.sqlite` 를 읽지도 쓰지도 않는다 |
| 뷰어 기존 UI | 추가 요소는 **기본 숨김**이며 실카 선택 시에만 열린다. 시뮬 화면은 종전과 동일 |

### 6-2. 주의가 필요한 곳

1. **`camerapos.json` 프리셋과 장비 프리셋은 다른 것이다.** 화면에 프리셋 셀렉트가 둘이 된다
   (상단 ‘대상 선택’ = 파일 프리셋, PTZ 제어 안 = 장비 프리셋). 라벨·툴팁·설계 주석에 그 구분을 명시했으나,
   **운영 중 혼동 가능성은 남는다.** 둘을 잇는 기능(장비 프리셋 → camerapos 등록)은 이번 범위에 넣지 않았다.
2. **장비 프리셋 이동은 카메라를 실제로 움직인다.** 정밀수집·센터라이징·순회 잡이 도는 중에 누르면
   경합한다. 화면단에서 `ptzBusy`·`touringActive` 로 막지만, **서버는 막지 않는다**(마지막 명령이 이긴다) —
   기존 수동 PTZ 와 같은 수준의 방어다.
3. **비밀번호 경로.** ONVIF 는 Hucoms 와 **같은 자격증명**(config `password` / `passwordEnv`)을 쓴다.
   UI 로그인으로 자격증명이 바뀌면 ONVIF 클라이언트를 폐기·재생성한다. 평문 비밀번호가 `tools.config.json` 에
   남아 있는 기존 이슈(`real-camera-1`)는 이 작업과 무관하게 **그대로**다.
4. **목록 응답 크기.** 장비는 255칸을 전부 보내므로 응답 XML 이 수십 KB 다. 필터는 서버에서 하고
   브라우저에는 설정된 것만 간다. 조회 시간은 실측 0.5~1초 수준.
