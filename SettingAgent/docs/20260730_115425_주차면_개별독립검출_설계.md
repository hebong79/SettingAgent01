## 0. 결론 (맨 앞)

**권고: 「면별 독립 닫힘」(A안) — 한 주차면을 「인접한 두 분리선 + 규격 치수」로 각각 따로 닫고, 면 하나하나를 자기 증거로만 채택한다.** 행 단위 격자·행 단위 점수·개수 분모를 전부 없앤다. 위치는 그 면의 두 분리선이 정하고(증거), 치수는 규격 2.5×5.0m 가 정한다(F7 — 확립사실, 바꾸지 않는다). 면이 여러 개 겹쳐 나오면 기존 `quadIoU` 로 **배타성**만 해소한다. 근변선은 지금처럼 **행 단위**로 유지한다(면별로 쪼개면 지레팔이 짧아져 U10 의 회전 편향이 되살아난다 — 8회차 실측).

이 구조에서 `expectedBays` 는 **참조할 자리가 없다**. 격자 위상도 없다(면의 경계가 곧 검출된 선이므로 "반칸 밀린 위상"이라는 상태 자체가 표현 불가능하다). 신규 수치 튜닝 축은 **1개**(`widthTolRatio`)뿐이고 나머지는 기존 옵션(`extendMinNearSupport`·`rowMergeIoU`·`maxGap`·`maxHeightCorrection`)을 재사용한다.

**대가는 가림이다.** 격자에는 보간이 있었고(`filledIndices`) 독립 검출은 보간할 수 없다. → 채택된 면 **사이**의 내부 결손만 별도 단계로 보간하고(외삽 금지), 응답에서 `origin:'evidence' | 'interpolated'` 로 구분한다(현행 자홍색 오버레이 규약 계승). 골든에서 보간이 실제로 기여한 면 수는 **미측정 — 구현자 실측 필요**(§9-2).

**단, A안 성립 여부는 아직 측정되지 않은 한 숫자에 걸려 있다**: 참 주차면 경계 중 몇 %가 ±허용치 안에 분리선을 갖는가(§3-1, §9-1). 그 값을 Phase 0 에서 재기 전에는 배선하지 않는다. 낮게 나오면 B안으로 전환한다(§5).

### 1-1. 리더가 확정한 것 (재확인: 코드로 검증했다)

### 1-2. ★ 설계자가 코드에서 새로 찾은 것 — 근변 지지는 **위상에 눈이 멀었다**

20c 는 "`paint.score`(칸당 평균) vs `coverage`(칸 개수)의 척도 불일치"를 원인으로 짚었다. 맞다. 그런데 **왜 증거 항이 애초에 그렇게 약했는가**가 남아 있고, 그것이 방향 전환의 진짜 근거다.

`quadPaintSupport`(`bayGeometry.ts:654-679`)는 `paint.score = near·1.0 + side·0.5 + far·0.3` 이다. 각 변이 어디에 놓이는지 보면:

| 변 | 좌표(`buildAtPhase`, `bayGrid.ts:215-219`) | 위상 `a` 에 의존? |
|---|---|---|
| 근변 `p0→p3` | `(a,0) → (a+w,0)` — **전방선 위** | **아니다.** 전방선은 행 전체에 연속인 도색 띠다. 위상을 옆으로 밀어도 근변은 여전히 같은 띠 위에 있다 |
| 원변 `p1→p2` | `(a,depth) → (a+w,depth)` — 원변 도색선 위 | **아니다.** 같은 이유(u 방향으로 뻗은 선) |
| 좌우 `p0→p1`, `p3→p2` | `(a,0) → (a,depth)` — **분리선 위** | **그렇다.** 위상 정보를 가진 유일한 항 |

**즉 `paint.score` 의 가중 총합 1.8 중 위상을 아는 성분은 `side` 0.5 = 27.8% 뿐이다.**

20c 실측표가 정확히 이 예측을 확인한다:

| 항 | P_정답 | P_반칸 | 차 |
|---|---|---|---|
| near | 1.0000 | 0.8980 | +0.1020 ← 양 끝 반쪽 칸이 프레임 경계를 벗어난 부수효과일 뿐 |
| **side** | **0.8413** | **0.6837** | **+0.1576** ← 실제 판별 성분 |
| far | 0.4921 | 0.5442 | **−0.0521** ← 오답을 밀어준다 |
| score | 1.568254 | 1.403061 | +0.165193 |

`side` 가 실제로 판별한다(+0.1576). 그런데 가중 0.5 를 먹어 `0.0788` 밖에 기여하지 못하고, `far` 는 오답 쪽으로 −0.0156 을 보탠다. 총 격차 0.165 는 커버리지의 길이 보너스(+16.7%)에 뒤집혔다.

**여기서 세 반증이 한꺼번에 설명된다.**
- **#5 `phaseFitM` 가중 상향**이 실패한 이유: `phaseFitM` 은 검출 코너와 격자 경계의 거리 = 위상의 **간접 대리 지표**다. 직접 지표(`side`)가 27.8% 로 억눌려 있는데 대리 지표를 올려도 신호 대 잡음이 개선되지 않는다. (리더 판정대로 재시도 금지 — 이 설계는 `phaseFitWeight` 를 건드리지 않는다. **기록: `phaseFitWeight = 0` — 위상이 핵심 결함인데 위상 항이 완전히 꺼져 있었다.**)
- **#8 `farWeight` 상향**이 실패한 이유: `far` 는 위상에 눈이 멀었고, 위 표에서는 오답을 밀어준다.
- **#7 도색지지 단독 적용**이 실패한 이유: 도색지지 자체가 72.2% 위상맹(盲)이라 단독으로 세우면 판별력이 더 얇아진다.

### 1-3. 그래서 무엇을 바꾸는가

위상을 아는 증거는 **분리선**이다. 그런데 현행 파이프라인은 분리선을 **버린다**:

```
roiAuto.ts:837-844
  const seps = refineSeparators(...)            ← RefinedLine (직선 방정식·잔차·스팬)
  for (const sep of seps) pts.push(meetLines(sep.line, front.line))   ← 교점 1개만 남기고 직선을 버린다
  cands.push({ front, cornersPx: pts })
```
그리고 `bayGrid.fitRowGridOnce` 는 그 교점을 **위상 후보 씨앗**으로만 쓴다(`:292-294`). 실제 격자는 상수 피치 2.5m 를 위상 하나로 밀어 세우고, 채택 여부는 **행 전체를 하나로 묶은 평균 점수 × 칸 개수**가 정한다.

**결함의 뿌리는 「행을 한 덩어리로 놓고 개수로 채점한다」는 결정 단위다.** 그 단위 안에서는
- 위상이 자유변수로 남고(반칸 미끄러짐 가능),
- 분모가 개수여서 `expectedBays` 가 스며들고(`:393`),
- 위상을 아는 유일한 증거가 행 평균으로 희석된 뒤 27.8% 가중을 먹는다.

**결정 단위를 「면 1개」로 내리면 세 가지가 동시에 사라진다.** 면의 경계가 곧 검출된 분리선이므로 위상이라는 자유변수가 없고, 채택이 면별이므로 분모가 없고, 분리선 증거가 희석되지 않고 그 면의 존재 근거 자체가 된다.

### 2-1. 리더가 물은 세 가지에 대한 답

**(a) `scanSeparators`/`refineSeparators` 가 내는 분리선은 개별 주차면 경계로 쓸 만한가?**

코드가 말하는 것과 보고서가 말하는 것까지만 적는다. **성립 판정의 핵심 수치는 아직 없다.**
- `floorPaint.ts:757-761` (구현자 실측 주석): 실제 분리선은 차량에 가려 **30~120px 스텁**이고, 전역 Hough 로는 차체 모서리에 묻힌다. 전방선 위 국소 탐색으로 바꾸면 **"참 코너 전부의 근방 2.6~31px 에 후보 생성 — 다만 오검출도 함께 늘어난다."**
- 즉 **적중률(누락)은 좋고 정확도 상한(2.6~31px)과 오검출이 문제**다. 다만 이 2.6~31px 는 `scanSeparators` **씨앗**의 값이고, 그 뒤 `refineSeparators` 가 좁은 창(`separatorProfileHalfPx=14`)으로 서브픽셀 정련한다. **정련 후 오차는 측정된 기록이 없다.**
- 20c 간접 증거: 정답 위상이 **모든 `bays` 값에서 후보 목록 안에 있었다.** 위상 후보는 `evid`(= 분리선 교점의 폭좌표)와 균등 스윕 40분할의 합집합이므로, 정답 위상이 스윕에서 왔는지 코너에서 왔는지는 **구분되어 있지 않다** — 이것을 분리선 품질의 증거로 쓰면 안 된다.

→ **판정 보류. Phase 0-b 에서 재야 하는 단일 숫자: 「씬 정답 면의 참 경계 폭좌표 중 몇 %가 정련된 분리선을 ±0.25m 안에 갖는가」와 그 오차 분포·행당 오검출 수.** 이 값이 A안 재현율의 **원리적 상한**이다. 추정치를 쓰지 않는다.

**(b) 한 면을 독립으로 닫는 데 최소한 무엇이 필요한가 / 근변선은 면별인가 행 단위인가?**

한 면 = **두 경계 폭좌표 + 근변선 + 규격 깊이**. 근변선은 **행 단위로 남긴다.** 근거는 추측이 아니라 실측이다:
- U10(7회차): 결손 전체가 근변선 배치 오차이고, 그것은 평행이동이 아니라 **회전 0.16~0.31°** 다. 원인은 "부분 가림된 짧은 지지구간 위 TLS 적합 → 지레팔이 짧아 각도 편향"(`bayGrid.ts:480-487`).
- 8회차 해법이 정확히 그 반대 방향이었다: 행 **전 구간**으로 지레팔을 늘려 2-DOF 재적합 → 1:1 0.9547→0.9767, 2:1 0.9312→0.9662.
- **면별로 근변선을 다시 적합하면 지레팔을 다시 짧게 자르는 것**이므로 U10 을 되살린다. 하지 않는다.

**(c) 면별 신뢰도를 무엇으로 정의하는가? `paintEvidenceOf` 를 그대로 쓸 수 있는가?**

쓸 수 있다 — `quadPaintSupport` 는 `readonly BayQuad[]` 를 받으므로 길이 1 배열을 넘기면 그대로 면별 값이 나온다. 이미 `roiAutoRecall.ts:169` 가 정답 면 1개에 그렇게 쓰고 있다(선례 있음).

**그러나 면별 신뢰도를 `side` 에 기대면 안 된다 — 자기충족이다.** 면의 좌우 변이 「검출된 분리선」이면 `edgePaintSupport` 는 정의상 도색에 붙어 있으므로 `side ≈ 1` 이 자동으로 나온다. 스스로 고른 선 위에서 스스로를 채점하는 것이므로 정보가 0 이다. **이 함정은 설계에 명시해 둔다.**

그래서 신뢰도는 **새 가중식을 만들지 않고** 다음 3층으로 둔다:

| 층 | 내용 | 새 파라미터 |
|---|---|---|
| **경성 게이트 ①** 기하 | 두 경계 간격이 규격 폭과 맞는가: `\|Δa − slotWidthM\| ≤ slotWidthM · widthTolRatio` | **`widthTolRatio` (신규 1개)** |
| **경성 게이트 ②** 증거 | 이 면의 근변 도색 지지 `paint.near ≥ extendMinNearSupport` | 기존(0.35) |
| **서열** | `paint.score`(면 1개 기준) desc → `\|widthDevM\|` asc → `rowKey` asc → `centerAM` asc | 없음 |

서열은 **배타성 해소 순서를 정하는 데만** 쓴다. 위상은 서열이 정하지 않는다 — 위상은 게이트 ①이 정한다(간격이 규격과 맞지 않는 쌍은 존재 자체가 기각). 따라서 `paint.score` 의 위상맹(§1-2)이 여기서는 무해하다. **새 수치 튜닝 축 1개.**

## 3. 권고 아키텍처 A — 면별 독립 닫힘

### 3-1. 절차 (한 행 = 전방선 후보 1개)

```
1) front(전방선) → rowFrameFromLine(model, front.line)      ← 기존
2) 분리선 s_1..s_m 각각: a_k = widthCoordOf(fr, model, meetLines(s_k, front))   ← 기존
   품질 q_k = { residPx: s_k.residPx, spanPx: s_k.spanPx }  ← 지금 버려지는 값
3) 모든 쌍 (i<j) 에 대해  Δ = a_j − a_i
   게이트①: |Δ − w| ≤ w·widthTolRatio            → 면 1개 후보
   ★ 인접 쌍만 보지 않는다. 오검출 분리선이 한 면 안에 끼면 인접 쌍은 둘 다 ~w/2 로 기각되고,
     그 오검출을 건너뛴 쌍이 통과한다. 오검출에 대한 내성이 이 한 줄에서 나온다.
4) 위치 = 두 관측의 평균:  aLo = (a_i + (a_j − w)) / 2       ← 최소제곱(관측 2개, 미지수 1개)
   치수 = 규격:            폭 w = slotWidthM, 깊이 = slotDepthM     ← F7, 바꾸지 않는다
5) quad = canonicalizeQuad([ P(aLo,0), P(aLo,depth), P(aLo+w,depth), P(aLo+w,0) ])   ← 기존 pointAt·projectToPixel
6) 게이트②: quadPaintSupport([quad]).near ≥ extendMinNearSupport
7) 살아남은 것 = 이 행의 면 후보. 격자 인덱스도 위상도 개수도 없다.
```

**「위치는 증거에서, 치수는 규격에서」가 이 설계의 축이다.** 폭을 측정값 `Δ` 로 쓰면 안 되는 이유는 명확하다 — 현행 산출 quad 의 치수는 이미 **정확히 2.500/5.000**(U12 실측)이고 잔여 오차는 전부 근변선 배치다(U10). 측정 폭을 쓰면 지금 없는 폭 잡음을 새로 넣는다. 목표②(IoU ≥0.95)에 역행한다.

### 3-2. 전 행 통합 — 배타성

```
pool = 모든 (전방선 후보 × v방향 2 × 면 후보)
정렬: paint.score desc → |widthDevM| asc → rowKey asc → centerAM asc     (난수 0, 동점 결정론 = R2)
accepted = []
for b of pool:  if accepted 중 quadIoU(b.quad, ·) ≥ rowMergeIoU 인 것이 없으면 accept
```

행 사이 경쟁이 없다. 행이 **이기거나 지지 않는다** — 각 행은 자기가 닫을 수 있는 면만 내놓는다. 이것이 `dedupeRows`(행 통째로 버림, `bayGrid.ts:557-578`)와 `rowMinScoreRatio` 진입 문턱(`:649`)을 **대체**한다.

`rowMergeIoU`(=0.5) 를 재사용한다. 뜻이 같다("두 quad 를 같은 칸으로 볼 최소 IoU").

### 3-3. 자가보정과 근변선 재적합 (2패스 — 현행 구조 계승)

1패스: 공칭 지상고로 위 절차 → 채택 면들의 증거 간격 `Δ` 들 → `factor = slotWidthM / median(Δ)` → `|factor − 1| ≤ maxHeightCorrection` 이면 채택. 게이트①의 허용치(수 %~십수 %)가 알려진 +1.0% 스케일 편차(F6)를 흡수하므로 1패스에서 후보가 죽지 않는다.
2패스: 보정 모델로 다시 닫는다. 그 뒤 행별로 `refitFrontLineOverRow`(기존, 그대로) → 3패스 재닫힘. 현행 `detectBaysWithModel` 의 ①선별 ②보정 ③재적합 3단 구조를 그대로 따른다.

## 4. ★ 가림(occlusion) 트레이드오프 — 정면 서술

### 4-1. 무엇을 잃는가

격자 적합에는 보간이 있었다. `bayGrid.ts:351-356` 이 채택 창 **내부**의 결손 칸을 되살리고 `filledIndices` 에 담으며, 오버레이가 자홍색으로 표시한다. 차량이 도색을 통째로 덮어도 격자가 그 칸을 채운다.

**독립 검출은 그럴 수 없다.** 두 분리선 중 하나라도 가려지면 그 면은 닫히지 않는다. 마스터 목표①이 "보이는 모든 주차면"(재현율)이므로 이것은 **정면 손실 위험**이다.

측정된 사실 두 개만 적는다.
- 20c 의 임의 뷰 A 에서 승자 두 위상 모두 **보간 0칸**이었다. 그 뷰에서 보간의 기여는 0 이다.
- **골든 5프리셋에서 보간이 매칭 24면 중 몇 면을 기여했는지는 미측정이다.** `roiAutoRecall.ts:193` 이 `보간N` 을 행별로 찍기는 하지만 그 칸이 **정답과 매칭됐는지**는 출력하지 않는다. → **구현자 실측 필요**(Phase 0-c). 이 숫자가 A안의 재현율 손실 상한이다. 추정으로 채우지 않는다.

### 4-2. 선택 — ⓑ(사후 보간을 별도 단계로)

ⓐ(보간 없음)는 정직하지만 목표①을 자진해서 깎는다. ⓑ를 택한다. 단 조건을 붙인다:

1. **보간은 채택된 면 사이에서만.** 두 채택 면의 폭좌표 간격이 `k·slotWidthM`(k≥2, `k−1 ≤ maxGap` 재사용) 에 허용치 안에서 맞을 때 그 사이를 `k−1` 개로 나눈다. **양 끝 밖으로는 한 칸도 외삽하지 않는다.** 18회차가 세운 규약("구멍은 양쪽이 증거로 둘러싸인 구간 = 보간, 근거 있음 / 행의 끝 너머는 한쪽만 = 외삽, 근거 없음", `bayGrid.ts:306-309`)을 그대로 계승한다.
2. **격자를 다시 세우지 않는다.** 보간 면의 좌표는 두 이웃 채택 면의 폭좌표에서 선형으로 나온다 — 새 위상 변수를 도입하면 이 설계의 목적을 스스로 깬다.
3. **응답·오버레이에서 구분한다.** `origin:'interpolated'`, 오버레이 **자홍색**(현행 규약 계승). 채점 하네스는 재현율·정밀도를 **두 벌**로 낸다: 증거만 / 증거+보간.
4. **`interpolateGaps` 는 끌 수 있다.** ⓐ와 ⓑ의 A/B 를 한 번의 스위치로 재기 위해서다(설정 유연성이 아니라 측정 장치).

### 4-3. 오검출/미검출 비용 비대칭을 설계에 반영

마스터 구상 3단계(찾고 → 리스트 → **사람이 선택**)에서 **미검출은 회복 불가**(목록에 없으면 고를 수 없다)이고 **오검출은 사람이 한 번 넘기면 끝난다.** 그래서:
- 게이트는 **두 개만**(§2-1) 두고, 추가 억제 문턱(`rowMinScoreRatio`·`rowMinNearSupport` 류)을 새로 만들지 않는다. 19회차가 그 문턱을 도입한 이유는 "정밀도 0.1832 인 사람이 쓸 수 없는 목록"이었는데, 그 폭증은 **행 전체가 통째로 산출되던 구조** 때문이다. 면별 게이트에서 같은 폭증이 나는지는 **측정으로 확인한다** — 나면 그때 문턱을 논한다.
- 목록은 `origin`·`paint.score`·`widthDevM` 을 함께 실어 **사람이 스스로 순위를 볼 수 있게** 한다.
- 채점 보고는 재현율을 1순위, 정밀도를 2순위로 읽는다(§7 게이트).

**정직한 결론: A안은 「도색이 보이는 면」에서는 재현율이 오르거나 같을 가능성이 크고(위상 오선택으로 문턱 아래에 깔려 탈락하던 면이 살아난다 — 20b 실측 미매칭 IoU 0.33~0.47), 「두 경계가 다 가려진 면」에서는 보간을 켜지 않으면 확실히 떨어진다. 두 효과의 합은 측정 전에는 모른다.**

1. **위상을 없앤다(B는 옮긴다).** 마스터가 지시한 것은 "가장 근본적으로"다. B안은 반칸 위상 칸을 여전히 후보로 만들고 그것을 점수로 이기라고 요구한다 — 20회차가 두 라운드를 쓴 바로 그 싸움이다.
2. **기존 경로를 건드리지 않는다.** A안은 `bayGrid.ts` 0줄 수정이 가능하다(신규 파일 + 서비스 분기). 골든 v1 이 비트 단위로 살아 있으므로 **A/B 기준선이 오염되지 않는다** — 20회차 함정 (d) 를 원천 회피한다. B안은 `coverage`/`denom` 제거를 위해 `bayGrid` 를 고쳐야 하고 그 순간 `refScore`(`:632-640`)를 통해 골든이 움직인다.
3. **오검출 규모가 훨씬 작다.** A안 후보 수 = Σ(행별 분리선 쌍) ≈ 수십. B안 = 수천.

**B안은 폐기하지 않는다.** Phase 0-b 에서 분리선 적중률이 낮게 나오면 A안의 재현율 상한이 그 값에 묶이므로, 그때 B안(격자가 후보를 만들고 면별 증거가 고른다)으로 전환한다. 그 분기 조건을 Phase 0 게이트에 명문화한다(§8). **C안은 기각** — 반증 #8 과 정면 충돌한다.

## 7. 채점·회귀 유지와 A/B

### 7-1. 봉인 유지

`sceneTruth.ts`·`roiAutoRecall.ts`(순수 채점 모듈) **무접촉**. 재현율·정밀도·매칭 IoU·매칭 임계 0.5·가시 판정(면적 ≥200px²)·`PLANE_Y_M=0.05` 전부 그대로. 신규 모듈 `bayIndependent.ts` 는 `test/roiAutoHoldout.test.ts` 의 `DETECT_MODULES` 에 **추가해야 한다** — 넣지 않으면 같은 파일의 메타 테스트(`roi.auto 가 쓰는 ground 모듈은 전부 봉인 대상이거나 명시적 예외다`)가 배선 시점에 터진다. 14회차에 `bayGrid.ts` 가 봉인을 2라운드 빠져나간 사고의 방어 장치다.

### 7-2. A/B 구조 — 가능하다. 그것이 A안을 고른 이유 중 하나다

```
A(기준선) : npx tsx src/tools/roiAutoRecall.ts v1 evidence rows            ← 기존 경로, 0줄 변경
B(신규)   : npx tsx src/tools/roiAutoRecall.ts v1 evidence rows --engine=independent [--no-interp] --raw
```
같은 프레임 파일(`test/fixtures/roiAutoGolden/frame_*_d0.jpg`) · 같은 프레임해시 5개 · 같은 정답 · 같은 채점기. **검출 엔진만 갈아 끼운다.** A안이 `bayGrid.ts` 를 0줄 고치므로 A 는 매 실행에서 기준선을 **원시 배정도로** 재현해야 하며, 그것 자체가 실험 유효성 검사다.

**기준선(변경 금지 · 프레임해시 병기)**
```
재현율 0.5854 (24/41) · 가림보정 0.8571 · 정밀도 0.8571 (24/28) · 매칭 IoU 0.88860 (최소 0.61302, ≥0.95 8면 · ≥0.98 1면)
1:1 6006a034bfe2 / 1:2 ceaaed722663 / 1:3 3c0db12efe75 / 2:1 e33628e921c2 / 2:2 0cf4fda4d3aa
```

### 7-3. `--raw` (QA 가 잡은 구멍)

`src/tools/roiAutoRecall.ts` 의 매칭 IoU 출력은 `toFixed(5)`(`:198`·`:215`)라 5e-6 미만 변화를 못 잡는다. 재현율·정밀도는 정수비(24/41·24/28)라 안전하다. → **`--raw` 플래그로 `meanIoU`·`minIoU`·쌍별 IoU 를 원시 배정도로 덤프**한다. Phase 0 에서 먼저 넣는다 — 이후 모든 비교가 원시로 이뤄지게.

### 7-4. ★ 21회차 1순위 부채(`rows` 문턱이 `effectiveScore` 에 종속)와의 관계

| | 판정 |
|---|---|
| 신규 경로가 이 부채를 **해소**하는가 | **해소한다 — 구조적으로.** A안에는 `effectiveScore`·`refScore`·`rowMinScoreRatio` 가 없다. 목록 진입은 면별 게이트 2개가 정하고 행 점수가 목록을 흔들 경로가 존재하지 않는다 |
| **우회**하는가 | 구 경로에 대해서는 우회한다. `bayGrid.ts` 를 0줄 고치므로 그 결합은 구 경로에 그대로 남는다 |
| **악화**시키는가 | 아니다. 구 경로에 새 결합을 만들지 않는다 |

**★ 리더 확인 필요 — 나는 착수 순서 ①을 건너뛰기를 권고한다.** ①의 목적은 "위상 실험이 골든을 오염시켜 A/B 가 불가능하다"였다. A안은 위상 실험을 하지 않고 `bayGrid.ts` 를 건드리지 않으므로 **오염 경로가 애초에 없다.** 반대로 ①을 먼저 하면 `rows` 진입 규칙이 바뀌어 **골든 정밀도(24/28)가 움직이고, 우리가 비교하려는 A 기준선 자체가 이동한다.** ①은 「격자 경로를 계속 튜닝할 경우의 선행 과제」로 재분류하기를 권고한다. 이것은 리더의 확정 결정과 충돌하므로 **진행 전 확인을 요청한다.**

### 7-5. 게이트 제안 (★ 수치는 리더 승인 필요)

20c 의 G3("골든 3지표 전부 개선 또는 동일")를 그대로 쓰면 A안은 재현율·정밀도가 동시에 오르지 않는 한 무조건 탈락한다. 목표①(재현율)과 목표②(IoU)의 우선순위를 리더가 정해야 한다. 설계자 제안:

| 게이트 | 조건 |
|---|---|
| **H1** 무회귀 | `engine=lattice` 로 돌린 골든 3지표·프레임해시 5개가 기준선과 **원시 배정도 동일** |
| **H2** `expectedBays` 무관 | `bays ∈ {1,2,4,7,8,12,16}` 전 구간 산출 좌표 비트 동일(유닛테스트) |
| **H3** 재현율 | 증거+보간 기준 **≥ 0.5854**. 증거만 기준도 함께 보고 |

## 11. MCP 도구 vs LLM 두뇌 경계

이 기능은 **전량 결정형 도구**다. 쌍 열거·기하 게이트·역투영·배타성 해소·채점은 모두 수치 반복이며 LLM 호출이 0이다(현행 `roi.auto.*` 와 동일). 모호·맥락 판단이 개입하는 자리는 마스터 구상 3단계의 **「선택」**(사람이 목록에서 고르고 번호를 배정)이며, 그것은 이번 범위 밖이다. `Math.random` 0 · 순회 순서 고정 · 동점은 낮은 인덱스(R2) — 봉인 테스트가 이미 강제한다.
