# SettingAgent 독립 서버(13021) 기동 + Claude MCP 연결 — 세션 격리 환경 구축

_작성: 2026-07-29 00:02:46 · 워크트리 `feat-standalone-mcp` / 브랜치 `worktree-feat-standalone-mcp` (main `19d5ad2` 분기)_

## 1. 목적

이미 다른 세션이 **13020 포트로 SettingAgent 서버를 띄워 작업 중**인 상태에서,
같은 저장소를 건드리지 않고 **별도 서버 인스턴스를 띄워 Claude(MCP)에 물리는 것**이 가능한지 확인하고 구축한다.

성공 기준:
1. 두 서버가 동시에 살아 있어도 서로의 **포트·설정·DB·저장물이 섞이지 않는다**.
2. Claude 가 MCP 도구(`setting_rpc` / `setting_rpc_catalog`)로 **새로 띄운 서버(13021)** 를 호출한다 — 13020 이 아니라.
3. 위 2번이 **추정이 아니라 실증**으로 확인된다(차동 검증).

## 2. 왜 가능한가 — 코드 근거

| 근거 | 위치 | 의미 |
|------|------|------|
| 설정 경로가 cwd 상대 | `src/config/toolsConfig.ts:419` `loadToolsConfig(path = 'config/tools.config.json')` | 프로세스 cwd 를 바꾸면 **다른 설정 파일**이 로드된다 |
| DB·저장물 경로가 cwd 상대 | `tools.config.json` 의 `capture.dbFile`, `store.dataDir/saveDir/reportsDir` | 워크트리에서 띄우면 **DB·저장물도 자동 분리** |
| 포트가 설정값 | `tools.config.json` → `server.port` | 한 줄 변경으로 충돌 회피 |
| MCP 가 자기 포트를 설정에서 읽음 | `src/mcp/server.ts:31-35` `baseUrl: http://localhost:${cfg.server.port}` | MCP 프로세스의 **cwd 가 곧 대상 서버 지정**이 된다 |

즉 **코드 수정 0줄**로 격리가 가능하다. 바꾼 것은 워크트리 사본의 설정 한 줄뿐이다.

## 3. 구축 절차 (실제 수행한 것)

### 3.2 의존성 — `node_modules` 정션 링크
워크트리에는 `node_modules` 가 없다(gitignore). npm workspaces 로 재설치하면 `sharp`·`better-sqlite3` 네이티브 빌드가 다시 돌아 오래 걸리므로 **메인 저장소의 `node_modules` 를 정션으로 재사용**했다.

```powershell
New-Item -ItemType Junction `
  -Path   "…\.claude\worktrees\feat-standalone-mcp\node_modules" `
  -Target "D:\Work\Parking3D\AgentVLA\ParkAgent\node_modules"
```

> ⚠️ 부작용: workspace 심링크(`node_modules/@parkagent/types`, `node_modules/parkagent-setting`)는 **메인 체크아웃**을 가리킨다.
> `packages/types` 를 이 워크트리에서 수정하면 그 변경은 반영되지 않는다(이번 작업은 types 무변경이라 무해).
> types 를 건드릴 작업이면 정션을 지우고 워크트리 루트에서 `npm install` 해야 한다.

### 3.3 DB 스냅샷 (실행 중인 13020 의 DB 는 무접촉)
파일 복사가 아니라 **SQLite backup API** 로 일관 스냅샷을 떴다(13020 이 WAL 을 잡고 있으므로 raw copy 는 위험).

```js
new Database('…\SettingAgent\data\setting.sqlite', { readonly: true })
  .backup('…\worktrees\feat-standalone-mcp\SettingAgent\data\setting.sqlite')
```

### 3.6 MCP 등록 (local 스코프)
```bash
claude mcp add -s local setting13021 -- \
  npm --prefix "D:/…/worktrees/feat-standalone-mcp/SettingAgent" run --silent mcp
```
- **`npm --prefix` 를 쓰는 이유**: MCP stdio 프로세스는 Claude Code 의 cwd(=워크트리 루트)를 물려받는다. 그대로 두면 `config/tools.config.json` 을 못 찾아 **기본값(`toolsConfig.ts:408` → port 13020)** 으로 떨어진다. `npm run` 은 스크립트를 **패키지 디렉터리 cwd** 로 실행하므로 이것만으로 대상이 13021 로 고정된다.
- **`--silent` 필수**: npm 이 stdout 에 찍는 `> parkagent-setting@0.1.0 mcp` 배너가 **MCP JSON-RPC 스트림을 오염**시킨다.
- **local 스코프인 이유**: 프로젝트 스코프(`.mcp.json`)로 두면 절대경로가 박힌 설정이 브랜치에 커밋된다. local 은 `~/.claude.json` 의 이 워크트리 경로 키에만 저장된다.

## 4. 검증 결과 (차동 검증 — 이게 핵심)

"MCP 가 13021 을 물었다"는 것을 **성공 응답만으로는 증명할 수 없다**. 두 서버가 같은 스냅샷 DB라 응답이 동일하기 때문이다(둘 다 `slot.list` 24건, catalog 70건). 그래서 **13021 을 죽인 상태**에서 같은 호출을 반복했다.

| # | MCP 기동 명령 | 13021 상태 | `setting_rpc(slot.list)` | 해석 |
|---|---|---|---|---|
| A1 | `npm --prefix …SettingAgent run --silent mcp` | **살아있음** | ok=true, 24 슬롯 | — |
| A2 | 동일 | **죽임** | **ok=false (연결 실패)** | ✅ **A 는 13021 만 본다** |
| B | `tsx …/SettingAgent/src/mcp/server.ts` (cwd=워크트리 루트) | **죽임** | **ok=true, 24 슬롯** | ⚠️ **cwd 를 안 잡으면 기본값 13020 = 다른 세션 서버로 조용히 붙는다** |

- B 는 이번 작업에서 **반드시 피해야 할 함정**의 실증이다. 오류도 경고도 없이 옆 세션 서버를 조작하게 된다.
- 등록된 MCP 서버 상태: `claude mcp get setting13021` → **Status: ✔ Connected**.
- 최종 포트 공존 확인: `13020`(다른 세션) · `13021`(이 워크트리) · `13110`(Unity 시뮬레이터) 동시 LISTENING.
- MCP 노출 도구 7종 확인: `camera_req_img · camera_req_move · vpd_detect · unity_rpc · unity_rpc_catalog · setting_rpc_catalog · setting_rpc`.

## 8. 남은 선택지 (필요 시)

워크트리는 임시라 삭제되면 MCP 등록이 죽는다. **상시 두 번째 인스턴스**가 필요하면 두 가지 안이 있다:
1. 워크트리가 아닌 **고정 디렉터리**(예: `SettingAgent-13021/`)에 config 사본을 두고 거기서 기동 — 경로가 안 죽는다.
2. `loadToolsConfig` 에 환경변수 오버라이드(`PARKAGENT_TOOLS_CONFIG`)를 추가 — cwd 함정(§4의 B) 자체가 사라진다. **소스 변경이므로 별건으로 설계·유닛테스트가 필요**하며 이번에는 하지 않았다.
