## 1. 무엇을 만들었나 (한 문단)

`unity/centering`(실기 Hucoms 검증 운영코드)의 **화각·게인 두 표와 측정 절차를 TypeScript
독립 컴포넌트로 이식**하고, 참조본이 §7-5에서 "미모델링"으로 남긴 **곡면율(방사왜곡) 축을 세 번째
표로 추가**했다. 조준은 `undistort → ×게인 → clamp` 3단이 되며, **곡면율 표가 없으면 참조본 식과
비트 단위로 동일**하다. SettingAgent 실카 경로에 **기본 OFF**로 연동했다.

### 2.1 핵심 로직 — 조준 3단 (`CameraCalibration.aim`)

```
클릭(실제 이미지 픽셀) → undistort(곡면율) → ×k(게인) → clamp 0..W → setcenter
```

정확성: `send = undistort(r_d)·k = r_u·(f_fw/f_true)` 가 펌웨어의 `atan(send/f_fw)` 를 참 각도
`atan(r_u/f_true)` 와 일치시킨다. **`k1=k2=0` → undistort 항등 → 참조본 식으로 환원**(회귀 0의 근거).

### 2.2 곡면율 측정 — 회전 광류 격자 (`runDistortion`)

클릭 스윕의 착지는 화면 중앙 근처라 왜곡(가장자리 현상)을 못 본다. 대신 줌마다 4방향(±pan,±tilt)
순수 회전하고 프레임 5×3 격자를 ZNCC 추적 → 회전 1회당 대응점 15개, 코너까지 커버. 솔버는
참조본 `predictLanding` 을 왜곡 포함으로 확장한 **비용함수 하나**로 (f,k1,k2)를 Nelder-Mead 피팅.

### 2.3 과적합 방지 두 겹

- **자유도 승급**: 대응점 ≥24→(f,k1,k2) / ≥12→(f,k1) / <12→f만 / <6→줌 스킵.
- **채택 게이트**: 왜곡항이 잔차를 25%+ 줄이고 코너 변위 4px+ 여야 채택. 아니면 `k1=k2=0` +
  `adopted:false` 로 기록(**미측정과 "재봤더니 없음"을 구분**).

## 3. 경험적 검증 결과 (goal/loop)

목 카메라에 정답(f, k1=−0.085, k2)을 숨기고 되찾게 했다. 목 카메라는 모델을 **역방향**으로
쓰고(픽셀→펴서→광선→텍스처) 솔버는 정방향으로 쓰므로, 그 사이 ZNCC 매칭이 끼어 있어
"같은 식 두 번"이 아닌 진짜 end-to-end다.

| 렌더 해상도 | k1 복원 오차 | 코너 잔차(전→후) |
|---|---|---|
| 384×216 | −17.9% | 4.9 → 1.2px |
| 768×432 | −5.2% | 4.8 → 1.1px |
| **1920×1080**(실카 기준) | **+4.2%** | 5.5 → 0.7px |

- **정확도는 매칭 서브픽셀 정밀도(=해상도)에 좌우**되고, 실카가 쓰는 1920에서 **목표 ≤5% 달성**.
  저해상도 오차는 목 텍스처 에일리어싱이지 솔버·모델 결함이 아니다(합성 대응점 테스트는 ≤5% 통과).
- **부호 게이트 통과**: k1 < 0(배럴) — 설계서 §3의 1차 예측대로. 2026-07-21의 "거의 선형" 실측과
  정합(배럴이 tan을 선형 쪽으로 되돌린다).
- 조준 개선(클릭 1700,900 @z5129): **무보정 58.7px → 게인 1.26px → 게인+곡면율 개선**.
- A/B 자가판정: 맞는 표 `adopt`, 부호 뒤집은 표 `reject`("나빠졌습니다").

## 5. SettingAgent 연동 (기본 OFF)

### 5.1 변경 파일 (2개)

| 파일 | 변경 | 회귀 |
|---|---|---|
| `src/calibrate/lensCorrection.ts` (신규) | 정규화↔픽셀 어댑터 + 아티팩트 로더. 파일없음/비활성/빈표/깨짐 → **항등** | — |
| `src/viewer/RealPtzSource.ts` | 생성자 5번째 인자 `lensCorrector`(**기본 IDENTITY**) + `centerOnPoint` 에 보정 삽입(항등이면 건너뜀) | **0** |

`centerOnPoint` 삽입부는 `lensCorrector === IDENTITY_CORRECTOR` 면 네이티브 조회조차 하지 않고
좌표를 그대로 통과시킨다 → 기존 산출값과 **비트 동일**. 기존 테스트
(`realPtzSourceCenterOnPoint.test.ts` 7개)가 이 항등 경로를 그대로 통과함으로써 회귀 0을 고정한다.

### 5.2 활성화 절차 (실측 후 수동 — 의도된 gating)

현재 **어느 카메라에도 실제 보정이 걸리지 않는다**(검증된 표가 아직 없음 = 걸어도 무의미).
실측 세션 후:

1. `runDistortion()` + `verifyDistortion()` → `recommendation === 'adopt'` 확인.
2. `data/lens_calibration.json` 에 해당 `camIdx` 표 저장 + **`enabled: true`**.
3. `sourceRegistry` 의 실카 생성부에서 `loadLensCorrector(path, camIdx)` 를 5번째 인자로 주입.

> `sourceRegistry` 자동 배선을 **지금 넣지 않은 이유**(외과적 변경 원칙): 검증된 표가 없는 상태의
> 배선은 speculative 하고, 활성화는 설계상 "사람이 A/B pass 를 확인하고 켜는" 수동 단계다.
> 배선 1줄과 config 필드는 실측이 실제로 나온 시점에 추가하는 것이 옳다.

## 7. 알려진 한계 (설계서 §14 재확인)

1. **개체차** — 프리셋 자동 적용 금지, 검증(3분) 먼저. 오차가 프리셋 절반보다 작은 개체엔 역효과.
2. **주점 오프셋 미모델링** — 2026-07-21의 `tilt 상수 −0.0144` 는 이 설계로도 안 풀린다(회전과 축퇴).
3. **프레임 가장자리 클램프** — 보정 좌표가 0..1920 초과 시 부분 보정(`clamped:true` 보고).
   완전 해결은 `mode:'absolute'`.
4. **야간·저조도** — 고배율부터 측정 실패. 결함이 아니라 측정 가능 조건.
5. **OSD 배율 표기 불일치**(x36 vs 표 기준 ≈x26) — 표를 정본으로 삼되 기록.
6. **실측 미수행** — 파이프라인은 목 카메라로 검증됐으나, 실카(192.168.0.153) 표는 아직 없다.
   다음 단계는 실카 검증 패스(3분)로 참조 프리셋이 이 개체에 맞는지 확인하는 것.

## 8. 실카 실측 결과 (2026-07-25, 추가)

일회성 도구 `SettingAgent/realLensVerify.ts`(미커밋, HucomsClient→HucomsCameraPort 어댑터 +
sharp gray)로 실기를 쟀다. 실측은 **154(real-camera-2, admin/`mts6500!!!`)** 기준이다 —
153(real-camera-1)은 측정 중 **다른 곳에서 동시 제어되어 충돌**했고(그 결과는 오염이라 폐기),
마스터 지시로 154로 전환했다.

### 8.1 게인 검증 — PASS (배포 성과)

| zoom | 잔차(px) | 적용 게인 | 필요 게인 |
|---|---|---|---|
| 0 | 0.8 | 0.988 | 0.99 |
| 8000 | 2.4 | 1.11 | 1.104 |
| 16384 | 1.7 | 0.765 | 0.768 |

**판정 pass · 최악 2.4px · 17/18.** 내장 cam-001 프리셋(2026-07-14 실측)이 **두 물리 개체
(153·154) 모두에 ~1% 이내로 맞는다.** 게인 보정은 실기에서 켤 가치가 확인됐다.

### 8.2 곡면율 스윕 — A/B reject (안전장치 정상 작동, 그리고 방법의 한계 발견)

154 클린 측정에서도:

| zoom | 잔차 전→후(px) | k1 | 판정 |
|---|---|---|---|
| 0 | 33.2 → 32.3 | 0 | 기각(not_significant) |
| 3000 | 9.8 → 8.8 | 0 | 기각 |
| 5129 | 7.0 → 5.0 | **+0.17** | (부호게이트 전) 채택 → **아티팩트** |
| 8000 | 6.4 → 5.0 | 0 | 기각 |
| 12161 | 5.0 → 5.0 | 0 | 기각 |

**A/B: fail → recommendation reject.** 두 가지가 드러났다:

1. **z0(최광각) 잔차 33px 를 k1 이 못 줄인다** → 그 오차는 **방사왜곡이 아니다**. 원인은
   **PTZ 팬축·광학중심 오프셋에 의한 시차**로 판단된다(와이드 25% 회전 ≈ 15° 팬, 근거리 주차장
   물체). 회전-광류 방식은 이 성분을 렌즈 왜곡과 분리하지 못한다.
2. 채택됐던 z5129 `k1=+0.17` 은 **핀쿠션(양수)** — 광각 배럴 예측(§3)에 위배. 비방사 잔차에
   옵티마이저가 마진으로 끼워맞춘 아티팩트다.

**대응(구현·커밋)**: 설계 §3이 예고한 **배럴 부호 게이트**를 `CalibrationSolver.solveDistortionZoom`
에 추가했다 — 개선율·코너변위에 더해 **`k1 < 0` 일 때만 채택**. 핀쿠션 아티팩트를 구조적으로
차단한다. 유닛테스트 추가(패키지 100 green).

**핵심**: 곡면율 표는 이 PTZ 에서 **채택되지 않았고, 컴포넌트가 스스로 그렇게 판정했다.** 이것이
설계의 안전 목표(측정 실패를 성공으로 위장하지 않는다)가 실기에서 작동한 증거다. 실측 잔차
수준(정중앙~와이드 게인보정 후 2.4px)에서 방사왜곡은 이 방법의 노이즈 바닥 아래다.
