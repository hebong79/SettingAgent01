## 0. 한 줄 요약

`unity/centering` 의 **실기 검증된 두 표(화각·게인)와 측정 절차를 TS로 이식**하고, 그것이 아직
모델링하지 않은 **곡면율(방사왜곡) 축을 세 번째 표로 추가**한다.
독립 컴포넌트 `@parkagent/lens-calib` — 의존성 0 · 어댑터 1개 · 표 없으면 기존 동작과 동일.

## 1. 개정 사유 — R1은 무엇을 틀렸나

R1은 "참조본은 단위(픽셀·centidegree·zoompos)가 ParkAgent(정규화·도·배율)와 달라 전량 재설계"라고
판단했다. **이 판단이 틀렸다.** 코드 실사 결과:

| 확인 항목 | 참조본 | ParkAgent 실카 경로 | 판정 |
|---|---|---|---|
| 센터링 API | `ptz_centering.cgi action=setcenter type=point` | `client.centerPtz({type:'point', …})` [RealPtzSource.ts:373](../src/viewer/RealPtzSource.ts#L373) | **동일** |
| 좌표 기준 | 0~1920 / 0~1080 고정 | `CENTERING_BASE_WIDTH/HEIGHT = 1920/1080` [:31-32](../src/viewer/RealPtzSource.ts#L31) | **동일** |
| pan/tilt 네이티브 | centidegree | `panRange 0~35999`, `tiltRange −2000~9000` | **동일** |
| zoom 네이티브 | zoompos 레지스터, **16384 포화** | 실측 후 `zoomRange:[0,16384]` [:14-16](../src/viewer/RealPtzSource.ts#L14) | **동일** |
| 기종 | Hucoms (HNR-2036LA, cam-001) | Hucoms (192.168.0.153) | **동일 계열** |

즉 **참조본의 "네이티브 단위" = Hucoms 와이어 포맷 = RealPtzSource 가 이미 보내고 있는 것**이다.
단위가 다른 곳은 **뷰어 추상층(zoom 1~36 배율)** 하나뿐인데, 그 추상층은 `mapRange` **선형** 매핑이고
참조본의 실측 `ZOOM_HFOV_TABLE` 은 그 선형 가정이 **틀렸음**을 보인다(z15000→16384 에서 화각이 절반).

그러므로 올바른 방향은 재설계가 아니라 **이식(port) + 곡면율 축 추가**다.

### 1.1 부수 성과 — 체크포인트 미결 (B) 가 함께 풀린다

체크포인트 `2026-07-21` 미결 항목:

> **(B)** 실카 `개별 center+zoom` 미수렴. … OSD 는 12007=x7, 16384=x36 → 레지스터가 배율에 **비선형**.
> … 손대려면 **실카 줌 실측 캘리브레이션이 선행**돼야 한다.

`ZOOM_HFOV_TABLE` 이 정확히 그 실측이다. 배율은 화각으로부터 정의된다:

```
배율(z) = tan(hfov(0)/2) / tan(hfov(z)/2)
```

이 표를 역함수로 쓰면 뷰어 `zoom 1~36` ↔ `zoompos` 가 **선형 근사 없이** 왕복한다.
(참고: 표의 z16384 = 2.39° 는 배율 ≈ **26x** 로, OSD 표기 x36 과 다르다. OSD 표기가 디지털 포함이거나
사양 공칭일 가능성이 있다 — 이 불일치는 **표를 정본으로 삼고** 별도로 기록만 한다.)

### 1.2 2026-07-21 "tan 기각"의 정확한 적용 범위

| | 측정 대상 | 결론 |
|---|---|---|
| 2026-07-21 A/B (§3.2) | **UE 시뮬레이터 렌더** (`/capture/detect` + `ptz` 오버라이드) | 시뮬에서 tan 보정은 나빠짐 → **시뮬 경로에 적용 금지(유효)** |
| 2026-07-21 §5 실카 | Hucoms `setcenter` **1표본**, 잔차 x **−0.031** | "우리가 개입할 인자가 없다" |
| 참조본 105샘플 | Hucoms 실기 | 펌웨어는 **정확한 tan + 1/cos(tilt) 짐벌 커플링**. 틀린 건 초점거리 상수 |

두 결론은 **다른 카메라에 대한 것**이라 충돌하지 않는다. 그리고 §5의 "개입할 인자가 없다"는
**API 파라미터** 이야기였다 — 참조본이 제공하는 개입은 API 인자가 아니라 **보내는 좌표를 미리 미는 것**
(`applyCenteringGain`)이므로 그 제약을 우회한다.

**수치 정합(1표본이지만 부합)**: 참조본 z8000 게인 k≈1.11 을 무보정으로 두면, |dx|≈0.35(정규화) 클릭의
잔차는 `0.35·(1 − 1/1.11) ≈ 0.035`. 실측 −0.031 과 자릿수·부호가 맞는다.

> **따라서 유지되는 금지 규정**: 시뮬레이터 경로에는 보정을 걸지 않는다. 시뮬은 자기가 렌더하는 표와
> 같은 표로 조준하므로 이미 정확하다(k=1) — 보정을 걸면 **없던 오차가 생긴다.**

## 3. 곡면율이 왜 새 축인가

참조본 스스로가 §7-5에서 남긴 미모델링 항목이다:

> **방사왜곡(곡면율)은 여전히 미모델링.** 현재 잔차 수준에서는 tan 핀홀 + 초점 스칼라로 충분히
> 설명된다. **더 넓은 렌즈나 더 엄격한 요구가 생기면 그때 별도 항으로 들어가야 한다.**

두 표가 원리적으로 잡을 수 없는 성분이 있다:

| 항 | 편심 의존성 | 증상 |
|---|---|---|
| `centeringGain` k | **1승**(선형) | 가장자리로 갈수록 비례해서 덜 온다 |
| `lensDistortion` k1 | **3승부터** | 가장자리에서만, 그것도 급격히 |

k 는 편심에 비례하는 오차만 만든다. 배럴은 세제곱부터 시작한다. **한쪽으로 다른 쪽을 대신할 수 없다.**

모델을 세우면 기존 두 후보가 특수해로 포섭된다:

```
θ = atan( undistort(r) / f_true )
   k1 = k2 = 0  → 순수 tan 핀홀          (참조본의 현재 모델)
   k1 < 0       → tan 을 선형 쪽으로      (배럴 — 광각의 정상)
   k1 > 0       → tan 보다 더 휘어짐      (핀쿠션)
```

> **구현 전 예측(1차 게이트)**: 광각단(z0, hfov 57°)에서 **`k1 < 0`** 이 나와야 한다.
> 양수가 나오면 부호 규약이나 측정이 틀린 것이므로 **표를 채택하기 전에 멈춘다.**

### 4.2 단위 — 네이티브를 그대로 쓰고, 경계에서만 변환

**라이브러리 내부는 Hucoms 네이티브 단위**(픽셀 0~1920/0~1080, centidegree, zoompos).
이유: 그것이 **와이어 포맷**이고, 참조본의 검증된 수식·표가 그 단위로 되어 있으며, 재유도는

ParkAgent 규약과의 변환은 **어댑터 한 곳**(`SettingAgent/src/calibrate/lensCalibAdapter.ts`, 패키지 **밖**):

```
정규화 0~1        ↔  픽셀 0~1920/0~1080     (×1920 / ×1080 — RealPtzSource 가 이미 하는 것)
도(°)             ↔  centidegree            (×100)
뷰어 zoom 1~36    ↔  zoompos                (zoomMap.ts — ★선형 mapRange 아님)
```

## 5. 수학 — 참조본 계승 + 왜곡 1항 추가

### 5.1 왜곡 모델 (교과서 Brown 방사 성분)

참조본과 상호운용하기 위해 **정규화 반경은 교과서 규약** `r = r_px / f` 를 쓴다
(R1의 "코너 정규화"는 폐기 — 참조본 수식과 어긋나 이식 이득을 버린다).

```
f      = (1920/2) / tan(hfov(zoompos)/2)          ← 주변축(paraxial) 초점거리
r_u    = hypot(x−cx, y−cy) / f
r_d    = r_u · (1 + k1·r_u² + k2·r_u⁴)            distort   : 이상 → 실제 이미지
r_u    = newton(r_d)                              undistort : 실제 이미지 → 이상
점 변환은 반경만 바꾸고 방향 보존 :  p' = c + (p − c)·(r_out/r_in)
```

배럴 = `k1 < 0`. 뉴턴 도함수 `1+3k1r²+5k2r⁴ ≤ 0` 이면 모델이 접힌 것 → 반복 중단(발산 금지).

### 5.2 조준 3단 — 순서가 중요하다

```
클릭(실제 이미지 픽셀)
   → undistort      (곡면율 — 표 없으면 항등)        ★신규
   → × k            (게인 — 펌웨어 초점 배율오차)     참조본
   → clamp 0..1920  → setcenter
```

**왜 이 순서인가**: 펌웨어는 왜곡을 **모르고** 받은 좌표를 핀홀로 해석한다. 먼저 펴서 진짜 광선
각도를 얻고, 그 다음 펌웨어의 초점 배율오차를 상쇄해야 한다. 반대로 하면 두 보정이 서로를 오염시킨다.

정확성 증명(참조본 §의 확장):
```
목표: 펌웨어가 atan(send/f_fw) 만큼 돌아 참 각도 atan(r_u/f_true) 와 같아야 한다
 ⟹  send = r_u · (f_fw/f_true) = undistort(r_d) · k        ∎
```
`k1=k2=0` 이면 `undistort = 항등` → **참조본과 완전히 동일한 식**으로 환원된다(G5).

### 5.3 부호 규약 (참조본 실측 확정 — 그대로 계승)

```
panpos +  = 시계방향  → 수학 방위각 a = −pan
tiltpos + = 아래를 봄 → 고도각       e = −tilt
F = [cos e·cos a, cos e·sin a, sin e]    R = [sin a, −cos a, 0]    U = R × F
```
가로로만 클릭해도 틸트가 딸려 온다(팬 축이 월드 수직축) — 참조본이 실기와 **0 centidegree 일치** 확인.

## 6. 측정 — 두 패스를 **분리**한다

| 패스 | 재는 것 | 방식 | 근거 |
|---|---|---|---|
| **클릭 스윕**(참조본 계승) | `zoomHfov`, `centeringGain` | 편심 클릭 → 착지 잔차. 14줌 × 8클릭 | 실기 105샘플 검증됨. 손대지 않는다 |
| **광류 격자**(신규) | `lensDistortion` k1,k2 | 회전 1회 → 격자 15점 추적 | ↓ |

### 6.1 왜 곡면율만 다른 방식인가

클릭 스윕의 신호는 "클릭한 것이 중앙에서 몇 px 남았나"인데 **착지는 언제나 화면 중앙 근처**다.
그런데 왜곡은 **가장자리에서만 크다.** 클릭 스윕은 왜곡이 가장 잘 보이는 곳을 관측에서 빼고 있다.
(게인 측정에는 최적 — 그래서 그 패스는 그대로 둔다.)

```
회전 1회 = 대응점 15개(5×3 격자)      vs   클릭 1회 = 대응점 1개
줌당 회전 4회(±pan, ±tilt) = 60 대응점
```
회전량은 FOV의 약 25% — 격자점이 회전 후에도 프레임 안에 남아야 추적된다.
두 축을 모두 도는 이유: pan 만으로는 세로 왜곡 정보가 얇고, 짐벌 커플링이 왜곡으로 오귀속된다.

### 6.2 왜 LPD 를 안 쓰나 (기각)

1. **밀도** — 판 위치를 우리가 못 고른다. 코너 커버리지 보장 불가.
2. **결정적 편향** — 2026-07-21 §4가 LPD quad 중심의 **스케일 의존 편향(상수 −0.0144)** 을 실측했다.
   왜곡은 정확히 "반경에 따라 달라지는 편향"이므로 **구별되지 않고 그대로 표에 흡수된다.**

### 6.3 FrameMatcher — 참조본에서 **한 곳만** 일반화

참조본은 탐색창이 **프레임 중심 고정**(센터링 결과를 찾으므로). 격자 추적은 점마다 다른 곳을 봐야 하므로
탐색중심을 인자로 받게 한다. 신뢰도 3종(`peak≥0.6` / `margin≥0.02` / `contrast≥12`)은 **그대로**.
특히 `margin` 은 참조본이 "점수는 아무것도 말해주지 않았고 margin 이 전부를 말했다"를 실측한 항목이다.

## 7. 솔버

### 7.1 참조본 3경로는 그대로 (화각·게인)

`fitTrueFocal`(영상만) / `firmwareFocal`(텔레메트리만) / `undershootSlope`(모델 없음).
**이 삼중화가 참조본을 믿을 수 있게 만든 이유**이므로 손대지 않는다.

### 7.2 왜곡 피팅 (신규)

미지수 3개 `f, k1, k2`. 비용함수는 참조본 `predictLanding` 을 **왜곡 포함으로 확장**한 것 하나:

```
predict(p_before) = undistort → 광선(자세0) → 투영(자세1) → distort
cost = RMS( predict − p_after )        전 대응점
```
광류 격자 샘플이 클릭 샘플과 **같은 스키마**(before점·after점·전후 PTZ)라 코드가 그대로 재사용된다.

- 최적화: **Nelder-Mead**(외부 의존 0, 60줄). 참조본 황금분할은 1D 전용이라 3D로 승급.
- 초기값: 황금분할 `f`, `k1=k2=0`.
- **자유도 승급**(데이터가 허락하는 만큼만): 대응점 ≥24 → `f,k1,k2` / ≥12 → `f,k1` / ≥6 → `f` / <6 → 줌 스킵.

### 7.3 채택 게이트 — 유의미하지 않으면 0으로 기록

`f`만 피팅한 `rms₀` 대비 왜곡 포함 `rms₁` 이 **둘 다** 만족해야 채택:
```
개선율 (rms₀−rms₁)/rms₀ ≥ 0.25          그리고        코너 변위 ≥ 4px
```
불만족 → `k1=k2=0`, `adopted:false`, `reason:"not_significant"`.
**측정을 안 한 것과 재봤더니 없었던 것은 다른 사실이다.**

## 8. 검증 패스 · A/B 판정

참조본의 검증 패스(짧은 격자 + 보정 **켜고**)를 계승하고, **OFF/ON 동시 측정**을 추가한다.

| 판정 | 조건 |
|---|---|
| `pass` | 모든 줌 측정 성공 **AND** ON 잔차 ≤ 10px **AND** 모든 줌에서 ON ≤ OFF |
| `fail` | 측정됐으나 미달 → `recommendation:'reject'` — **표를 켜지 말 것** |
| `incomplete` | 한 줌이라도 측정 실패 → **`pass` 가 아니다** |

이 A/B 가 2026-07-21에 사람이 손으로 한 실험의 **자동화판**이다. 이번엔 컴포넌트가 매번 스스로
돌리고 **기각을 스스로 말한다.**

**측정 가능 조건**(권고가 아님): 밝을 때 · 차량/주차선처럼 무늬 있는 쪽 · 스윕 중 다른 이동 차단 ·
실패·취소해도 **원 PTZ 복귀**.

## 14. 알려진 한계

1. **개체차** — `k = f_펌웨어/f_렌즈` 의 분자는 펌웨어 상수(동일 모델 공통)지만 분모는 개체차를 탄다.
   그래서 프리셋 자동 적용 금지, **검증(3분) 먼저**. 오차가 프리셋의 절반보다 작은 개체에 걸면 오히려 키운다.
2. **주점 오프셋 미모델링** — `tilt 상수 −0.0144` 는 이 설계로도 안 풀린다. 남은 상수 잔차가 그 후보다.
3. **프레임 가장자리 클램프** — 보정 좌표가 0..1920 을 넘으면 부분 보정(`clamped:true` 보고).
   완전 해결은 `mode:'absolute'`(목표 PTZ 직접 계산 후 `goptzfpos`).
4. **야간·저조도** — 고배율부터 측정 실패. 결함이 아니라 측정 가능 조건.
5. **OSD 배율 표기 불일치**(x36 vs 표 기준 ≈x26) — 표를 정본으로 삼되 기록해 둔다.
