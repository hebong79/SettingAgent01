## 0. 결론 (맨 앞)

**마스터 관측은 코드상 정확하다.** `buildAtPhase`(`bayGrid.ts:219-247`)는 `a = phase + k·slotWidthM` 등간격으로 칸을 깔고 `slotDepthM` 단일값을 전 칸에 적용한다. 자유도는 `front line`·`phase`·`run 범위` 셋뿐이며 **개별 면은 자기 폭·깊이·각도를 갖지 못한다.** 「1개를 만들고 임의 개수를 한 번에 복제」가 맞다.

**그러나 착수 전에 코드가 이미 답한 것이 하나 있다 — 이것이 이 설계서의 중심축이다.**

> ### ★ 시뮬 골든의 「정답」 자체가 격자 복제다.
> `facesOfRow`(`sceneTruth.ts:55-84`)는 `offsetPos` 에서 **피치 2.5m 등간격**으로 `faceCount` 개를 복제하고, 전 면이 **동일한 `xSize/zSize`** 를 쓰며 `faceRot ≠ 0 || groupRot ≠ 0` 이면 아예 **null** 을 낸다. `_workspace/18_scene_spec.json` 실측: **5행 전부 `2.5 × 5.0`, `faceRot=0`, `groupRot=0`.**
> **→ 골든 41면에서 「면별 자유도」로 회수할 오차는 구조적으로 0이다.** 면마다 다른 치수를 주면 정답에 없는 자유도를 잡음에 맞추는 것이 된다.

그러면 마스터가 본 문제는 무엇인가. **복제 자체가 아니라 「행 하나가 통째로 채택되면 N칸이 자동으로 생긴다」는 채택 단위**다. 이 둘은 다르다:

| | 좌표 생성 | 채택 단위 | 증거 요구 |
|---|---|---|---|
| **현행(복제)** | 격자 등간격 | **행 1개** — 행이 이기면 N칸이 함께 산출 | 행 평균 점수 1개 |
| **A안(기각됨)** | 분리선 쌍 | 면 1개 | 면당 독립 관측 2개(경계마다 1개) |
| **★ 이번 안** | **격자가 후보를 제안** | **면 1개** — 칸마다 자기 증거로 채택/기각 | **면당 자기 증거 1벌** |

**권고: 「격자 prior + 면별 독립 채택 + 차량 존재 증거」 3중 구조.** 좌표의 규칙성(= 실측상 옳다)은 지키고, **채택의 독립성**(= 마스터가 요구한 근본)을 얻는다. 「근본이 흔들리면 안 된다」에 대한 설계자의 답은 이것이다 — **근본은 「면이 자기 증거로 홀로 선다」이지 「면마다 치수가 다르다」가 아니다.**

**그리고 이 안은 새로 발명한 것이 아니다.** 21회차 설계서 §5 가 **B안(격자 후보 + 면별 승격)** 으로 이미 표에 올려 두었고, Phase 0 구현자가 A안을 기각하며 **"B안으로 전환할 때 이 측정이 주는 것"**(`02aa` §4 말미)까지 적어 두었다. 측정이 지목한 경로다(§1).

**단, 성립 여부는 아직 측정되지 않은 한 숫자에 걸려 있다**: **면 단위 `side`(분리변 도색지지)가 위상을 가르는가.** Phase 0-b 가 이미 `near` 는 못 가른다고 확정했다(게이트② 90.8% 통과 = 판별력 ≈ 0). 그 값을 Phase 0 에서 재기 전에는 배선하지 않는다(§7).

## 1. A안과 무엇이 다른가 — 한 문단 (리더 요구 1)

**A안은 「분리선 쌍이 면의 위치를 **결정**한다」였고, 이번 안은 「격자가 위치를 **제안**하고 분리선은 그 제안을 **채점**한다」이다. 위치 정본이 반대로 뒤집혀 있다.** A안이 기각된 이유는 정확도가 아니라 **증거의 수**였다 — 면 N개를 얻으려면 독립 관측 N+1개(경계마다 분리선 1개)가 필요해 면당 성공률이 `p²` 로 떨어지고(뷰 A: p=0.769 → 4/10 실측, 격자는 같은 프레임 6/10), 행당 오검출 분리선 32개가 게이트를 다 통과한 뒤에도 행당 7.4~9.8개 위치를 남겨 **정밀도 상한이 0.35~0.46** 이었다(`02aa` §3-4·§3-5·§4). 이번 안은 격자가 **위상 1개만** 추정하므로 `p²` 손실이 없고(격자의 구조적 장점을 그대로 유지), 분리선은 「이 칸 경계에 실제 분리선이 있는가」라는 **가부 투표자**로만 쓰여 32개 오검출이 면을 **만들지 못한다**(오검출은 표를 얻지 못할 뿐 후보를 생성하지 않는다). **재시도 금지 대상은 「분리선 쌍으로 면을 닫는 것」이며 이번 안은 그것을 하지 않는다.** 반대로 A안 측정이 남긴 긍정 자산 — 분리선은 **맞힐 때 median 3.9cm 로 정확하다**(`02aa` §3-3) — 은 채점자 역할에 그대로 쓴다. 구현자 판정문이 그 결론을 먼저 적었다: *"분리선은 **위치의 정본이 아니라 위상의 채점자**로 쓰는 것이 측정에 맞는다"*(`02aa` §4 말미).

## 4. 면별 자유도 설계 (리더 요구 2)

**질문을 정확히 놓는다: 면이 자기 폭·깊이·각도를 어디까지 가져야 하는가.** 3단계로 정의하고, **상한 측정으로 고른다**(§7-ⓒ). 지금 값을 정하지 않는다.

| 단계 | 폭 | 깊이 | 각도 | 신규 파라미터 |
|---|---|---|---|---|
| **L0**(현행) | 행 공유 규격 2.5m | 행 공유 5.0m | 행 공유 | 0 |
| **★L1**(권고 기본) | 행 공유 규격 2.5m — 단 **행 단위 관측 피치**로 스케일 보정(기존 자가보정) | 행 공유 | 행 공유 | 0 |
| **L2**(측정 대상) | **면별** `w_i ∈ [2.5(1−τ), 2.5(1+τ)]` | 행 공유 5.0m | 행 공유 | `widthTolRatio` 1개 |
| **L3** | 면별 | 면별 | **면별** | — **금지**(2-7) |

**설계자 권고: 기본 L1, L2 는 상한 측정으로 검증하고 이득이 실측될 때만 채택.** 근거는 추측이 아니다:

1. **회수할 신호가 관측 잡음의 1/9다**(2-2). 실카 칸간격 편차 ≤4.5mm vs 분리선 관측 오차 median 39mm.
2. **골든에서는 회수할 신호가 정확히 0이다**(2-1). L2 의 골든 이득 상한 = 0이며, **골든에서 L2 가 이득으로 보이면 그것은 과적합의 증거**다.
3. 치수를 측정값으로 바꾸면 **지금 없는 잡음을 새로 넣는다** — 현행 산출 quad 치수는 이미 정확히 2.500/5.000 이고 잔여 오차는 전부 근변선 배치다(U12·U10). A안 설계서 §3-1 이 같은 이유로 「위치는 증거에서, 치수는 규격에서」를 택했고 그 판단은 기각되지 않았다(기각된 것은 위치 정본이었다).

**규격 이탈 기각 기준(L2 를 켤 경우)**: `|Δ − 2.5m| > (분리선 관측 오차 p90 = 0.118m)` 이면 **그것은 면의 진짜 폭이 아니라 잡음/오검출**로 보고 기각한다. 즉 `widthTolRatio ≈ 0.047` 이 관측이 허용하는 상한이며, **이보다 넓게 열면 오검출 쌍을 받아들이는 것**이다(A안의 ±10% = 0.25m 는 관측 잡음의 2배였다 — 그래서 정밀도 상한이 0.35였다). **값은 Phase 0 분포에서 도출한다. 지금 확정하지 않는다.**

관측 피치는 **이미 있는 것을 쓴다**: `calibrationFromGrid`(`bayGrid.ts:127`, export 완료)가 격자 배정 인덱스를 고정하고 `a_i ≈ phase + k_i·s` 에서 `s` 만 최소제곱으로 적합한다(`estimateCellPitch:108-124`). 자기충족 측정을 피하는 구조가 이미 들어 있다. **재발명 금지.**

| P4 | **스케일 보정 기준** — 채택 면들의 관측 피치로 지상고 자가보정 | `calibrationFromGrid` |

### 5-2. prior 가 **절대 하지 않는** 일 (금지 목록)

| # | 금지 | 왜 |
|---|---|---|
| **N1** | **면을 채택하지 않는다.** 격자에 속한다는 사실은 채택 근거가 **0**이다 | 이것이 「복제」와 「prior」를 가르는 유일한 선 |

## 6. 차량 증거 설계 (리더 요구 4 + 추가 지시)

### 6-1. ★ 오염 격리표 — 어느 필드가 검출에 들어가고 어느 필드가 채점에만 남는가

`car.list` 실측 필드(설계자 직접 호출 확인, §2-5):

| 필드 | 실카에 있는가 | **검출 경로** | **채점 전용** | 근거 |
|---|---|---|---|---|
| `presetId` | ✗ | **금지** | 허용 | **정답지**(어느 행인지) — 18회차 `expectedBays` 오염과 동형 |
| `faceSlot` | ✗ | **금지** | 허용 | **정답지**(몇 번 면인지). 이걸 쓰면 15라운드 수치를 무효화한 그 사고의 재발 |
| `pos{x,y,z}` | ✗ | **직접 금지 / 투영 후 강등본만** | 허용 | 월드 3D 좌표. 실카는 이미지 공간 박스뿐 — 마스터 못박음 *"리얼카메라도 시뮬레이터와 동일한 조건"* |
| `rotY` | △ | **강등본만**(투영된 박스의 방위로) | 허용 | 실카 대응물은 차량 박스 장축·번호판 방위 |
| `visible` | ✗ | **금지** | 허용 | **Unity 가 판정한 가림 여부**. 쓰면 가림 판정을 공짜로 얻는 것 = 재현율 천장(28/41) 측정 자체가 무의미해진다. **채점 전용이 맞다** |
| `prefabId` | ✗ | **금지**(치수 조회에만, 강등 투영 내부) | 허용 | 차종 = 치수. 실카는 차종을 모른다 |
| `carNameId` | ✗ | 금지 | 허용 | 식별자 |

### 6-2. 인터페이스를 **실카 기준으로 먼저** 정하고 시뮬을 강등해 맞춘다

```ts
/** 검출 경로가 받는 유일한 차량 증거 형태. 실카가 실제로 줄 수 있는 것만 담는다. */
export interface VehicleObservation {
  /** 이미지 공간 접지 사각형(픽셀). 실카=VPD/LPD 유래, 시뮬=투영 강등본. */
  footprintPx: PixelQuad;
  /** 이미지 공간 번호판 사각형(정규화). 있으면 점유영역 규약이 쓴다. 없으면 null. */
  plateQuad: NormalizedQuad | null;
  /** 어디서 왔는가 — 응답에서 절대 뭉개지 않는다. */
  source: 'sim-projected' | 'real-lpd' | 'real-vpd';
}
```

- **시뮬 강등 경로**: `pos + rotY + prefab 치수` → **현재 프리셋 카메라로 투영** → `footprintPx`. 월드→카메라 변환은 `sceneTruth.ts:124` 의 `projectWorld` 가 하는 일과 **동형**이므로 재발명하지 않는다.
  - ⚠ **단 `sceneTruth.ts` 는 채점 전용 봉인 모듈이다.** 검출 경로가 그것을 import 하면 봉인이 무너진다. → **강등 어댑터를 `src/tools/`(진단·측정 전용)에 두고 Phase 0 상한 측정에만 쓴다.** 검출 경로에는 위 인터페이스만 남기고, 시뮬 자동 배선은 **상한이 목표선을 넘은 뒤에** 별도 설계한다.
- **실카 경로**: **LPD 뿐이다**(2-4 — VPD 자동 경로는 제품 정책상 OFF). `plateQuad` → 기존 **`occupancyRegion`**(`src/domain/occupancyRegion.ts`, `REGION_DEFAULTS` = 폭배율 3.5~4.0 · `topWidthRatio` 1.0 · `upRatio` 0.9 · `downRatio` 0.6)로 점유 사다리꼴을 얻는다. **마스터 확립 정본이며 재발명 금지.**

### 6-3. 차량 → 주차면 좌표 유도 경로와 **오차원**

```
footprintPx 하단(접지선) → backprojectToGround → 지면 위 차량 중심·방위
   → 「그 자리에 면이 하나 있다」는 존재 투표 + 위상 투표
```

**★ 핵심 설계 판단: 차량은 「면의 존재」를 말하지만 「면의 경계」를 말하지 않는다.** 따라서 차량 증거를 **위치 정본으로 쓰지 않는다.** ②층의 **존재 투표자 + 위상 투표자**로만 쓴다. 이유는 오차원이 전부 경계 방향으로 몰려 있기 때문이다:

| # | 오차원 | 측정값/근거 |
|---|---|---|
| E1 | 차량 중심 ≠ 면 중심(전·후진 주차) | `car.list` 실측 — 같은 행에서 `rotY` 180 / 270 / 0 / 86.9 가 섞여 있다 |
| E2 | 차량이 비뚤게 섬 | 실측 `rotY` **268.25~271.13(±1.75°)** |
| E3 | 차량 폭 ≠ 면 폭 | 2.5m 면에 승용차 ~1.8m — **양옆 0.35m 여유**가 곧 경계 불확실성 |
| E4 | 차종별 치수 차 | 실측 `prefabId` **1·2·3·7 (4종)** |
| E5 | 접지선 판정(그림자·가림·박스 하단 ≠ 접지) | 미측정 — 실카에서 큰 항 |
| E6 | 면보다 큰 차량 | 트럭/밴이 두 면에 걸침 → 유도된 면이 **반칸 어긋난다** |
| E7 | 차량 위치의 지터 | 실측 x 산포 **91mm**(행2 5대) |

**사전 반증 (리더 요구 — 반드시 먼저 적는다)**
- **R-a 「반칸 어긋남」**: E3·E6·E7 이 합쳐지면 차량 중심이 면 경계 근처에 오고, 그 투표는 **정확히 격자 위상 문제를 재생산**한다. 차량 증거가 위상을 **틀리게** 밀면 도색만 쓸 때보다 나빠진다.
- **R-b 「가린 면에는 차가 있다 — 그런데 그 차도 가려질 수 있다」**: 재현율 천장을 만든 13면은 **차량이 도색을 가려서** 못 찾는 면이다. 그 차량 자신이 다른 차·기둥에 가리면 회수 불가.
- **R-c 「빈 면은 회수되지 않는다」**: 차량 증거는 **점유된 면만** 회수한다. 리더 육안 소견(실카 3장 모두 **우하단의 비어 있고 도색선이 선명한 구역을 못 잡았다**)은 차량 증거로 **풀리지 않는 별개 성분**이다.
- **R-d 「LPD 는 멀리서 안 보인다」**: 자동 바닥 ROI 는 프리셋 전경을 넓게 보는 뷰다. 번호판이 몇 px 인지 미측정 → **Phase 0 에서 먼저 잰다**(§7-ⓑ 전제 조건).
- **R-e 「VPD 금지와 정면 충돌」**: 실카에서 차량 박스를 자동으로 얻는 경로가 **제품 정책상 없다**(2-4). LPD 만으로 가면 R-d 가 지배한다 → **§10 마스터 확인 1순위.**

## 7. ★ 착수 전 상한 측정 (리더 요구 5 — 알고리즘 0줄)

**21회차 Phase 0 이 A안을 착수 전에 기각한 방식 그대로.** 상한이 현행(**재현율 0.5853658536585366 / 정밀도 0.8571428571428571**)에 못 미치면 **그 사실이 결론이고 배선하지 않는다.**

### ⓐ 격자 prior + 면별 게이트의 상한

> A안(격자 prior **없이** 면별 독립)의 상한은 **이미 측정됐다** — 재현율 0.39~0.56(의미 있는 tol ±0.05~0.10m) / 정밀도 0.35~0.46(`02aa` §3-4·§3-5). **재측정하지 않는다.** 이번에 재야 할 것은 다른 값이다.

**측정 A-1 (성립의 급소)**: 골든 5프리셋에서 **모든 위상의 모든 칸**을 후보로 놓고, 각 칸에 대해 `면 단위 side`·`면 단위 near`·`경계 분리선 정합(±tol)` 을 라벨(정답과 IoU≥0.5)과 함께 덤프한다.
→ **판정: `side`(면 단위)가 「정답 칸」과 「반칸 밀린 칸」을 가르는가.** `near` 는 못 가른다는 것이 이미 측정돼 있다(게이트② 통과율 **90.8%** — `02aa` §3-5). `side` 는 격자 칸의 좌우변이 **검출선이 아니므로 자기충족이 아니고**(A안 §2-1(c)의 함정을 회피), 20c 실측에서 **위상 판별 성분 +0.1576** 으로 유일하게 살아 있었다.
→ **면 단위로 내려오면 행 평균 희석이 사라진다** — 이것이 이번 안이 반증 #5(위상 항 가중 상향)와 다른 지점이다. **가중치를 올리는 것이 아니라 평균을 걷어내는 것이다.**

**측정 A-2**: 위 후보 전집합에서 **완전 분리 여부 / 최적 문턱의 오분류 수 / 시뮬 재현율·정밀도**. 판정 기준은 `_workspace/01g_...` §4 규약 그대로(원시 배정도 · 진짜 탈락 0 · 문턱은 분포에서 도출).

### ⓑ 차량 증거가 회수할 수 있는 가림 13면의 상한 — **두 값으로 가른다**(리더 지시)

| | 쓰는 것 | 의미 |
|---|---|---|
| **ⓑ-1 오라클 상한** | `faceSlot`·`presetId`·`visible` 포함 전량 | **도달 불가능한 천장.** 참고용 |
| **★ⓑ-2 전이 가능 상한** | 투영된 `footprintPx` + 방위만(§6-2 강등본) | **진짜 목표선** |

**둘이 크게 벌어지면 차량 증거는 「시뮬에서만 되는 것」이고, 그 사실이 결론이다.**
**전제 조건(먼저 잴 것)**: 골든 5프레임에서 **번호판이 몇 px 인가**(R-d). LPD 가 원리적으로 불가능한 크기면 ⓑ-2 는 실카에서 **정의되지 않는다** — 그 경우도 결론이다.

### ⓒ 면별 참 폭·깊이·각도의 실제 분산 — **코드가 이미 답했다**

| 대상 | 분산 | 근거 |
|---|---|---|
| **골든(시뮬)** | **정확히 0** | `sceneTruth.ts:55-84` 가 등간격·동일치수 복제 · `18_scene_spec.json` 5행 전부 2.5×5.0/rot 0 |
| **실카** | **직접 측정 불가**(정답 부재) — 간접 지표 **0.11~0.18%** | 리더 실측 관측 칸간격 2.4972/2.5045 |

→ **격자 복제로 잃는 면 수의 상한 = 골든 0면.** 남은 측정은 「실카 관측 피치의 **면별** 잔차」뿐이며, `estimateCellPitch`(`bayGrid.ts:108`)의 잔차 분포로 낸다. **잔차가 분리선 관측 오차(median 39mm)보다 작으면 L2 자유도는 잡음 적합이다**(§4).

### ⓓ (설계자 추가) 결함 A·B 승계 점검 측정

§8 의 주장(행 기준선이 사라진다)이 **실제로** 성립하는지를 후보 덤프에서 확인한다 — 면 단위 문턱이 **절대값**으로 성립하는가, 아니면 프레임마다 스케일이 달라 다시 기준선이 필요한가(19회차가 절대값을 포기한 이유가 여기서 재발할 수 있다).

### Phase 0 종료 조건

```
ⓐ A-1 에서 side 가 위상을 가르지 못하면        → 이번 안 기각. 그 사실이 결론.
ⓐ A-2 시뮬 정밀도 < 0.8571428571428571        → 기각(또는 목표선 재협상).
ⓑ-2 가 0면이거나 ⓑ-1 과 크게 벌어지면        → 차량 증거는 시뮬 전용. 그 사실이 결론.
ⓒ 실카 면별 잔차 < 39mm                       → L2 자유도 폐기, L1 확정.
전부 통과해야 Phase 1(코드) 착수.
```

## 8. 리더 실측이 드러낸 구조 결함 2건을 물려받는가 (리더 요구 6)

| 결함 | 현행 발현 | 이번 안 | 판정 |
|---|---|---|---|
| **A** `refScore` 가 후보 의존 → 문턱이 프레임·분모마다 이동(2:1 −27%) | `bayGrid.ts:687-699` | **행 기준선이 사라진다.** 채택이 면 단위이므로 「행 점수의 argmax」라는 개념이 없다 | **구조적으로 소멸 — 단 조건부**(아래) |
| **B** `paint.score` 가 칸당 평균 → 길이에 중립적이지 않다(짧아지면 오른다) | `bayGeometry.ts:697-699` `/k` | **면 단위에서는 `k=1`** 이므로 평균과 총량이 같다. 길이 편향이 존재할 수 없다 | **구조적으로 소멸** |

**★ 정직한 단서 — A 는 소멸이 아니라 「이동」일 수 있다.** 행 기준선은 사라지지만 그 자리에 **면 단위 문턱을 절대값으로 둘 것인가 상대값으로 둘 것인가**라는 같은 질문이 온다. 19회차가 절대값을 포기한 이유(프리셋별 `paint.score` 스케일 **0.919~1.559**, `bayGeometry.ts:255` 주석)가 면 단위에서도 유효하면 **결함 A 가 그대로 재발한다.** → **측정 ⓓ 로 먼저 확인한다.** 여기서 내 R1 명제가 면 단위로 번역된다:

> 「기준선은 길이 가중이어야 안정하고, 게이트는 길이 중립이어야 포용적이다」
> → 면 단위에서 **게이트는 자동으로 길이 중립**(k=1)이 된다. 남는 문제는 **기준선을 없앨 수 있는가**뿐이고, 그것이 ⓓ 다.

## R2-1. ★ 격자의 잔여 자리 — **없다. 폐기한다.**

리더가 *"격자를 아예 못 쓴다는 결론이 나오면 그렇게 적어라"* 고 했다. **그 결론이다.** 근거는 정책 순응이 아니라 **산술**이다.

### R2-1-1. 격자가 제공하던 유일한 구조적 이점이 사라졌다

A안이 기각된 진짜 이유는 정확도가 아니라 **관측 요구 수**였다(`02aa` §4-2):

| 방식 | 면 1개에 필요한 독립 관측 | 면당 성공률(경계 적중률 `p`) | 뷰 A 실측(p=0.76923) |
|---|---|---|---|
| A안(분리선 **쌍**) | **2개**(좌·우 경계 모두) | `p²` | 0.592 예측 → **4~5/10 실측** |
| 격자(위상 1개로 전 칸) | **1개**(행당) | `p¹` | 6/10 실측 |
| **★ 경계 1개 + 규격 폭 닫기** | **1개**(좌 **또는** 우 아무거나) | **`1 − (1−p)²`** | **0.9467** |

**규격 치수로 닫기가 허용된 순간, 면당 관측 요구가 2개 → 1개로 줄고 `p²` 손실이 사라진다.** 게다가 좌·우 **둘 중 하나만** 있으면 닫히므로 성공률은 `p¹` 이 아니라 `1−(1−p)²` 로 **격자보다도 높다**. 격자가 제공하던 이점(`p²` 회피)을 **격자 없이 더 잘 얻는다.**

### R2-1-2. 「채점용 prior」로 남기는 것도 하지 않는다

면을 독립 생성한 뒤 「다른 면과 2.5m 배수로 정렬되면 가점」을 주는 관계 prior는 **면을 만들지 않으므로 형식상 허용 범위**다. 그럼에도 **넣지 않는다**:

1. **채택을 다시 결합시킨다.** 등간격 정렬에 가점을 주면 「이웃이 붙어야 내가 산다」가 되어 **복제의 부드러운 형태**가 된다. 마스터 지시의 문언이 아니라 **취지**에 반한다.
2. **필요가 없다**(R2-1-1). 이점이 이미 다른 데서 나온다.
3. **21회차 실측이 이 방향을 이미 경고했다** — 「행 조각 의심」 진단은 자동 병합을 **하지 않는다**(`bayGrid.ts:620-641`): *"진짜 이웃 행 둘을 하나로 붙일 수 있고, 그건 거리 하드 게이트가 죽은 것과 같은 종류의 실패다."*

### R2-1-3. 코드 수준 금지목록 (재작성 — §5-2 를 대체)

## R2-2. 완전 개별 생성 알고리즘 — 2안 (+ 예비 1안)

### ★ 안 1 (권고) — **경계앵커 닫기**: 분리선 1개 + 규격 폭 → 면 1개

```
1) front(전방선) → rowFrameFromLine → 행 좌표계        ← 기존 재사용 (행 단위 근변선 유지 = G7)
2) 분리선 s_k 각각 → 폭좌표 a_k = widthCoordOf(...)      ← 기존 재사용
3) ★ 면 후보 = 분리선 1개당 **2개**:
      왼쪽으로 닫기 : [a_k − w, a_k]
      오른쪽으로 닫기: [a_k, a_k + w]
   (× v방향 2 — 전방선이 근변인지 원변인지 이미지로 알 수 없다)
4) quad = canonicalizeQuad([P(aLo,0), P(aLo,d), P(aLo+w,d), P(aLo+w,0)])   ← 기존 pointAt·projectToPixel
5) 게이트 — §R2-2-1
6) 배타성 해소 — quadIoU(신규 IoU 0줄 · R4)
```

**면 하나가 관측 하나에서 독립으로 태어난다.** 이웃 면을 참조하지 않고, 인덱스도 위상도 창도 없다(G1~G4 충족).

#### R2-2-1. ★ 판별의 급소 — 「예측변 도색지지」 (이 설계의 새 축)

한 면의 좌우 두 변 중 **한 변은 관측된 분리선**(자기충족)이고 **다른 한 변은 규격 폭으로 예측한 변**이다. **그 예측변만 채점하면 순수한 검증량이 된다.**

| 방식 | 좌변 | 우변 | `side` 의 정보량 |
|---|---|---|---|
| A안(쌍) | 관측 | 관측 | **0** — 스스로 고른 선 위에서 스스로를 채점(A안 §2-1(c) 함정) |
| 격자 | 예측 | 예측 | 있으나 **어느 쪽이 검증인지 구분 없음** |
| **★ 안 1** | **관측** | **예측** | **예측변 단독이 순수 검증량** — 이 구조에서만 정의된다 |

**왜 가르는가**: 참 경계에서 2.5m 떨어진 곳에는 **다음 참 경계가 있다**(도색 있음). 차체 모서리·그림자에서 2.5m 떨어진 곳에는 도색이 있을 이유가 없다.
**게이트①(쌍 간격 = 규격폭)과 다른 점**: 게이트①은 그 자리에 **검출된 분리선**을 요구했고(적중률이 밀도에 포화 — 우연 적중 median 0.8517), 예측변 게이트는 **5m 변 전 구간의 도색 지지**를 요구한다. `edgePaintSupport`(`floorPaint.ts:921-952`)는 변을 따라 `supportSamples` 개를 훑으므로 **점이 아니라 선 전체**를 본다 — 30~120px 짜리 스텁은 통과할 수 없다. **포화된 지표를 포화되지 않은 지표로 교체하는 것**이 이 게이트의 요점이다.

게이트 구성(**새 가중식을 만들지 않는다**):

| 층 | 내용 | 파라미터 |
|---|---|---|

| **경성 ②** | 근변 도색지지 `near ≥ extendMinNearSupport` | 기존 0.35 — ⚠ 위상맹이라 **판별 기대 없음**(§R2-2-2) |

#### R2-2-2. ★ 사전 반증 (측정 전에 적는다 — 이 안은 **정밀도에서 죽을 가능성이 크다**)

**규격닫기 허용은 재현율을 올리는 대신 A안의 유일한 기하 필터를 없앤다.** 게이트①(쌍 간격 2.5m)이 오검출 분리선을 죽이던 장치였는데, 단일 경계에는 그 필터가 없다. 정량 예측:

```
골든 분리선 총 384개(행당 32.0 — 02aa §3-2)
후보 = 384 × 2(닫는 방향) × 2(v방향) = 1536
  vs A안 게이트① 통과 304쌍(±5%) → 배타성 후 89위치 → 정밀도 0.4607

정밀도 0.70 달성 조건: 참 41면 → 총 산출 ≤ 58개
  → 1536 → 58 = **생존율 3.8% 이하**여야 한다.
```

**즉 예측변 게이트 + 물리 게이트가 후보를 26배로 걸러야 목표선에 닿는다.** 걸러내지 못하면 정밀도는 **~0.09** 수준이 된다(게이트②만 적용 시 45% 통과 → 691 → 배타성 후 수백).

| # | 반증 조건 | 어디서 깨지는가 |
|---|---|---|
| **F1** | 예측변 게이트가 26배를 못 거른다 | **전 프리셋.** 이것이 안 1의 생사다 |
| **F2** | 게이트②(`near`)는 도움이 안 된다 | 이미 측정됨 — 통과율 **90.8%**, 위상맹(`02aa` §3-5) |
| **F3** | 도색이 촘촘한 구역에서는 예측변도 우연히 도색에 걸린다 | 분리선 평균간격 **0.303m** 인 구역(1:1·2:2 우연 적중 0.887·0.911) |
| **F4** | 예측변이 **차량에 가려** 도색이 안 보이면 **참 면이 탈락** | 가림 13면 — **재현율 손실 = 즉시 실패** |
| **F5** | 감사 프레임의 u 축이 그 행의 폭축과 어긋난 행 | 실측 존재 — 2:1 r4(간격 5.05m=깊이축) · 2:2 r2(4.33m=사선) (`02aa` §3-6) |

### 예비 안 3 — **면 템플릿 슬라이딩** (안 1·2 가 모두 탈락할 때만)

## R2-3. 차량 증거 3경로 (VPD / LPD / 세그멘테이션)

**오염 격리표(§6-1)는 그대로 유지한다** — 마스터가 푼 것은 VPD **정책**이지 **오라클 금지**가 아니다. `presetId`·`faceSlot`·`visible`·`pos`·`prefabId` 는 **검출 경로 금지 / 채점 전용**.

```ts
export interface VehicleObservation {
  footprintPx: PixelQuad;                 // 이미지 공간 접지 사각형
  plateQuad: NormalizedQuad | null;       // 있으면 occupancyRegion 규약이 쓴다
  source: 'sim-projected' | 'real-vpd' | 'real-lpd' | 'real-seg';   // ★ 산출에 반드시 명시
}
```

| 경로 | 주는 것 | 정확도 축 | 사전 반증 |
|---|---|---|---|
| **VPD**(차량 박스) | 축정렬 박스 | 접지선 = 박스 하단 가정 | 박스는 **방위를 주지 않는다** → F6 악화. 그림자 포함 시 접지선 하향 편의 |
| **LPD**(번호판) | 판 quad + **방위** | 판 폭 기준 사다리꼴 — **기존 자산 `occupancyRegion`**(3.5~4.0배·위0.9/아래0.6) **재발명 금지** | 원거리에서 판이 안 보인다(F9). 전/후면 중 하나만 보임 |
| **세그멘테이션**(SAM 등) | **차체 실루엣** | **접지 다각형을 직접** 준다 — 3경로 중 접지선 오차(E5)가 가장 작다 | 신규 의존성·추론 비용. 실시간 경로에 넣을 수 있는지 미검토. **차량/노면 그림자 분리**가 미지수 |

**설계자 권고 순서**: 상한 측정에서는 **세그 > LPD > VPD** 순으로 유망하다(접지 정확도 순). 단 **도입 비용은 반대 순서**이므로, Phase 0 은 **시뮬 강등본**(`src/tools/` 측정 전용, `sceneTruth` 봉인 유지)으로 **경로 무관 상한**부터 재고, 어느 실카 경로가 그 상한에 닿는지는 **그 다음**이다.
