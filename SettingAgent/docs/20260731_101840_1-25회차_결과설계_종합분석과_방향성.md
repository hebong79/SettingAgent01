## 0. 한 장 요약 (마스터용)

1. **목표는 3번 재정의됐다**: 「IoU 0.98」(1회차) → 「씬 41면 분모의 재현율·정밀도」(18회차, expectedBays 오염 발견) → 「완전 개별 독립 생성의 성립 여부 자체」(22회차, 마스터 확정 지시).
2. **25회차 종료 시점의 최대 성과는 검출 성능이 아니라 병목의 특정이다** — ① 도색선 경로의 천장 0.6829는 차량 가림(13면)·근변 무도색이 만들고, ② 차량앵커는 관측이 정확하면 0.9512/0.9286 까지 가능함이 측정됐으며(단 오라클 강등 투영 기준), ③ 이미지 유래 관측으로 바꾸는 순간 **방위 오차 31.05°** 한 지점에서 전면 붕괴한다(24회차).
3. **"안 2(차량앵커) 성립"(22회차)은 액면대로 믿으면 안 된다.** 그것은 관측 완전성을 가정한 상한이고, 실제 이미지 검출로는 재현율 `0.04878...`(24회차 Q1 FAIL)이다. 성립한 것은 「경로의 상한」이지 「검출기」가 아니다.
4. 그럼에도 24회차가 남긴 원인 분해는 결정적이다 — **검출기(VPD seg)는 병목이 아니다**(미회수 39면 중 기하 결손 34면 = 비중 0.8718). 무너진 것은 `nearEdgeOf` 12줄짜리 접지선 요약뿐이다. **수리 지점이 한 곳으로 좁혀진 상태**다.
5. **추천: 26회차는 「접지 방위 추정 수리」 단일 표적**(안 2 노선 계속). 병행으로 현행 서비스의 야간 오검출(OSD 자막 가설)·전경 역전(`frontCandidates=8`)은 저비용 검증만. 반자동(사람 확정)은 회군 시의 안전망으로 명시해 둔다. 상세는 §6.

## 1. 목표의 변천사

### 1-1. 최초 목표 (1~13회차)

> "2개 카메라 전 프리셋(23면)에서 **주차면 개별 IoU ≥ 0.98**. 조건: 이미지에서 사각형 4점을 직접 검출(수동 ROI 는 채점에만 — hold-out). 실카에서도 성립" — `CHECKPOINT.md` 목표 절

수동 정본 23면을 재현하는 **정밀 정합 문제**로 시작했다. 1회차 평균 IoU 0.09116 에서 12회차 0.75668 까지 올렸다(`CHECKPOINT.md` 회차 목록).

### 1-2. 1차 재정의 — 측정 기반 자체가 무효였다 (14·18회차)

- **14회차**: 같은 PTZ·같은 코드인데 프레임에 따라 통과 면수가 ±6면 — **프레임 종속** 확정. "7~13회차 회차간 비교(0.72496→0.74229→0.75668)는 무효"(`CHECKPOINT.md` 14회차). → 골든 프레임 세트(`test/fixtures/roiAutoGolden/`) 확립, 프레임해시 없는 IoU 무효 규약(F13).
- **18회차**: **`expectedBays` 가 정답지(정본)에서 왔다**(`roiAuto.ts:364`) — "15라운드 수치는 전부 '개수를 알려준' 값"(`CHECKPOINT.md` 18회차). 동시에 Unity 씬 정답을 복원해 **실제 가시 면이 41면 vs 정본 23면(56%)** 임을 확인.
- 목표가 「정본 23면 IoU」에서 **「씬 41면 분모의 재현율·정밀도·매칭IoU」** 로 바뀐다. 19회차에 rows 정밀도 0.1832→0.8571(진짜 면 0개 손실)로 회복, 이것이 이후 전 회차의 기준선(recall `0.5853658536585366` / precision `0.8571428571428571` / meanIoU `0.8886003068644802`)이 된다.

### 1-3. 2차 재정의 — 실카 이행 (20~21회차)

- 20회차: 마스터 지시로 「현재 화면 그대로 검출」(카메라 무이동 V1, `f = f@zoom1 × zoom` 경로) — 실카 이행 경로로 표적 교체(`20260730_020139_...20회차` — [요지는 체크포인트·인계서 기준, 전문 미확인]).
- 21회차: `rowExtentMode:'evidence'` 로 개수 의존 제거 + **개별 독립 A안(분리선 쌍) Phase 0 기각**(정밀도 상한 0.35~0.46 · 재현율 상한 0.39~0.56, 행당 오검출 분리선 32개) + **도색 천장 확정: 재현율 상한 28/41 = 0.6829, 미검출 17면 중 13면이 차량 가림**(22회차 본문 §3·§4 재인용).

### 1-4. 3차 재정의 — 「완전 개별 독립」이 성공기준 그 자체가 되다 (22회차)

마스터가 결과 이미지를 보고 *"주차면 1개 생성하고 임의의 갯수를 한번에 만드는 것 같다"* 고 지적 → 코드 검증 결과 정확했다(`buildAtPhase` 의 `a = phase + k*w` 등간격 복제, `bayGrid.ts:219-247`; 22회차 §3). 마스터 확정 지시:

> "기존의 격자방식을 이용하여 한번에 여러개 주차면을 그리는 것은 현재 작업에 사용 금지 … 완전 개별로 생성하는 방식에서의 알고리즘을 찾는 방식으로 진행" — 22회차 §7-b

**성공기준이 「치수 회수량」이 아니라 「개별 독립 생성이 성립하는가」로 바뀐다**(22회차 §7-b). 규격 치수(2.5×5.0m)는 「면 하나 닫는 데만」 허용·복제 금지, VPD+LPD+세그 이번 작업 한정 허용, 목표선 정밀도 ≥ 0.70(재현율 우선), 빈 면 미검출 범위 포함.

재정의를 유발한 실측 사실(22회차 §2): `refScore` 기준선이 후보 의존이라 분모를 바꾸면 문턱이 통째로 이동(2:1 에서 −27%, 가짜 6개 일괄 통과)하고, `paint.score` 칸당 평균은 길이에 중립적이지 않다 — **종전 정밀도 0.8571 은 「개수를 알려준 덕」**이었다(22회차 §2-3).

### (e) 문서 주장 ↔ 실측 어긋남 (반드시 짚을 것)

1. **「안 2 성립한다」(22회차 §7-n)는 그대로 인계하면 위험하다.** 그 수치(0.9512/0.9286)는 `car.list` 월드 좌표를 투영한 **강등본** — 24회차 스스로 "시뮬 전용 치트"로 정량했다(치트 상회분 최소 `0.0731...`, §6). 이미지 유래 실검출의 현재 실측은 **`0.04878...`** 이다. "성립"의 올바른 독해는 「관측만 정확하면 도달 가능한 상한이 측정됨」까지다.
2. **23회차 「P1~P5 전부 PASS」 배지** — 문서 자신이 §2 에서 "수치적으로는 상한 재측정에 불과"라 정직하게 적었으나, 배지만 읽으면 성능 진전으로 오독된다. 검출 능력 향상은 0이었다.
3. **25회차 골든 rows 무회귀** — 문서화 담당이 `roiAutoRecall.ts` 재실행 없이 developer 수치를 인용(§7·§9 자기 고지). 구조적 보장(무력 기본값)이 있어 위험은 낮지만 「재실행 미검증」이 맞는 분류다.
4. **마스터 실측 스샷 7장은 영구 재현 불가**(frameHash 전역 검색 0건, 뷰어가 프레임을 디스크에 안 남김 — 25회차 §7). 마스터가 본 현상 중 EV4 거대 사각형·EV5 자막 겹침은 **육안 증거로만** 남았고 수치 판정에서 제외됐다. 이는 인프라 결손(§7 위험·부채)이다.
5. 22회차 인계서 §1-1 의 "병목 4개(실카 EV 실측)"는 본문 §7-m 의 "evPresetDetect 미착수"와 시점이 어긋난다 — 인계서가 더 늦은 시점 기록으로 보이나 원본 대조는 [미확인]. 실카 수치 인용 시 주의.

## 6. 앞으로의 방향성 (핵심)

### 6-1. 갈림길 3개

**선택지 A — 안 2 노선 계속: 「접지 방위 추정」 한 지점을 수리한다 (추천)**

- **전제**: 24회차 원인 분해가 옳다 — 검출기(seg 마스크)는 상한 0.8780 까지 건전하고, 콘투어는 접지를 정확히 따르며(스샷 확증), 무너진 것은 `nearEdgeOf` 12줄의 직선 요약뿐이다(24회차 §2·§3·§4).
- **내용**: L자 하단 윤곽을 두 선분(앞변/옆변)으로 분해(꺾임점 검출·RANSAC 2선분·최소면적 회전사각형 등)하고, LPD 판 방위(정면 시점에서 이미 작동 — 24회차 §10)와 융합한다. 실카 σ 감내선은 이미 측정돼 있다: 계통 편의 30px 까지 정밀도 0.854, 60px 에서 붕괴(22회차 §7-n 경계 3).
- **비용**: 낮음~중간(수리 지점이 `src/tools/imageObservation.ts` 국소 함수 2개로 특정돼 있음). 비교 기준선·계측 도구(`groundErrProbe`)·채점 파이프라인 전부 준비 완료.
- **성공확률**: 시뮬에서 중간~높음(추정 — 방위 min `0.2704...`° 사례가 존재해 정보 자체는 마스크에 있다). 실카 전이는 별도 관문.
- **중단조건**: §6-4 참조.

**선택지 B — 관측원 자체를 격상: 외부 세그/방위 모델(SAM 계열·회전 박스 차량검출) 도입**

- **전제**: 마스터가 이번 작업 한정 세그 허용(22회차 §7-b). 현 VPD seg 의 마스크 품질이 아니라 **방위를 직접 주는 모델**이 필요하다는 판단이 설 때.
- **비용**: 큼 — 신규 의존성·추론 비용·실시간 경로 편입 미검토(설계서 R2-3). A 를 건너뛰고 B 로 가면 "기하 12줄 수리로 충분했는지"를 영영 모른다.
- **성공확률**: 모델 성능에 종속(추정 불가). **A 실패 시의 2안**으로 두는 것이 측정 경제상 옳다.
- **중단조건**: 도입 후 2회차 내 방위 중앙값 10° 미달이면 학습기반도 이 뷰에서는 불가로 결론.

**선택지 C — 문제 정의 축소: 반자동(자동 후보 제안 + 사람 확정)**

- **전제**: 셋업은 1회성 작업이라 사람 개입 비용이 낮다. 수동 ROI 드로잉 페이지(ROIMaker, git log `34e244a`)와 주차면 목록·4정점 편집(`ef9d2b6`)이 **이미 존재**한다.
- **내용**: 자동검출은 「후보 + 신뢰도」만 내고, 확정(③ 번호 배정·정본 쓰기)은 사람이 한다. 현행 3단계 분리 설계(①찾고②리스트③선택, 순서도 문서 P3)와 정확히 합치 — 새 설계가 거의 필요 없다.
- **비용**: 최소. **성공확률**: 제품 관점에서 사실상 확실.
- **역할**: 독립 노선이 아니라 **회군 시 착지점 + 그전에도 제품 안전망**. 자동이 정밀도 0.70 을 못 넘는 동안에도 「후보 제안」으로는 유용하다.

(참고 — "현행 lattice 서비스 경로를 계속 튜닝"은 선택지로 세우지 않는다. 결함 A·B·진입컷이 구조적이고, 마스터가 격자 복제를 명시 금지했으며, 22회차 §7-c 산술이 격자의 잔여 이점이 없음을 보였다. 현행 경로는 **회귀 비교용 + D3/D4 저비용 수리**만 남긴다.)

### 6-2. ★ 추천안 — A (접지 방위 수리) 를 주노선으로, C 를 명시적 안전망으로

근거 3가지:

1. **병목이 한 지점으로 특정된 상태는 이 작업 25회차 역사상 처음이다.** 24회차 원인 분해(기하 결손 0.8718·검출 미탐은 상한과 정확히 일치)와 스샷 육안(콘투어 정상·현이 원인)이 독립적으로 같은 곳을 가리킨다. 이런 순간에 노선을 바꾸는 것이 가장 비싸다.
2. **목표 도달 여력이 측정으로 보장돼 있다.** 검출기 상한 0.8780 > 현행 기준선 0.5854, 안 2 상한 0.9512(+합집합 0.9756). 방위만 복구되면 「도색 천장 0.6829 돌파」라는 15회차 이상 못 넘던 벽을 넘는 최초의 실측이 나온다. 게다가 차량 증거는 시뮬·실카 양쪽에 존재하는 유일한 증거라(P6) 실카 전이 검증이 가능한 유일한 노선이다.
3. **실패해도 싸다.** 수리 대상이 계측 전용 `src/tools/` 국소 함수라 서비스 무접촉이고, 판정 도구·기준선·중단조건이 전부 준비돼 있어 1~2회차 안에 성패가 갈린다.

## 8. 결론

15회차 이상을 지배한 질문 「도색선으로 어디까지 가는가」는 **0.6829 라는 숫자로 닫혔고**, 22~24회차가 그 대체 경로(차량앵커)의 상한 0.9512 와 붕괴 지점(방위 31.05°) 을 모두 측정으로 확정했다. 25회차는 현행 서비스의 야간·전경 문제를 상류 진입 컷으로 특정했다. **지금은 노선을 바꿀 때가 아니라, 특정된 한 지점(접지 방위)을 1~2회차 안에 수리해 성패를 가를 때다.** 실패 조건(K1~K5)이 명확하므로, 실패하더라도 회군 착지점(반자동)은 이미 제품 안에 준비돼 있다.
