## 2. 신규 클래스·모듈

### 2.1 `LensCalibrationJob` (`src/calibrate/LensCalibrationJob.ts`)

`PlateDiscoveryJob` 패턴 미러 — 단일 인메모리 상태머신, 중복 시작 거부, 폴 기반 상태 제공.

**상태**: `idle → running → (done | aborted | error)`, 중지 시 `running → stopping → aborted`.

- **`stopping` 을 별도 상태로 둔 이유**: `abort()` 직후에도 엔진이 카메라를 원위치로 되돌리는 중이다. 여기서 곧바로 `idle` 이라고 말하면 사용자는 아직 슬루 중인 카메라에 다음 명령을 쏜다. `stopping` 동안 폴은 계속되고 정지 버튼도 비활성이다(중복 중지 요청 방지).
- **중지는 실패가 아니다**: `signal.aborted` 면 `error` 가 아니라 `aborted` 로 마감하고 `error` 필드를 비운다. UI 가 빨간 실패로 오인하지 않게.

**로그**: 링버퍼(기본 500줄) + `seq` 증분. `getStatus(sinceSeq)` 가 그 seq 초과분만 준다.
- SSE/WebSocket 을 쓰지 않은 이유: 이 저장소의 모든 잡 UI가 폴이고 `pollPlan` 라이프사이클이 검증돼 있다. 로그 한 줄 때문에 새 전송 채널을 도입하는 것은 과설계다.
- 버퍼가 넘치면 `logsTruncated:true` 를 켠다 — **조용한 유실 금지**.
- `usable:false` 샘플은 사유(`low_contrast`/`smooth` 등)와 함께 `warn` 으로 남긴다. 저조도·무늬부족은 코드 결함이 아니라 현장 조건이고, 그 구분이 로그에 없으면 운영자가 "고장났다"고 오해한다.

**동시성**: 자기 중복 시작 → `already running`. 정밀수집·센터라이징·번호판 탐색 중 하나라도 running/stopping/finalizing 이면 `busy` + 누가 쓰는지. 다른 잡의 클래스를 import 하지 않고 **상태 조회 클로저(`isBusy`)만 주입**받는다(의존 역전).

### 2.2 `hucomsCameraPort.ts`

`realLensVerify.ts`(실카 실측으로 검증된 CLI)의 포트 조립을 서버 모듈로 **이식**했다. 새로 설계하지 않고 동작이 확인된 코드를 옮겼다. 일시 fetch 실패 4회 재시도 포함(실카 슬루 중 간헐 실패는 실측된 정상 현상).

> **★ `RealPtzSource` 를 재사용하지 않은 이유**: `RealPtzSource` 는 뷰어 좌표계(정규화·도·배율)로 말하고 클릭에 **이미 렌즈 보정을 적용**한다. 캘리브레이션이 재려는 것은 바로 그 보정 **이전**의 장비 원오차다. 뷰어 소스를 통해 재면 "재려는 대상을 보정 너머로" 재게 된다(엔진 `runner.ts` §1 rawAim 규칙). 엔진은 Hucoms 네이티브 단위(px 0~1920 · centidegree · zoompos)를 요구하므로 `HucomsClient` 직결이 옳다.

### 2.3 `lensCalibFile.ts`

`data/lens_calibration.json` 의 writer(읽기 `loadLensCorrector` 의 대칭 쪽).

- **한 카메라 항목만 건드린다.** 다른 카메라 항목·`_comment`·미지 필드를 전부 보존한다(전량 재작성 금지 — 검출 데이터 wipe 사고와 같은 부류의 취약점).
- **새 표는 항상 `enabled:false`**. 기존이 `true` 였어도 강등한다. 사람이 리포트를 보고 `apply` 를 눌러야 조준에 걸린다(설계서 20260725 §10 opt-in 원칙).
- 실측 표가 들어오면 `model`(프리셋 상속)을 떨어뜨린다 — 두 출처가 공존하면 어느 쪽이 적용됐는지 사람이 알 수 없다.
- 축끼리 서로 지우지 않는다(곡면율 저장이 화각·게인 표를 보존).
- 수치는 프로젝트 규약대로 `stringify5`(소수점 최대 5자리).

## 3. REST 라우트 (`/calibrate/lens/*`)

| 메서드 | 경로 | 응답 |
|---|---|---|
| POST | `/calibrate/lens/start` | `{ok,started,mode,total,sourceId}` · 409(실행 중/타 잡 점유) · 400(미지 소스·sim·바디오류) |
| POST | `/calibrate/lens/stop` | `{ok,state:'stopping'}` · 400 `not running` |
| GET | `/calibrate/lens/status?sinceSeq=N` | 상태 + 증분 로그 + `lastSeq` (`no-store`) |
| GET | `/calibrate/lens/result?source=id` | 결과 전문 · 404 |
| POST | `/calibrate/lens/apply` | `{ok,enabled,restartRequired:true}` · 400(표 없음) |

- **409 vs 400 구분**: 재시도로 풀리는 일시 충돌(실행 중·점유)만 409. 설정 오류(시뮬 소스·미지 소스)는 400.
- `apply` 는 `restartRequired:true` 를 항상 실어 보낸다 — `sourceRegistry` 가 프로세스 시작 시 표를 1회 로드하므로 **재시작 전까지 조준은 바뀌지 않는다**. UI 가 그 사실을 반드시 말하게 하는 장치다.
- 서버 등록은 주입 시에만(`if (deps.lensCalib && deps.lensCalibPaths)`) — 헤드리스 보존.
- 뷰어 alias(`/viewer/api/...`)는 만들지 않았다. 정밀수집 UI 는 `/calibrate/*`·`/discover/*` 를 절대경로로 호출하는 기존 규약을 따른다.

## 4. UI

정밀수집 탭의 **`LPD 검지` 카드와 `주차면 자동보정` 카드 사이**에 `#lens-box` 카드를 추가했다. 기존 카드 클래스(`precise-stage precise-operation-card`)를 재사용해 CSS 추가는 `.op-log`(로그 박스)·`.op-target`(대상 배지) 두 블록뿐이다.

| 요소 | id | 역할 |
|---|---|---|
| 종류 선택 | `lens-mode` | 초기 캘리브레이션(기본) / 검증 / 곡면율 |
| 시작·정지·적용 | `lens-start`·`lens-stop`·`lens-apply` | 적용 버튼은 **표가 실제로 저장됐을 때만** 노출 |
| 진행바·라벨·경과 | `lens-bar`·`lens-label`·`lens-elapsed` | |
| 진행 메시지 | `lens-msg` | 현재 단계·시작 실패·완료 안내 |
| 진행 LOG | `lens-log` | 서버 증분 로그 append(자체 스크롤, warn/error 색) |
| 완료 요약 | `lens-summary` | 모드별 판정·줌별 수치·미측정 사유 |
| 대상 배지 | `lens-target` | **지금 무엇을 점유하려는가**를 클릭 전에 보여준다 |

**안전 장치**
- 시뮬레이터 소스 선택 중이면 클라에서 먼저 시작을 막는다(서버 400 을 기다리지 않는다).
- `full`·`distortion` 은 확인창 1회 — 어느 장비를 얼마나(추정치임을 명시) 잡는지 문장에 넣는다. `verify` 는 짧으므로(≈3분) 확인 없이 시작.
- 로그 박스는 사용자가 위로 올려 읽는 중이면 자동 스크롤하지 않는다.
- 폴 타이머는 `lensPollTimer` 단일 변수가 소유한다(2026-07-24 "타이머 소유 단일 지점" 규칙).
- 결선 시점에 `lensPoll()` 1회 — 새로고침해도 진행 중인 잡의 진행바·로그를 이어받는다.

**순수 헬퍼 `lensCalibView(status)`**(`core.js`): percent·label·버튼 disable·applyVisible·폴 여부·tone. 브라우저 DOM 자동화가 이 저장소에 없으므로 UI 판단 로직은 전부 순수함수로 뽑아 vitest 로 덮었다.

### 6.1 알아야 할 트레이드오프 (은닉 금지)

1. **표 적용에 서버 재시작이 필요하다.** 핫리로드는 `sourceRegistry` 재조립 + ffmpeg 스트림 어댑터까지 얽혀 요청 범위 밖. 대신 응답·UI 양쪽이 재시작 필요를 명시한다.
2. **`full` 모드는 카메라를 25~40분 점유**한다(14줌×8타깃=112샘플). 그동안 정밀수집·센터라이징은 409로 막힌다.
3. **`full` 실행이 해당 카메라를 `enabled:false` 로 강등**한다. 지금 154는 `enabled:true`(게인 보정 ON)이므로, full 을 돌리면 **그 순간부터 apply 전까지 보정이 꺼진 상태**가 된다. 확인창·완료 요약 양쪽에 명시했지만 운영 시 유의.
4. **곡면율 reject 는 정상 결과다.** 2026-07-25 실측에서 이 PTZ 는 시차 교란으로 스퓨리어스 핀쿠션이 나왔고 A/B 가 막았다. UI 는 reject 를 실패가 아니라 "안전장치 동작"으로 표시한다.
5. **보정표 파일 개행**: writer 가 LF 로 쓰므로 CRLF 저장소에서 apply 후 `git status` 에 개행만 다른 변경으로 뜰 수 있다(내용 동일). 커밋 시 정규화된다.

### 6.2 미검증·한계

- **브라우저에서 사람이 직접 클릭한 확인은 하지 않았다**(이 저장소에 DOM 자동화 없음). UI 는 정적 봉인 테스트 + 서빙 확인 + 서버 API 라이브 확인으로 대체했다. 실제 화면 클릭 확인은 마스터가 `/viewer/` 에서 1회 해보는 것이 좋다.
- ⚠️ **뷰어 정적파일은 `no-store` 지만, 이미 열려 있던 탭은 하드리로드(Ctrl+Shift+R) 전까지 옛 JS 로 돈다**(2026-07-24 기록). 새 카드가 안 보이면 이것부터 확인할 것.
- `full`·`distortion` 모드는 **라이브 완주를 하지 않았다**(각각 25~40분·10~15분 카메라 점유). 두 모드의 코드 경로는 유닛(목 러너)으로만 덮여 있고, 실카 완주는 `verify` 로만 확인했다. 세 모드는 같은 잡·같은 진행/로그/중지 경로를 공유하지만, **full 의 표 생성·저장까지가 실카에서 끝까지 도는 것은 아직 미확인**이다.
- `data/lens_calib_result_real-camera-2.json` 은 이번 라이브 측정으로 생긴 산출물이다(커밋하지 않음).

## 7. 사용법

1. 뷰어 `/viewer/` → 정밀수집 탭 → 상단에서 **실카 소스 선택**(배지에 대상 표시).
2. **렌즈 캘리브레이션** 카드에서 종류 선택
   - `검증` — 현재 표가 이 개체에 맞나(≈3분). 파일을 만들지 않는다. **처음이라면 여기부터.**
   - `초기 캘리브레이션(표 생성)` — 화각·게인 실측(≈25~40분).
   - `곡면율 측정` — 방사왜곡(≈10~15분). A/B 통과 시에만 채택.
3. **시작** → 진행바·LOG 실시간 관찰. 중단하려면 **정지**(카메라는 원위치로 복귀한다).
4. 완료 후 요약을 읽고, 표를 만들었다면 **[이 표 적용]** → **서버 재시작**(`npm run dev` — 이 환경엔 nodemon 미설치라 `npm start` 는 실패).
