# 승인 프롬프트 자동승인 체계 적용 (2026-07-28)

## 1. 목적

"코드 방향 선택을 제외한 일반적인 사용 승인"을 자동화한다. 즉 툴 권한 프롬프트(Bash 실행·파일 편집·MCP 호출)는 무음 통과시키되, 되돌리기 어렵거나 외부로 나가는 작업만 확인을 남긴다.

### 두 경로의 구분 (핵심 전제)

| 종류 | 발생 주체 | 이번 변경 대상 |
|---|---|---|
| 툴 권한 프롬프트 | 하네스(권한 시스템) | ✅ 자동승인 |
| 코드 방향 선택 (AskUserQuestion), 계획 승인(ExitPlanMode) | 모델(에이전트) 판단 | ❌ 권한 시스템 밖 — 그대로 유지 |

권한 설정을 아무리 열어도 "A안/B안 중 어느 쪽으로 갈까요"는 그대로 뜨고, 반대로 "이 curl 실행해도 되나요"는 사라진다.

## 2. 설계 판단 — 왜 allow 목록만으로는 안 되는가

적용 전 상태를 실측한 결과:

| 파일 | allow 항목 수 |
|---|---|
| `~/.claude/settings.json` (전역) | **794** |
| `.claude/settings.json` (프로젝트, git 추적) | 84 |
| `.claude/settings.local.json` (프로젝트 로컬) | 456 |

전부 "그때그때 승인한 명령의 전체 문자열 스냅샷"이었다. 문제는 이 중 상당수가

```
PowerShell($c = Get-NetTCPConnection -LocalPort 13020 ...; if ($c) { ... } else { ... })
Bash(node -e "const d=require('./x.json'); console.log(...)")
```

같은 **인라인 복합 스크립트**라는 점이다. allow 패턴은 접두어 매칭이므로 이런 명령은 인자가 한 글자만 달라도 새 프롬프트를 만든다. 1,334개가 쌓인 원인이 이것이며, 와일드카드로 접어도 같은 이유로 계속 쌓인다.

→ **명령 형태와 무관하게 판정하는 PreToolUse 훅**을 1차 방어선으로, 와일드카드 allow를 2차(훅 장애 시 폴백)로 두는 2단 구조를 채택했다.

`defaultMode: "bypassPermissions"`(전부 무조건 통과)는 채택하지 않았다. 이 프로젝트가 `git push`·`rm -rf _workspace_prev*`·외부 REST 업로드를 실제로 수행하므로 사고 시 되돌릴 수단이 사라진다.

## 3. 변경 내역

### 3-1. 신규: `C:\Users\hdw-goback\.claude\hooks\auto-approve.mjs`

PreToolUse 훅. stdin으로 `{tool_name, tool_input, cwd}`를 받아 `permissionDecision`을 stdout으로 돌려준다.

| 도구 | 판정 |
|---|---|
| `Bash`/`PowerShell` | 위험 패턴 미매치 → `allow`, 매치 → `ask` |
| `Edit`/`Write`/`MultiEdit`/`NotebookEdit` | 작업 영역 내부 → `allow`, 밖·자격증명 파일 → `ask` |
| `Read`/`Glob`/`Grep` | 자격증명 파일만 `ask`, 나머지 `allow` |
| `mcp__*`, `WebFetch`, `WebSearch`, `Skill`, `Agent` | `allow` |
| 그 외 | 판단 없음(기본 흐름) |

**`ask`로 남긴 위험 패턴**

- 재귀 삭제: `rm -r*`, `Remove-Item -Recurse`, `del /s`
- 작업 손실 git: `push --force`, `reset --hard`, `clean -fdx`, `checkout -- `, `restore`, `branch -D`
- 외부 공개: `npm publish`, `gh pr/release create|merge`
- 시스템: `shutdown`/`Stop-Computer`/`diskpart`, 레지스트리(`HKLM:`), `C:\Windows`·`C:\Program Files`
- 자격증명: `.env`, `id_rsa`, `*.pem`, `credentials.json`, `.npmrc`, `.aws/`
- **외부 호스트 업로드**: `curl -d/-F/--upload-file`, `Invoke-WebRequest -Body/-InFile` 중 대상이 localhost·사내망(192.168./10./172.16-31.)이 **아닌** 경우만

마지막 항목이 이 훅의 핵심이다. 로컬 REST(13020/13100/13110)와 사내 VPD/LPD(192.168.0.125)로의 POST는 이 프로젝트의 일상 작업이므로 통과시키고, 외부 도메인으로 데이터가 나가는 경우만 붙잡는다.

**장애 시 동작**: JSON 파싱 실패·예외 발생 시 아무것도 출력하지 않고 exit 0 → 기본 권한 흐름으로 복귀(=평소처럼 물어봄). 훅이 깨져도 작업이 막히거나 무단 통과되지 않는다.

**구현 주의점**: Windows에서 `process.exit()`를 stdout 쓰기 직후 호출하면 파이프 flush 전에 잘려 훅 출력이 유실된다. 명시적 exit 없이 자연 종료하도록 작성했다(초기 구현에서 실제로 재현되어 수정).

## 5. 영향도 분석

### 5-1. 현재 진행 중인 다른 세션 — **작업이 끊길 위험 없음**

| 변경 | 다른 세션 영향 |
|---|---|
| `allow` 확대·`hooks` 추가 | 통과 범위가 **넓어지기만** 함 → 진행 중 작업을 막지 않음 |
| `ask` 추가 (`deny` 아님) | `ask`는 프롬프트를 띄울 뿐 **차단하지 않음**. `deny`를 의도적으로 쓰지 않은 이유 |
| `allow` 목록 794→94 축소 | 축소분은 전부 일회용 스냅샷. 재등장 시 훅이 `allow` 판정하므로 실질 영향 없음 |
| `defaultMode` 변경 | 세션 시작 시 결정 → 진행 중 세션은 현재 모드 유지 |

`deny`를 한 줄도 쓰지 않은 것이 이 보장의 근거다. `deny`였다면 다른 세션이 `.env`를 읽던 중 하드 차단될 수 있었다.

**반영 시점**: 훅과 `defaultMode`는 세션 시작 시 로드된다. 진행 중인 세션(워크트리 3개 포함)은 **재시작 후**부터 자동승인이 적용된다.

### 5-2. 워크트리 세션

`.claude/settings.json`은 **git 추적 파일**이라 각 워크트리가 자기 커밋의 사본을 읽는다. 즉 프로젝트 파일 변경은 **커밋·머지 전까지 워크트리에 전파되지 않는다**.

반면 **전역 `~/.claude/settings.json`은 모든 워크트리·모든 프로젝트가 공유**한다. 훅과 `defaultMode`를 전역에 둔 이유가 이것 — 워크트리 3개(`feat-lens-calib-web-ui`, `feat-rpc-control-plane`, `preset-summary-20260724`)에도 재시작만으로 적용된다.

`.claude/settings.local.json`은 git 미추적이라 워크트리에 존재하지 않는다(영향 없음).

### 5-3. 코드·테스트 영향

없음. SettingAgent/ActionAgent/DMAgent 소스, 빌드, vitest 스위트와 무관한 하네스 설정 변경이다. `.claude/agents/*`, `.claude/skills/*`도 건드리지 않았다.
