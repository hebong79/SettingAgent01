## 4. ★ P1 반증 — `farWeight` 는 답이 아니다

`farWeight` 스윕(0.3 기본 → 0.6 → 1.0), `1:2`·`2:2` 후보별 실측:

| | 정답 행 `far` | 오답 승자 `far` | 판정 |
|---|---|---|---|
| **1:2** | rank3 = **0.119** | rank0 = 0.071 | 정답이 근소 우위 — 그러나 near 격차(0.714 vs 0.988)를 못 뒤집는다 |
| **2:2** | rank1 = **0.127** | rank2 = **0.262** | **오답이 더 높다 — 방향이 반대** |

`farWeight` 를 0.3 → 1.0 으로 올려도 1:2 격차는 0.435 → 0.402 로 겨우 줄고, **역전에 필요한 값은 ≈8.4** 로 비현실적이다. 2:2 는 올릴수록 나빠진다.

**원인은 설계자 F2 가 이미 말한 것이다 — 원변은 차량에 가려 도색 증거가 원리적으로 약하다(검출 2~6/9).** 정답 행의 `far` 가 0.119·0.127 로 낮은 것은 검출 실패가 아니라 **그 자리에 도색이 안 보이는 것**이다. "진짜 베이 행은 양쪽 경계가 다 실재해야 한다"는 내 3회차 가설은 **이 장면에서 성립하지 않는다.** 기본값 0.3 유지.

## 5. ★ 진짜 원인 규명 — 프레임 안에 **주차열이 여럿** 있다

`roiAutoRowWhy.ts` 에 quad 중심 출력을 추가해 승자와 정답이 **어디에 있는지** 봤다:

| | 자동 승자 quad 중심 | 수동(정답) 중심 |
|---|---|---|
| **1:2** | (1294,**10**) (1468,**39**) (1666,**71**) (1890,**108**) | (440,680) (844,553) (1178,452) (1451,369) |
| **1:2 rank3(정답)** | (1453,370) (1183,453) (855,554) (444,680) | ← 거의 완전 일치 |
| **2:2** | (768,**141**) (981,170) (1217,203) (1481,239) | (1482,707) (1064,595) (721,504) (435,428) |
| **2:2 rank1(정답)** | (438,429) (722,505) (1061,595) | ← 일치 |

**승자는 화면 최상단(y=7~239), 정답은 중앙(y=369~707)에 있다.**

역산하면 `1:2` 승자는 카메라에서 **약 31m** 지점의 지면이다(y=10, tilt 20.1°, f=2736 → z≈30.9m). 즉 **쓰레기가 아니라 진짜 주차열**이다 — 다만 이 프리셋이 겨냥한 열이 아니다.

> **결론: 도색지지가 못 가른 이유는 점수가 나빠서가 아니라, 후보 둘 다 진짜 주차열이기 때문이다.** 이미지 증거만으로는 "여러 실재 열 중 어느 것이 이 프리셋의 대상인가"를 원리적으로 답할 수 없다.

### 그래서 넣은 신호 — 조준 중심성(`aimCenterWeight`)

프리셋의 PTZ 는 운영자가 **대상 열을 향해** 맞춘 것이다. 따라서 대상 열은 화면 중앙 근처에 온다. 이것은 **카메라 조준 사실**이지 주차면 정답지가 아니다(fov·tilt·설치고와 같은 부류 — R1 위반 아님).

`aimTerm = 1 − (quad 중심들의 화면중심 거리 평균 / 반대각)`, 선택 점수에 가산.

## 9. 6회차 권고

1. **★ `2:2` — 커버리지 벌점이 정답을 죽인다.** rank1 은 quad 3개(0.75 배)라 1.049 짜리 오답에 진다. 벌점 없으면 1.705 로 **이긴다**(계산 확인). 4번째 베이는 `extendMinNearSupport`(0.35) 미달로 탈락한다 — **그 칸만 도색이 약한 것**이다. `extendMinNearSupport` 를 낮추거나, 커버리지 분모를 "지지 기준을 넘긴 칸 수"가 아니라 "격자가 만든 칸 수"로 바꾸면 즉시 갈린다. **가장 값싼 다음 수.**
2. **U2 — `1:2` 보정 이상치.** `maxHeightCorrection` 을 15% → 5% 로 조여 `1:2` 가 5.218m 대신 공칭을 쓰게 하고 IoU 를 재라. 다른 프리셋(0.8~1.0% 보정)은 영향 없다.
3. **U4 — 과적합 점검.** `aimCenterWeight` 는 5장에서만 봤다. 프리셋을 더 확보하거나, 중심성 대신 **"PTZ pan/tilt 로 계산한 광축이 지면과 만나는 점"** 과의 거리로 바꾸면 물리적으로 더 단단하다(현재는 이미지 중심 근사).
4. **마스터 보고 문장:** "제원 주입 경로로 `1:1` 0.955 · `2:1` 0.931 · `1:2` 0.739 까지 왔습니다. 남은 건 `2:2` 1건이고 정답 행은 이미 후보 안에 있으며, 원인(커버리지 벌점)까지 특정했습니다."
