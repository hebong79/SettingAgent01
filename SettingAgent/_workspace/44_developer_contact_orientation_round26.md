## 4. ★ 90° 뒤집힘 8/36 은 해소됐는가 — **거의 해소됐다(8/36 → 1/36)**

`groundAxisOf`(`carAnchorUpper.ts:256-262`)는 quad 의 두 축 중 **긴 쪽**을 head 로 잡는다. `footprintFromContact` 가 앞변에서 4.7m 를 밀어 quad 를 만들므로, **앞변 지면 길이가 4.7m 를 넘으면 장축이 가로변으로 뒤집힌다.**

| | 앞변 지면 길이 4.7m 초과 |
|---|---|
| 수리 전 chord | **8/36 = `0.2222222222222222`** |
| **수리 후 kink** | **1/36 = `0.027777777777777776`** |

잔존 1건 = **`2:2 seg#6`**, 앞변 지면 길이 `5.699768096703846` m (꺾임각 `86.33893100476958`°, 개선배수 `2.253211282686337`).

**§4-3 조건부 예외(스팬 클램프)는 적용하지 않았다.** 사전 측정 결과 클램프는 **일치율은 올리지만 오차 중앙값은 악화**시켰다:

|---|---|---|---|

| 클램프 적용 | 30/36 = `0.8333333333333334` | `12.482965006828001` | `12.482965006828001` |

클램프 구현(`clampSpan`)은 `contactOrient.ts` 에 존재하지만 **`frontEdgeOf` 산출 경로에서 호출하지 않는다**(계측에서만 사용). 채택했다면 차량 prior `CAR_BODY.widthM=1.85` 에 의존하게 되므로, 이득이 확인되지 않은 상태에서 prior 의존을 늘리지 않았다.

**Q1. `r26_edge_kink_2_2_0cf4fda4d3aa` — 24회차에 0/8 이던 밀집 프레임에서 자홍 앞변이 실제 앞범퍼 접지선 위에 놓이는가?**
**부분적으로만.** 확대 확인 결과 자홍 앞변은 앞범퍼 접지 근처에서 시작하지만 **차체 아래를 지나 오른쪽(옆면 방향)으로 더 뻗는다** — 앞범퍼 폭에 딱 맞지 않는다. 그래도 chord(같은 프레임 `_crop_chord_22.png`)가 **차량을 대각으로 가로질러 옆 주차면까지 뻗던 것**에 비하면 명확히 짧고 접지에 가깝다. 이 프레임의 방위오차 median 은 `49.0`° → `14.4`°(헤더 표기), 앞변 지면길이 median 은 `4.0`m → `2.6`m.

**Q2. `r26_edge_kink_1_1_6006a034bfe2` — 저틸트(8.7°) 원경 마스크에서 자홍 앞변이 어디에 놓이는가? 꼬리 늘어남이 눈에 보이는가?**
자홍 앞변은 각 차량 **하단 접지선을 따라** 놓이며, 이 프리셋은 정면에 가까운 시점이라 앞변이 비교적 안정적으로 잡힌다. **꼬리 늘어남은 픽셀 이미지에서는 눈에 안 보인다** — 그것은 역투영 후 지면에서 나타나는 현상이고(§1-3 의 `10.67`~`13.20` m), 화면상으로는 짧은 선분이 원경에서 큰 지면 거리로 확대되는 것이라 **육안으로 판별 불가**다. 이 항목은 **수치(§3-4)로만 확인된다**.

**Q3. chord/kink 두 장 대조 — 산출 quad 의 회전량이 눈에 띄게 줄었는가?**
**그렇다, 명확히.** chord 장에서는 산출 quad 가 거의 전부 **빨강(비매칭)**이고 프레임을 가로지르는 큰 대각선을 이룬다. kink 장에서는 **시안(매칭) quad 가 등장**하고 주차면 방향과 대체로 정렬된다. 다만 이는 §2의 「개선 16 · 악화 14」와 모순되지 않는다 — 육안으로 두드러지는 것은 **크게 망가졌던 건의 개선**이고, 원래 잘 맞던 건이 조금씩 나빠진 것은 눈에 잘 띄지 않는다. **육안을 성립 근거로 쓰지 않는다.**
