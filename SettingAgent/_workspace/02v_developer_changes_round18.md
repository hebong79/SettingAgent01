## 2. A. 개수 없는 행 범위 — "내부 구멍은 보간, 바깥은 외삽 금지"

`bayGrid.ts` `fitRowGridOnce` 의 창 선택이 `opts.rowExtentMode` 로 갈린다.

- `'expected'` — `expectedBays` N칸 연속창. **기존 블록을 바이트 동일하게 보존**(회귀 비교 전용).
- `'evidence'`(기본) — kept 를 격자인덱스 오름차순으로 보며 인접 차 `≤ maxGap+1` 이면 같은 run,
  넘으면 끊는다. run 이 여럿이면 `sum(near)` 최대인 run 을 창으로 삼는다(기존 `bestSum` 선택과 동형).
  run **내부** 결손은 기존 격자 quad 로 되살리고 `filledIndices` 에 전부 기록한다.
  **창 양 끝 밖으로는 한 칸도 확장하지 않는다.**

새 튜닝 파라미터를 만들지 않았다 — 기존 `maxGap`(3)을 그대로 쓴다.

`extentEndedBy: {lo, hi}` 로 양 끝이 왜 끝났는지 보고한다:
`'evidence'`(다음 칸이 프레임 안인데 도색 없음 = 진짜 끝) / `'frame'`(화면의 끝 = **미완결**) / `'span'`(격자 생성 범위 끝).

### 실측된 부작용 — 창이 짧아지면 **위상 탐색이 다른 위상을 고른다**

`maxGap` 을 좁혀 run 을 끊었더니 채택 칸 수가 **줄지 않고 늘었다**. 반칸 어긋난 격자가 6칸 전부에서
부분 지지(0.5 안팎)를 받아 커버리지 1.0 을 얻고 이겼기 때문이다.
→ 유닛테스트는 칸 수를 고정하지 않고 **전방선을 참값으로 고정한 `fitRowGrid`** 로 창 규칙만 격리해 잰다.
→ 규칙이 보장하는 것은 "지지 없는 칸에 다리를 놓지 않는다"이지 "칸 수가 준다"가 아니다. 이 구분을 테스트에 박았다.

### 끝 칸 결손(U1·2:2)은 **고치지 않았다**(리더 지시)
N-창이 억지로 채워 가려 왔던 결손이 이제 재현율 미검출로 드러난다. 그것이 이번 라운드의 목적이다.

## 3. ★ 설계 초안 `:314` denom 변경 — 실측으로 기각(3안 확정)

설계 §2-3 은 `'evidence'` 모드에서 `denom = Math.max(1, inFrameCells)` 로 바꿔 `expectedBays` 만 빼자고 했다.
**구현해서 재 봤더니 전제가 틀렸다.**

| | phase(m) | quads(격자idx) | paint.score | inFrameCells | coverage | effective |
|---|---|---|---|---|---|---|
| expected(정답 격자) | 10.42370 | −4,−3,−2,−1 | 0.8958 | 5 | 4/4=1.0 (min 클램프) | 1.98510 |
| evidence(같은 격자) | 10.42370 | −4,−3,−2,−1 | 0.8958 | 5 | **4/5=0.8** | 1.588 |
| evidence(승자) | 0.81250 | 0,1,2,3 | 0.7637 | 4 | **4/4=1.0** | 1.83855 |

두 격자는 폭방향으로 **0.389m**(칸의 15.6%) 어긋나 있고 그게 IoU 0.96→0.75 의 전부다. 전방선은 두 모드가 동일했다.

**원인(설계자가 F18 로 등재)**: `inFrameCells` 는 `scored`(= 그 위상의 `kFrom..kTo` 전 칸)에서 세는데
`kFrom`/`kTo` 가 `phase` 의 함수라 **분모 자체가 위상 의존 자유변수**다. `min(expectedBays, ·)` 클램프가
그 병리를 가려 왔다. 클램프를 빼면 "프레임 밖으로 칸을 잘 밀어낸 위상"이 보상을 받는다.

**손익**: 재현율은 두 모드 **동일**(17/41). 즉 **이득 0 · 손실 0.21**.

→ 설계자와 합의해 **3안(`:314` 무변경)** 채택. `rowExtentMode` 는 창 선택 규칙만 바꾼다.

### 설계자 제안 4안(위상 불변 분모) 측정 — **게이트 실패, 19회차로 이월**

`denom = max(1, min(maxRowCells, round((spanHi−spanLo)/w)))` 로 재 봤다.

| 1:1 | 0.97474 | 0.97474 | 통과 |
| 1:2 | 0.95373 | **0.95373** | 통과(게이트 1) |

설계자가 정한 규칙("하나라도 실패 → 3안 유지")대로 **즉시 되돌렸다.**

### ★ 잔여 누출 — 숨기지 않고 명시한다

**`expectedBays` 가 커버리지 항(`:314`)에 남아 있으므로 목표 ①의 "개수 무사용"은 부분 달성이다.**

두 모드 17/41 동일로 실측됐다. 창 선택 규칙(어느 칸을 낼지)에는 개수가 전혀 쓰이지 않는다.

## 4. B. 다중 행 출력 — 가산만

`GridDetection` 에 `rows: GridResult[]` **추가만** 했다. 파라미터 불변, 소비자 10곳 수정 0줄.

- **위치**: `scoredCands` 조립 직후, **거리 게이트 앞**. `maxRowDistanceRatio` 는 `pool`(= `best` 전용)에만
  걸리도록 구조적으로 고정했다 — 게이트가 `rows` 에 걸리면 목표 ①("먼 행도 찾는다")이 정면으로 깨진다.
- **`best` 경로 무변경**: 거리 게이트·argmax·지상고 보정·근변선 재적합을 **한 줄도 옮기지 않았다**.
- **dedup**: `quadIoU` 재사용(R4, 신규 IoU 0줄). B 의 quad 중 A 의 어떤 quad 와 `quadIoU ≥ rowMergeIoU`(0.5)
  인 것이 **절반을 넘으면** B 를 버린다.
- **정렬**: `paint.score` desc → `quads.length` desc → 순회 인덱스 asc.
  **`effectiveScore` 를 쓰지 않는다** — `aimCenterWeight` 가 곱해져 있어 목록 1등이 도색 증거가 아니라
  조준으로 정해지면 서열 규약이 목록에서 역전된다.
- **F-b 진단**: 전방선 각 차 < 1° 이고 위상 차가 칸 주기로 < 0.25m 면 `issues` 에 `행 조각 의심` 을
  **기록만** 한다(자동 병합 없음). `'evidence'` 모드에서만 발화해 `'expected'` 회귀 출력은 바이트 동일하다.

`aimCenterWeight`(1.6)는 값 불변이고 `best` 선택에만 작용한다. 역할 구분:
**`best` = 조준·거리까지 고려한 대표 행 / `rows` = 도색 증거 기준 전체 행.**

## 8. 미검증 · 실패 · 한계 (은닉 없음)

1. **설계 §8 의 재현율 예측 23/41 = 0.561 은 과대였다.** 실측 출발점은 **17/41 = 0.4146**.
   어긋난 이유: 1:3 은 정본·검출 모두 실패(씬 가시 2면의 도색 지지가 0), 2:2 는 d0 기저시점에서 원래 0.
   예측을 실측에 맞춰 지우지 않고 둘 다 남긴다.
2. **다중 행 정밀도 0.18** — 설계 §6-7 의 "0.9 미만이면 오검출 목록을 먼저 본다" 기준을 크게 밑돈다.
   `spurious` 목록은 로그에 있으나 **원인 분류는 하지 않았다**(이번 라운드 범위 밖).
3. **`rowMergeIoU=0.5` 의 타당성 미측정** — 설계 §6-4 가 요구한 "같은 행 쌍/다른 행 쌍 겹침 비율 분포"를
   찍지 않았다. 현재 0.5 는 **설계 초안값 그대로**이며 골짜기에 있는지 확인되지 않았다. **미측정이다.**
4. **`minAreaPx = 200` 의 근거 미측정** — 설계 §7-4 가 요구한 면적 분포를 찍지 않고 값을 정했다.
   41면이라는 가시 면 수는 이 값에 의존한다. **미측정이다.**
5. **`measure.cameraHeight` Unity 조회(설계 6-1) 미실시** — `planeYM=0.05` 는 정본 재현 스윕에서
   역산한 값이고, 정본과 무관한 독립 확인은 하지 않았다. §7-1(설치고 정책)은 **리더 결정 대기**이며
   `calibrateHeight` 는 손대지 않았다.
6. **d0 단일 시점만 잰다** — `roiAutoRecall` 은 디더 6시점 합의·융합을 하지 않는다.
   그래서 2:2 가 0 으로 나온다(`roiAutoFuse` 의 "③ 선별 tilt보정"에서는 0.94 다).
   **재현율 수치는 "합의 이전" 성능**이며, 합의를 얹으면 올라갈 여지가 있다. 그 측정은 안 했다.
7. **F-c(연속 주차장에서 run 이 안 끊김)** — 시뮬 5뷰에 미발현. 실카 위험으로 표기만 한다.
8. **실카에서 재현율은 측정 불가** — `preset.list` 가 없다. 도구 헤더와 로그 첫 줄에 박아 두었다.
9. **`bayGrid.ts:508` 조기반환** — 리더 지시대로 손대지 않았다(별도 라운드).
10. **`bayGrid.ts` 가 `autoRoiPlan.ts` 를 import 하게 됐다**(`quadIoU` 재사용, R4 준수).
    `autoRoiPlan.ts` 는 `placeRoi` 를 import 하므로 **bayGrid 의 모듈 그래프에 capture 계층이 전이적으로 들어온다.**
    데이터 접근은 없고 기존 정적 봉인(소스 문자열 검사)도 전부 통과하지만, **구조적으로는 봉인이 한 겹 얇아졌다.**
    보고 대상으로 남긴다 — 필요하면 `quadIoU` 를 의존 없는 모듈로 옮기는 별도 작업이 필요하다.
