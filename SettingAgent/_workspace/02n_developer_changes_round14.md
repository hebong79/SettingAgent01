**조치:** 리더 승인 하에 **서비스에 배선하지 않았다.** 지시 문언은 "옵션 플래그로 강등"이나 그것은 *부분* 실패 대비 조항이고, 세 기준을 다 실패한 경로를 위해 시점별 quad 를 기저 픽셀로 되돌리는 배관 ~25줄을 프로덕션에 넣는 것은 "하나 살리고 둘 깨지 말 것"에 어긋난다. **재현 가능한 구현은 `src/tools/roiAutoFuse.ts` 에 남겼다** — 되살리려면 그대로 옮기면 된다.

**왜 실패했나(관측 사실만):** 융합은 **잡음을 평균하는 것이 아니라 시점별 계통 차이를 평균한다.** 시점별 자가보정 지상고가 `1:1` 4.956~5.080m, `2:1` 4.983~5.121m 로 갈리고 tC 드리프트도 시점마다 −0.01~−3.60px 로 다르다. 기저 시점이 이미 좋은 `1:1` 에서는 나쁜 시점을 섞어 **악화**하고, 기저가 나쁜 `2:1` 에서는 **개선**한다. 방향이 프리셋마다 반대다.

"`1:2` 최대 IoU 0.827~0.900" 은 자동 격자가 정확히 2.5×5.0m 에 고정됐을 때의 해석적 상한이다(내가 재계산해 같은 값을 얻었다: 폭배율 1.0540~1.1236 × 깊이배율 1.0542~1.0760 → 1/(a·b) = 0.8271~0.9000).

**그러나 지상고 자가보정이 격자 배율을 자유롭게 만들어 이 상한이 구속력을 잃는다.** 실측이 상한을 넘는다:
```
1:2  s8=0.9073  s9=0.9553  s10=0.9698  s11=0.9825   ← s11 이 "상한 0.9000" 을 크게 초과
```
`1:2` 는 **≥0.95 3/4 · ≥0.98 1/4 로 현재 가장 잘 되는 프리셋**이다. 제외하면 개선 신호를 정리하는 게 아니라 **통과면 3개를 지운다**(§2-2). **리더 지시대로 회신 전까지 현행 유지했고 양쪽 집계를 병기했다.**

`1:3` 은 이미 `graded:false`(D1_TOO_FEW_BAYS) 이므로 추가 조치 불필요. 축 뒤바뀜은 모델 표현범위 밖 — 변동 없음.

### ② 서버 재시작 — **해소됨.** 13020 은 nodemon 이 반영하고 있고 `roi.auto.*` 3종 정상 응답. 재시작 요청 0건.

## 9. 15회차 권고

1. **`selectedCameraId` 를 시뮬로 되돌린 뒤** 서비스 라이브 채점을 재개하라. 되돌리기 전 라이브 수치는 전부 무의미하다.
2. **골든 세트 위에서만 알고리즘을 움직여라.** 라이브는 최종 확인용.
3. **다음 표적은 `2:1`(≥0.95 1/6, 평균 0.854)** 이다. 골든 세트에서 `2:1` 이 잡은 프레임(`e33628e921c2`)은 **정착본**이고, 이동 직후본(`80cdf49cdecc`)은 0.966(4/6)이다. **어느 쪽이 실카를 대표하는가**를 먼저 정해야 `2:1` 의 진짜 결손을 잰다 — 이건 튜닝이 아니라 **평가 기준 확정**이다.
4. **지상고 자가보정이 증폭기다.** 화소 MAD 0.068 짜리 프레임 차이가 관측 칸간격 2.5093→2.3853m(−4.9%)를 만들고 그것이 IoU 0.21 을 움직인다. `CALIB=0` 실측: `1:1` 0.85541→**0.93182**, `2:1` k1/k3 격차 0.115→**0.0002**(소멸). **반증목록에 없는 미탐색 항목**이며 골든 세트 위에서 통제 비교가 가능하다.
5. 마스터 결정 대기: **`1:2` 채점 제외 여부**(§5 ①. 내 권고는 **제외 반대**).
