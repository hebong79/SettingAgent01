## 1. D1 — UI 가 `expectedBays: 0` 을 보낸다 (마스터가 본 그 에러)

**원인**(리더 진단 그대로 확인): `apNum('ap-bays')` 는 **빈 칸만** `undefined` 로 만든다. 칸에 `0` 이 있으면 `Number('0')=0` 이 유한하므로 그대로 전송되고 스키마 `z.number().int().min(1)` 이 거부한다 → `invalid params — expectedBays: Number must be greater than or equal to 1`.

**수정(보내는 쪽)** `web/app.js`
```js
const baysRaw = apNum('ap-bays');
const expectedBays = Number.isInteger(baysRaw) && baysRaw >= 1 ? baysRaw : undefined;
const baysDropped = baysRaw !== undefined && expectedBays === undefined;
```
- 1 미만·비정수는 **보내지 않는다**(서버 의미로 **0 = 「모른다」** 이고, Phase 1 의 `coverageDenom` 이 `expectedBays >= 1` 로 갈리므로 미지정과 같은 뜻이다).
- **조용히 무시하지 않는다**: `⚠️ 예상 주차면 수 0 은 **미지정으로 처리했다**(1 이상 정수만 쓴다 — 0 은 「모른다」와 같은 뜻이다). 개수를 쓰지 않고 검출한다.`
- **서버 스키마는 그대로 엄격**하게 뒀다(0 은 계속 거부). 리더 지시대로 고칠 곳은 보내는 쪽이며, 스키마를 느슨하게 하면 "0 을 보내도 된다"는 계약이 생겨 다른 클라이언트가 같은 함정에 빠진다.
- **칸에 왜 `0` 이 있었는가 — 미측정.** HTML `min="1"` 은 브라우저 **검증** 속성이라 `0` 입력·잔존을 막지 않는다(`type=number` 는 값 자체를 거부하지 않는다). Phase 1 에서 placeholder 를 「비워라(개수 미사용)」로 바꿨으므로 새로 0 을 유도하지는 않는다. 마스터가 직접 넣었는지 이전 상태의 잔값인지는 **알 수 없다 — 추정하지 않는다.**

## 2. D2 — 틸트: 부호를 뒤집지 않고 **왕복 검산으로 알아본다**

**수정** `src/rpc/services/roiAuto.ts` — `specTiltEqualsViewerTilt()` 신설 + hucoms `providerFor`/`warningsFor`.

판정은 **세 조건이 동시에** 성립할 때만이다:
1. 입력값이 하향 각도로 **쓸 수 없다**(≤ 0). 양수면 그럴듯한 하향 각도이므로 **손대지 않고 경고만** 한다.
2. 소스 환산기가 **항등이 아니다**(항등이면 "표시값"과 "네이티브 각도"를 구분할 근거가 없다).
3. `toNativePtz({tilt: 입력값})` 이 **이 프레임의 tiltpos 와 ±1(=0.01°) 안에서 일치**한다.

→ 확인되면 **미지정으로 강등**(장비 `tiltpos/100` 사용)하고 그 사실을 ⚠ 로 크게 남긴다. 확인되지 않은 음수는 **손대지 않는다**(R3).

`abs()` 도, 무조건 부호 반전도 없다. 근거는 §0 의 13.2982° 오차 실측이다.

**추가 수정(중요)**: `D5_VP_DEGENERATE` **강등 경로에서도 경고를 싣는다.** 종전에는 그 한 줄만 나가서 **원인을 말해 주는 경고가 정확히 필요한 순간에 버려졌다**(마스터가 본 화면이 이 경로였다). 유닛테스트가 이 회귀를 잡았다.

**수정**: 수동 입력이 자동 해석값과 **15% 이상**(화각) / **3° 이상**(틸트) 다르면 ⚠ 경고. 규약은 그대로 — **입력값이 이기고**(조용한 재해석 금지) 차이를 알린다.
```

   광각단 사양값(예 58°)을 유효 화각으로 쓰지 마라 — 칸을 비우면 실측표가 쓰인다.
```
**설치고**: `real-camera-1` 에 `cameraSpec.heightM` 이 없어 **비우면 명시 거부**(17회차 설계대로)다. 파일에 13m 을 **써넣지 않았다** — `real-camera-2` 의 13m 을 복제할 근거가 없고(같은 기종이라는 증거 없음), 설치고는 줄자 실측이다. **마스터 입력 또는 실측 등록이 필요하다**(미해결로 남긴다).

**뷰어 안내**(값을 유도하지 않게): 실카에서 틸트 placeholder 「비워라(장비 tiltpos 자동)」 · 화각 placeholder 「비워라(실측표 자동)」 + tooltip 에 range-fit 함정과 58° 함정을 실측 수치로 명시.

## 7. 측정 불가로 남긴 것

1. **실카 재현율·정밀도 — 측정 불가**(씬 정답 부재). 검출 면수·오버레이·기하 자가검산만 낸다. 마스터가 화면상 면수를 세어 주면 그때 대조한다.
2. **`real-camera-1` 의 설치고** — 파일에 없다. 13m 은 마스터 입력값이며 **실측 근거를 확인하지 못했다**(`real-camera-2` 의 13m 복제 금지).
3. **갯수 칸에 `0` 이 있던 경위** — 알 수 없다.
4. **실카 동일 프레임 전후 비교** — 실카에는 프레임 캐시 경로가 없어 두 오버레이의 frameHash 가 다르다.
