## 3. 구조 제약(리더 지시 2) — **측정했고, 이 씬에서는 성립하지 않는다**

★ **반증목록 #9 재확인**: #9 는 `medianDepthM` 하나로 후보를 자르는 **거리 단독 하드 게이트**다.
이번 구조 제약 검토는 **행끼리의 관계**(평행·등간격)이며 거리를 게이트로 쓰지 않는다 — **겹치지 않는다.**
그리고 아래 실측대로 **채택하지 않았다**. `maxRowDistanceRatio` 는 18회차와 같이 `rows` 에 미적용(기본 0)이다.

지면 위 행축(`RowFrame.u`)의 사잇각을 전 쌍에 대해 쟀다(이미지 각이 아니라 **역투영한 지면 각**).

| 관측 | 값 |
|---|---|
| **진짜 행 ↔ 진짜 행이 평행한가** | **아니다.** `1:2` 의 진짜 두 행(ci0·ci3)은 **89.60°** — 씬에 서로 **직교**하는 주차열이 실재한다 |
| 가짜 행이 진짜 행과 평행한가 | **평행하다.** `1:1` 0R-1F **0.12°**, 0R-6F 0.25° · `2:1` 0R-3F 0.40° |
| 등간격 검정 가능한가 | **불가.** 프리셋당 진짜 행이 1~2개뿐이라 간격 수열이 성립하지 않는다 |

→ **"진짜 행끼리 평행·등간격"이라는 전제가 이 씬에서 거짓이다.** 구조 제약을 넣으면 `1:2` 의 진짜 행 하나를
버리게 된다(재현율 −4면). **채택하지 않았고, 코드에 넣지 않았다.**
문턱만으로 목표를 넘겼으므로 변수를 섞지 않는 편이 낫다는 판단도 함께 작용했다.

## 4. dedup 이 왜 안 먹었는지 (리더 지시 3) — **기준이 느슨한 게 아니라, 후보들이 진짜로 안 겹친다**

후보 쌍 전수의 겹침을 `dedupeRows` 와 **같은 식**으로 쟀다.

| 측정 | 값 |
|---|---|
| 겹침비 = 0.000(제거 후보의 **어느 quad도** 상대와 IoU ≥ 0.5 에 못 닿음) | **186 / 214 방향쌍** |
| 겹침비 ≥ 0.5(= 실제로 제거된 쌍) | 19 방향쌍 |
| 쌍별 **최대 quadIoU** 분포 | 0.0~0.1: 54 · 0.1~0.3: 28 · **0.3~0.5: 104** · 0.5~0.8: 26 · 0.9~: 2 |
| 실제 dedup 제거 수 | 후보 39 → 행 33 (**6개 제거**) |

**판정: dedup 은 애초에 해법이 아니었다.** 겹침 질량이 **0.3~0.5 구간**(104쌍)에 몰려 있는데, 이건
후보들이 서로 반 칸쯤 어긋난 **서로 다른 엉뚱한 위치**에 있다는 뜻이다. 기준을 0.5 → 0.35 로 내리면
그 104쌍이 병합 대상이 되지만, 그건 "겹치는 쓰레기를 하나의 쓰레기로 합치는" 것이지 **목록에서 빼는 것이 아니다**
(정밀도는 그대로다). 필요한 것은 병합이 아니라 **진입 문턱**이었다.

→ `rowMergeIoU = 0.5` 는 **이번 라운드에 바꾸지 않았다.** 18회차 §6-4 미측정 이월은 이로써 **해소**한다:
0.5 는 "골짜기에 있는 값"은 아니지만(분포는 0.3~0.5 에 봉우리가 있다), **이 문제의 지배 변수가 아니다.**

## 5. 구현 — 진입 문턱 (`bayGrid.ts` +14줄)

```ts
// dedup 뒤에 문턱을 건다. 기준은 best 로 뽑힌 후보의 도색 점수(프리셋마다 스케일이 다르다).
let refScore = 0, refEff = -Infinity;
for (const e of scoredCands) {
  const s = e.r.effectiveScore ?? e.r.paint.score;
  if (s > refEff + 1e-12) { refEff = s; refScore = e.r.paint.score; }
}
const rows = dedupeRows(scoredCands.map((e) => e.r), opts)
  .filter((r) => r.paint.score >= refScore * opts.rowMinScoreRatio && r.paint.near >= opts.rowMinNearSupport);
```

설계 사항 4가지:

1. **위치는 dedup 뒤**다. 앞에 두면 걸러진 고득점 행에 흡수됐어야 할 저득점 중복이 살아남는다(단조성 깨짐).
2. **기준 후보 선정은 `best` argmax 와 같은 식**(strict `>` + `1e-12`, 동점은 먼저 담긴 쪽). 새 규약을 만들지 않았다.
3. **거리 게이트 앞이라는 18회차 구조는 유지**된다 — `maxRowDistanceRatio` 는 여전히 `pool`(= `best` 전용)에만 걸린다.
4. **0 을 주면 18회차 동작 그대로**다(끄기 가능). 회귀 비교 통로를 남겼다.

`best` 산출 경로는 **한 줄도 건드리지 않았다.**
