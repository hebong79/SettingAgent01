## 6. 어떻게 좌표를 잡았나 (검증 가능하게)

면의 변은 **직선 3종의 교점**으로 잡았다. 각 직선은 이미지에서 측정한 두 점으로 고정했고, `truth.json` 의 `lines[].evidence` 에 **측정 원자료를 그대로** 적어 두었다.

측정 방법(모두 `src/tools/evPresetProbe.ts`, 라벨 보조 도구 — 검출 알고리즘 아님):
- **도색선**: 지정 행/열의 **원시 밝기 프로파일**을 8~12px 간격으로 찍어 밝은 띠의 중심을 읽음 → 최소자승 직선 적합
- **재질 경계**(연석↔아스팔트, 블록↔아스팔트): 세로 방향 **밝기 계단(gradient)** 최대점
- **잔디 경계**(EV3·EV4 원변): 회색조가 아니라 **초록도 `G−(R+B)/2`** 로 잔디 띠의 위/아래를 읽음 → 잔여 오차 <3px

적합 품질(직선 잔차):
- EV1 근변선 <2px · EV4 근변선 <1.5px · EV4 잔디선 <3px · EV3 칸막이 S1 <1.5px · EV4 칸막이 C 잔차 0
- EV2 는 도색 4선을 원시 프로파일로 재확인 → 모두 **±5~10px 이내** 일치
- EV5 근변선 <0.6px 이나, **판독 가능한 열이 3개뿐**이라 (x=900/1700 은 차량 그림자·수목) 여전히 불확실

## 8. (여력분) `detectPaintLines` 읽기 전용 관찰 — **관찰일 뿐, 채점 아님**

`src/tools/evPresetPaintObserve.ts` 로 5장에 기본 옵션 그대로 돌려 상위 12직선을 그렸다(`paintobs_EV*.png`). **수치 결론은 내지 않는다.**

- **EV4**(도색 있음): 상위권에 **근변(블록↔아스팔트 재질 경계)을 거의 정확히 따라가는 직선이 있다**(#4 v611). 즉 근변선은 도색이 아니어도 잡힌다. 반면 **칸막이 도색선은 상위 12개 안에서 확실히 대응시키기 어려웠다.**
- **EV1**(도색 있음): 칸막이 P3·P4·P5 를 따라가는 직선이 여럿 보인다. 다만 차량 지붕 반사·연석·수목을 지나는 **가짜 직선이 상위권에 다수 섞여 있다.**
- **EV2**(도색 있음, x95): 검출 60개 중 상위 votes 가 712/578 로 크게 벌어지고, 나머지는 200 미만으로 급락한다.
- **EV3·EV5**(도색 없음): 상위 직선 대부분이 **차량 유리 반사 띠·건물 창틀·보도블록 seam** 을 따라간다. 특히 **EV5 는 면 칸막이 방향(거의 세로)의 직선이 상위 12개에 하나도 없다.** 도색이 없는 장면에서 무엇이 잡히는가에 대한 답은 "면 경계가 아니라 차량 반사와 건물 선"이다.

## 9. 스키마 (truth.json)

```
{ schema, purpose, author, createdAt, coordinateSystem, cornerStatus{...},
  presets: [ {
    preset, sourceFile, imageWidth, imageHeight, osdPtz, osdNote, sceneNote,
    lines: [ { id, kind:'near'|'far'|'sep', a:{x,y}, b:{x,y}, uncertain, evidence } ],
    bays:  [ { id, occupied, occluded, clipped, uncertain, leftSep, rightSep,
               corners: { nearLeft|nearRight|farRight|farLeft: { status, pt:{x,y}|null, note? } },
               cornerOrder: ['nearLeft','nearRight','farRight','farLeft'], note } ]
  } ] }
```

- 좌표계: **원본 이미지 픽셀**(좌상단 0,0 / x→우 / y→아래), 소수점 **최대 5자리**(프로젝트 `round5` 규약).
- `cornerOrder` 는 다각형 순회 순서(시계/반시계는 프리셋 시야에 따라 다름 — 순서대로 이으면 사각형이 된다).
- `nearLeft/nearRight` 의 좌/우는 **이미지 x 기준**이 아니라 "좌측 칸막이/우측 칸막이"에서 온 이름이다. 각 면의 `leftSep`/`rightSep` 로 확인 가능.
