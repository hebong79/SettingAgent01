→ 설계 §2 「안 1을 언제 꺼내는가」의 착수 조건 1번이 **해소됐다**. 조건 2(안 1 τ=0.82 생존 8면과의 겹침)는 여전히 미측정.

## 9. ★ 정직하게 — 이 이터레이션이 22회차 상한과 무엇이 다른가

### 다르지 **않은** 부분 (= 상한 재측정에 불과한 부분)

- **산출 수치 전부.** recall `0.9512195121951219` · precision `0.9285714285714286` · outputs 42 · faces 39 — 22회차와 **비트 동일**하다. 그것이 P3 의 설계 의도이며, 다르게 나왔다면 이식 실패였다.
- **관측 소스가 여전히 `degradeCar` 강등 투영이다.** 골든 프레임의 픽셀을 차량 검출에 **한 바이트도 읽지 않는다**(도색 증거 `edgePaintSupport` 측정에만 프레임을 읽는다). 이미지에서 차량을 검출하는 부분 전체가 **아직 없다**.
- **차량 치수 단일 가정** 4.7×1.85×1.45m 그대로. 종별 치수 미측정.

### **다른** 부분 (= 이 이터레이션의 실제 산출물, 3가지)

| # | 새로 생긴 것 | 실제로 새로 측정된 값 |
|---|---|---|
| **(a)** | **교체 가능한 `ObservationSource` 경계** | 수치 산출물 없음(구조). 22회차는 `main()` 안 인라인 루프였고, 이제 실카 전환의 접점이 **`observe(t, view)` 함수 1개**로 좁혀졌다. `ObservationKind` 에 `real-seg`/`real-vpd`/`real-lpd` 자리가 이미 있다 |
| **(b)** | **게이트 3층이 실재하고 효과가 측정됐다** | **★ 22회차가 못 잰 값: 게이트는 이 데이터에서 아무 효과가 없다.** F10 결손 3건 중 **0건**이 죽고 참도 **0면** 죽는다. 조이면(`maxOut=1`) 잡음 2 : 참 2 의 1:1 교환이 되어 **P4 실패**. 면적 하한은 원리적으로 이 잡음(칸 밖 큰 차)을 못 잡는다 |
| **(c)** | **배타성 해소가 파이프라인에 들어갔다** | **접힘 0건.** σ=10/그림자=15 에서도 0건. 22회차가 「필요 없었다」고 넘어간 것이 **실제로 필요 없음이 측정**됐다 |
| (보너스) | **σ 관측소스 승격** | 게이트 유무 차이 **0** (§8-1). 22회차 σ 표는 게이트 없는 값이었고, 게이트를 붙여도 같다는 것이 확인됐다 |
| (보너스) | **미회수 2면 ID 특정** | `1:2\|r2f2`(차량있음) · `1:3\|r5f2`(빈 면) — §8-2 |

**한 줄 요약**: 이번 이터레이션은 **수치상으로는 상한 재측정**이고, **구조상으로는 실카 전환의 접점을 1개 함수로 좁힌 것**이며, **새로 안 사실은 "게이트가 이 데이터에서는 순손실"이라는 부정 결과**다.

## 11. 금지 규약(G1~G8) 준수 방식

| 규약 | 준수 방식 |
|---|---|
| **G1** | `proposeFromObservation` 의 반환 타입이 **`BayProposal \| null`** — 배열이 아니다. 타입이 「관측 1건 → 면 2개」를 막는다. 테스트 1이 `obsId` 유일성으로 재확인 |
| **G2** | `phase + k*w` 복제 없음. 격자 좌표 생성 코드 0줄 |
| **G3** | 격자 인덱스 개념 부재 |
| **G4** | 행 단위 창 없음 |
| **G5** | **행 단위 점수 없음.** `gateBay(p, g)` 는 인자가 면 1개와 절대 파라미터뿐 — 다른 면을 볼 방법이 시그니처에 없다. 분모·비율·상대점수 0개 |
| **G6** | 면 개수를 미리 아는 인자가 어느 시그니처에도 없다 |
| **G7** | 근변선 재적합 없음 |
| **G8** | 면간 정렬 가점 없음. 면끼리의 유일한 상호작용은 **배타성 해소(겹치면 하나만)** |
| **정적 봉인** | 테스트 2가 소스 문자열에서 `filledIndices`·`latticeIndex`·`expectedBays`·`coverage`·`refScore`·`rowMinScoreRatio`·`effectiveScore` **7개 토큰 부재**를 강제 |
| **IoU 재사용** | `autoRoiPlan.quadIoU` 만 사용. 신규 IoU **0줄** |
| **오라클 격리** | `faceSlot`·`presetId`·`visible` 은 검출 경로가 읽지 않는다(`degradeCar` 가 유일 경계). 정답 `t.vis` 는 `closedOf`/`scoreBays` 에서만 접촉. 테스트 3(봉인)·4(대조군)이 강제 |
| **중복 고지** | `resolveBays` 는 `anchorCloseUpper.resolveExclusivity`(서열 키가 `predHit`·`sepSpanPx` 로 박혀 재사용 불가)와 **알고리즘이 같은 8줄 중복**이다. 설계 §1-5 의 결정을 그대로 따랐다 |
