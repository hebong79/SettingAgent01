> **"점 4개를 찍은 후 사각형이 그려지지 않는다."**

"코드가 그 자리에 있다"까지만 증명했던 영역이고, 마스터 실사용이 그것을 뚫었다.

## 리더 진단 (코드 근거 확정 — 재조사 불필요)

### 원인 1 — 그리는 중 경로가 닫히지 않는다
`web/app.js:655-659` `drawPlaceDrawOverlay`:
```js
if (pts.length > 1) {
  ctx.beginPath();
  pts.forEach((p, i) => (i ? ctx.lineTo(p.px, p.py) : ctx.moveTo(p.px, p.py)));
  ctx.stroke();            // ← closePath() 없음
}
```
4점을 찍어도 **변 3개짜리 열린 선**만 보인다. 마스터가 본 그대로다.

### 원인 2 — 커밋 후에도 화면 변화가 0일 수 있다
4번째 클릭에서 `placeDrawClick`(app.js:2341-2353)은 정상 동작한다:
`appendPlaceSpace` → `state.placeRoi` 반영 → `endPlaceDraw()` → `drawRoiOverlay()`.
그런데 그 면을 그리는 `drawFileFloorRoi` 가 **`app.js:611` 에서 `!$('roi-floor').checked` 면 즉시 return** 한다.
`drawPlaceDrawOverlay` 의 **정점 핸들도 같은 토글을 요구**한다(app.js:644).

마스터 캡처에 **자동ROI(주황 점선)는 보이는데 초록 파일 ROI 가 하나도 없는 것**이 이 상태와 일치한다.

확인된 사실:
- `#roi-floor` 는 `index.html:41` 기본 `checked`
- `selectFloorRoi`(core.js:542)는 **필터링을 하지 않는다** — `placeRoi[key]` 를 그대로 매핑
→ **토글만 켜지면 반드시 보인다.**

### 결함 유형 판정
**미리보기 무반응과 완전히 같은 유형이다** — 동작은 성공했는데 화면 변화가 0이라 사용자는 실패로 인식한다.
`ggPreview` 는 `$('roi-auto').checked = true`(app.js:1992)로 **강제로 켜주는데 그리기 경로에는 그 대응이 없다.**
같은 실수를 두 번 했다.

## 리더 확정 결정
- **원인 1·2 를 둘 다 고쳐라.** 하나만 고치면 다른 조건에서 같은 증상이 재현된다.
- 4점째에 **닫힌 사각형**이 보이고, 커밋 전(노랑 미리보기) → 커밋 후(초록 파일 ROI) 사이에
  **화면이 비는 순간이 없어야** 한다.
- 그리기 **시작 시**에도 `#roi-floor` 를 켜라 — 기존 면이 보여야 어디에 그릴지 안다.
- **정점 핸들의 `#roi-floor` 의존을 검토**하라. 토글 하나가 꺼지면 편집 수단이 통째로 사라진다.

## 신규 기능 (마스터 요청)
- **초기화(점·사각형만 지우기)**: 그리는 중이면 찍은 점 전부 삭제, 선택된 면이 있으면 그 면 삭제.
  **메모리(`state.placeRoi`)까지만** — 파일 반영은 '저장' 버튼에서만.
- **전체 삭제**: **현재 프리셋**의 파일 ROI 전부 삭제. 파괴적 → **확인 단계 필수**, 저장 전 되돌리기 가능,
  **범위(현재 프리셋인지 전 프리셋인지)를 버튼 문구와 확인문에 명확히** 쓸 것.
- 둘 다 **전역 idx 규약**을 깨면 안 된다. 삭제 후 재부여 필요 여부를 판단하고
  기존 `reindexPlaceSpace`/`removePlaceSpace` 를 **재사용**(신규 로직 최소화).

## Loop
1. `closePath` + 커밋 연속성 → 4점째 닫힌 사각형, 커밋 후 끊김 없음. **리더가 sharp 렌더로 육안 확인**
2. `#roi-floor` 강제 ON(시작·커밋) + 정점 핸들 토글 의존 검토 → 토글 꺼진 상태에서 그려도 보인다
3. 초기화 → 그리는 중/선택 각각에서 점·사각형만 사라지고 다른 레이어(검출·자동ROI)는 그대로
4. 전체 삭제 → 확인 단계 동작, 현재 프리셋만, 저장 전 되돌리기, 전역 idx 정합
5. 회귀 → 기존 캔버스 동작·L3 골든 해시·전량 테스트 유지

## 리더 결정 (2026-07-28, 설계 리뷰 후) — 판단 4건 확정

### ★ 리더 진단 정정 — 원인 1 은 증상의 원인이 아니었다
설계자 반박(코드 근거): `placeDrawClick`(app.js:2325-2354)에서 **4점째 클릭은 렌더를 거치지 않고 같은
동기 블록에서 커밋**되고 `endPlaceDraw()` 가 `state.placeDraw = null` 로 만든다.
→ `drawPlaceDrawOverlay` 가 `pts.length === 4` 로 호출되는 경로가 **존재하지 않는다**
(mousemove 도 `if (!state.placeDraw) return`). **`closePath()` 만 넣으면 화면은 1픽셀도 안 변한다.**

**리더 진단이 틀렸다.** 실제 증상 = **원인 2(`#roi-floor` 게이트로 초록 면이 안 보임)** +
**3점 단계에 닫힘 예고가 없어 사각형이 될 것임을 알 수 없음**.

**판단 1 ✅ 승인**: 설계자 해석 채택. `closePath()` 는 넣되(방어), 실제로 보이게 하는 수단은
**3점째 p3→p1 점선 닫힘 예고**. 커밋 계약은 불변. **원인 2 수정이 본체다.**

**판단 2 ✅ 승인**: 초기화/`place-delete` **병존**, 삭제 분기는 `deletePlaceSpace()` 에 위임(구현 중복 0).
초기화 우선순위 **그리는 중 > 선택 면**(비파괴 분기 우선), 그리기 모드는 유지.

**판단 3 ✅ 승인**: 전체삭제 범위 = **`currentFrameKey()`** — `drawFileFloorRoi` 와 **같은 기준**이라
"화면에 보이는 것을 지운다"가 사용자 기대와 일치한다.

**판단 4 ✅ 승인**: 되돌리기 **1단계 한정**(`state.placeRoiUndo` 전체 맵 스냅샷).
파일 재로딩 불채택(비결정론 + 다른 미저장 편집까지 파괴)에 동의. `placeRoiBackup`(자동보정 전용,
프리셋 단위라 전역 재번호 복구 불가)과 **분리** 유지.

### 채택된 코드 근거 판단 (그대로 구현)
- **idx 재부여 확정 — '구멍을 둔다'는 선택지가 없다**: `normalizeGlobalIdx`(core.js:640)가 idx 집합이
  1..N 순열이 아니면 **무조건 재부여**하므로 구멍은 저장해도 다음 로드에서 메워진다.
  `removePlaceSpace`(core.js:682)는 이미 전역 재압축 → **전체삭제 = 기존 '삭제' n회 = 새 위험 클래스 아님.**
  신규 순수함수 `clearPresetSpaces(placeRoi, key)` 는 **큰 idx부터** `removePlaceSpace` 를 접어 전량 위임
  (**core.js 무수정**).
- **정점 핸들의 `#roi-floor` 의존은 그대로 둔다**: 표시(644)와 히트테스트(1373)가 **이미 대칭**이라
  한쪽만 떼면 **"안 보이는 사각형을 드래그"** 하는 상태가 생긴다. 대신 그리기 시작·커밋·정점편집 ON
  **세 진입점에서 토글을 강제 ON**.
- **서버 무변경**: `PlaceRoiPutSchema.spaces` 는 min 없는 `z.array` → **빈 배열 PUT 통과**,
  `applyPlaceRoiUpdateEx` 통째 교체로 파일 반영 성립. `assemblePlaceRoi` 가 빈 키를 `[]` 로 보존해
  `savePlaceRoi` 순회에서 안 빠진다.
- **부수효과 고지 수용**: `#roi-floor` 강제 ON 은 artifact 슬롯 floor 히트테스트(app.js:4629)도 켠다 —
  기본값(checked) 상태와 동일 동작이라 **회귀 아님**.
