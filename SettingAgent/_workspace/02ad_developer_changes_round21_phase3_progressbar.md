## 1. 설계 — 거짓 진행률 금지 (이번 작업의 핵심 규율)

서버가 단계 진행을 보고하지 않으므로 시간으로 채우는 막대는 **추측**이다. 그래서 판정을 **순수 모듈**로 분리해 테스트로 못 박았다.

| 상태 | 조건 | 막대 | `aria` | 문구 |
|---|---|---|---|---|
| **① 진행 중** | `경과 < 예상` | 확정 폭 = `min(0.99, 경과÷예상)` | `aria-valuenow` **있음** | `25%` |
| **② 예상 초과** | `경과 ≥ 예상` | **불확정** — 좁은 띠(28%)가 왕복, **채우지 않는다** | `aria-valuenow` **DOM 에서 제거** | `예상 시간 초과 — 계속 진행 중` |
| **③ 완료·실패** | 응답 도착 | 막대 **숨김** → 결과 요약으로 대체 | `aria-valuenow` 제거 | `완료 — 검출 7면 · 프레임 6006a034bfe2 · 소요 12.3초` / `실패 — 거부 — 설치고 (소요 2.5초)` |

- **끝나기 전에 100% 를 보이지 않는다** — ① 구간 상한 **0.99** 클램프(테스트: 경과 11999/12000 → 99%).
- 예상 시간을 **아예 모르는 경우**(`etaMs=0`)는 처음부터 불확정이며 `"진행 중"`(초과라고 말하지 않는다 — `overdue:false`).
- 값이 없으면 `검출 면수 —`·`프레임 —` 로 남긴다(지어내지 않는다).
- **취소는 만들지 않았다**(요청 범위 밖 — 테스트가 `ap-cancel` 부재를 봉인).

- 실측하지 않은 조합에 값을 만들지 않았다(위 4개가 분기 전부). 실측 수치는 **테스트가 주석 존재를 검사**한다(값만 바뀌고 근거가 사라지는 것을 막는다).

### 기존 동작 변경 1건(정직하게)
`setInterval(tick, 1000)` → **250ms**. 막대가 1초 단위로 튀면 "멈춘 것"으로 보이기 때문이다. **화면 문구는 변하지 않는다** — `elapsed()` 가 초 단위로 반올림하므로 텍스트는 여전히 1초에 한 번만 바뀐다(DOM 쓰기 빈도만 4배). 타이머를 2개로 늘리는 대안은 수명 관리 중복이라 택하지 않았다.

### ★ 렌더 검증의 한계 (명시)
- 이 저장소에는 **브라우저 자동화가 없다.** 그래서 스샷은 실제 렌더가 아니라 **SVG 재현**이다.
- 재현의 충실도: 색·치수는 `web/app.css` 를 **실제 파싱**(track 6px · 불확정 띠 28%), 문구·진행률은 `web/apProgress.js` 를 **그대로 호출** → **그림이 로직·팔레트와 어긋날 수 없다.**
- 재현하지 못하는 것: **폰트·자간·flex 배치·CSS 애니메이션.** ② 의 왕복 띠는 애니메이션 **한 프레임**을 정지 화면으로 그린 것이다.
- → **배치·정렬의 최종 확인은 브라우저 육안이 필요하다**(마스터/리더). 라이브 서빙은 확인했다: `/viewer/` 에 `id="ap-progress"` 1건 · `/viewer/apProgress.js` 응답 정상 · `/viewer/app.css` 에 `ap-progress-track` 3건.

## 6. 못 한 것 / 남긴 것

1. **브라우저 실제 렌더 확인** — 자동화 수단이 없다(§4 한계). 마스터 육안 필요.
2. **취소 버튼** — 요청 범위 밖이라 만들지 않았다(테스트로 부재 봉인).
3. **실카 다시점 합의 ETA** — 실카는 디더를 찍지 않으므로(서버가 강제 OFF) 그 조합은 **존재하지 않는다**. 값을 만들지 않았다.
4. **`roi.auto.score` 실카 조합의 ETA** — 채점은 프리셋 종속이고 실카에 프리셋이 없어 조합이 성립하지 않는다(미측정으로 남김).
5. **진행바의 단계 표시**(프레임 취득 → 검출 → 채점) — 서버가 단계를 보고하지 않으므로 **만들 수 없다.** 만들면 그것이 곧 거짓 진행률이다. 서버가 단계 이벤트를 내보내게 되면 그때 확정 단계 표시가 가능하다.
