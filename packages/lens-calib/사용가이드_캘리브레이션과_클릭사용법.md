# 광각렌즈 캘리브레이션 · 클릭 조준 — 쉬운 사용 가이드

> **한 줄 요약**: ① 카메라로 스스로를 재서 **보정표를 만들고** → ② 표를 **켜고** → ③ 웹 화면에서
> **클릭하면 그 지점이 정확히 가운데로** 온다.
>
> 2026-07-26 기준. 대상: `@parkagent/lens-calib` + SettingAgent 웹(포트 **13020**).

---

## 0. 지금 무엇이 되고, 무엇이 아직인지 (솔직하게)

| 기능 | 상태 | 실행 위치 |
|---|---|---|
| **마우스 클릭 → 그 지점 센터링** | ✅ **웹에서 이미 됨** | 브라우저 스트림 화면 클릭 |
| **보정표(게인) 검증·생성** | ✅ 됨 (현재는 **명령줄 도구**) | 터미널 `realLensVerify.ts` |
| 클릭에 **보정표 적용**(정확도 향상) | ✅ 됨 (**기본 꺼짐**, 파일로 켬) | `data/lens_calibration.json` |
| 곡면율(방사왜곡) 표 | ⚠️ 실측상 이 PTZ에선 **채택 안 됨**(§6) | — |
| 캘리브레이션 **웹 버튼** | ❌ 아직 없음(다음 단계) | — |

> **핵심**: "클릭해서 쓰는 것"은 **웹에서 바로** 되고, "표 만드는 것"은 **지금은 터미널 명령**이다.
> 표를 켜기 전에도 클릭 센터링은 동작한다 — 표는 그 **정확도를 올려줄** 뿐이다.

## 1. 준비 (5분)

### 1-1. 무엇이 필요한가
- 휴컴스 PTZ 카메라 1대 (네트워크 연결). 이 문서 예시는 `192.168.0.154`.
- 카메라 **자격증명**(아이디/비밀번호). `SettingAgent/config/tools.config.json` 의
  `cameraSources[]` 에 카메라별로 들어 있다.
- **밝을 때 · 무늬가 있는 쪽**(차량·주차선)을 향하게. 하늘·빈 아스팔트·야간은 측정이 실패한다
  (도구가 이유를 알려준다 — 실패를 성공으로 위장하지 않는다).

### 1-2. 카메라가 다른 곳에서 쓰이고 있지 않은지 확인
캘리브레이션은 카메라를 **물리적으로 움직인다.** 다른 사람이 같은 카메라를 조작 중이면 측정이
오염된다(실제로 그런 일이 있었다 — §7). 나 혼자 쓰는 카메라로 하라.

## 2. 표 만들기 — 3단계 (터미널)

작업 폴더는 `SettingAgent/` 이고, 실행 도구는 `realLensVerify.ts` 다. **어느 카메라를 쓸지는
`CAM` 으로 지정**한다 — 그러면 `config/tools.config.json` 에서 그 카메라의 호스트·아이디·비밀번호를
자동으로 읽는다(직접 타이핑하지 않는다. 오타·잘못된 카메라 접속 방지).

> ⚠️ **두 가지 함정**
> 1. **셸 문법**: PowerShell 에서 `MODE=verify npx ...` 는 `is not recognized` 오류가 난다 —
>    인라인 접두사는 **bash 전용**이다. PowerShell 은 `$env:MODE='verify'; npx ...` 형식.
> 2. **카메라 지정 필수**: `CAM`(또는 `CAM_HOST`)을 **매 세션 안 주면 도구가 실행을 거부**한다.
>    예전엔 기본값(153)으로 조용히 접속했는데, 153 이 다른 곳에서 쓰이면 충돌한다(§7). 이제 막았다.

**PowerShell (Windows 기본)**
```powershell
cd SettingAgent
$env:CAM='real-camera-2'      # config 에서 host·자격증명 자동 로드
```

**bash / Git Bash**
```bash
cd SettingAgent
export CAM=real-camera-2
```

> 카메라 이름(`real-camera-2` 등)은 `config/tools.config.json` 의 `cameraSources[].id` 다.
> `CAM` 없이 실행하면 사용 가능한 카메라 목록을 보여준다. config 에 없는 임시 장비면
> `CAM_HOST`/`CAM_USER`/`CAM_PASS` 로 직접 줄 수도 있다.

### ① 접속·화면 상태만 확인 (카메라 안 움직임)

```bash
npx tsx realLensVerify.ts        # 두 셸 공통 (CAM 은 위에서 이미 지정)
```

이렇게 나오면 정상:
```
실카 192.168.0.154 접속 OK · PTZ pan=33375 tilt=624 zoom=14073 · 스냅샷 1920x1080
  프레임 평균밝기 100/255 · RMS대비 49.7
```
- **평균밝기**가 너무 낮으면(야간) 측정이 고배율부터 실패한다.
- **RMS대비**가 20 미만이면 무늬가 부족하다 — 카메라를 차량·주차선 쪽으로 돌려라.

### ② 검증 — 내장 표가 이 카메라에 맞나 (약 3분, 카메라 움직임)

**PowerShell**
```powershell
$env:CAM='real-camera-2'; $env:MODE='verify'; npx tsx realLensVerify.ts
```

**bash / Git Bash**
```bash
CAM=real-camera-2 MODE=verify npx tsx realLensVerify.ts
```

결과 예(실측):
```
판정: pass · 최악 잔차 2.4px · 대응 17/18
   zoom   잔차(px)  적용게인  필요게인
       0      0.8    0.988     0.99
    8000      2.4     1.11    1.104
   16384      1.7    0.765    0.768
```

- **`판정: pass`** = 내장 프리셋(`cam-001`)이 이 개체에도 맞는다. **여기서 끝내도 된다.**
  적용게인과 필요게인이 거의 같으면(위처럼) 새 표를 만들 필요가 없다.
- `판정: fail` = 이 개체는 다른 값이 필요하다 → 아래 ③.
- `판정: incomplete` = 측정 실패한 줌이 있다(어둡거나 무늬 없음) → 밝을 때·무늬 쪽에서 재시도.
  **incomplete 는 합격이 아니다.**

> **잔차(px)** 는 "화면 1/4 지점을 클릭했을 때 몇 픽셀 빗나가나". **10px 이하면 사람 눈엔 정확.**

### ③ (검증이 fail 일 때만) 전체 표 만들기

현재 도구는 검증(verify)까지 자동이고, **전체 생성/저장은 표를 파일로 옮기는 수동 단계**다.
- 대부분의 경우 ②에서 `pass` 가 나오므로 **내장 프리셋을 그대로 쓰면 된다**(§3).
- 정말 개체 전용 표가 필요하면 담당자에게 요청하라(전체 스윕 20분 + 저장 로직 연결이 필요하다).

## 3. 표 켜기 — 클릭 보정을 실제로 적용 (기본은 꺼져 있음)

표를 만들어도 **기본은 꺼져 있다.** 켜야 클릭 조준에 반영된다. 이유: 검증(pass)을 사람이 눈으로
확인하고 켜는 것이 안전하기 때문이다(안 맞는 표를 자동으로 걸면 오히려 오차가 커진다).

### 3-1. 보정 파일 작성

`SettingAgent/data/lens_calibration.json` 을 만든다(없으면 새로).

```jsonc
{
  "cameras": [
    {
      "camIdx": 1,               // 이 카메라의 번호(1-based)
      "host": "192.168.0.154",   // 참고용(기록)
      "model": "cam-001",        // 내장 프리셋을 그대로 씀(검증 pass 였으므로)
      "enabled": true            // ★ 이 줄이 "켜기". false 나 없으면 보정 안 함
    }
  ]
}
```

> - 검증 `pass` 였으면 위처럼 `"model": "cam-001"` 한 줄이면 된다(내장 표 재사용).
> - 개체 전용 표를 만들었다면 `model` 대신 `zoomHfov`·`centeringGain` 배열을 직접 넣는다.
> - `enabled` 를 `false` 로 두거나 파일을 지우면 **즉시 보정 꺼짐**(원래 동작으로 복귀).

### 3-2. 배선 (담당 개발자, 한 줄 — 최초 1회)

`src/viewer/sourceRegistry.ts` 의 실카 생성부에서 보정기를 주입한다:

```ts
import { loadLensCorrector } from '../calibrate/lensCorrection.js';

// 실카(hucoms) 소스를 만들 때:
new RealPtzSource(
  src, cfg.camera.imageTimeoutMs, rtspAdapter(src, cfg.cameraStreaming),
  {},                                                   // settle 옵션(기본)
  loadLensCorrector('data/lens_calibration.json', camIdx),  // ★ 이 인자 하나 추가
);
```

- 이 인자를 안 주면 **기본 무보정**(지금과 동일). 그래서 배선 전/후 기존 동작이 100% 같다.
- 배선 후에도 `enabled:true` 인 카메라에만 실제로 보정이 걸린다.

### 3-3. 서버 재시작

```bash
cd SettingAgent
npm run dev        # 또는 운영이면 pm2 restart 등
```

## 4. 클릭해서 쓰기 (웹) — 이게 최종 목적

1. 브라우저에서 **`http://<서버IP>:13020/`** 열기 (SettingAgent 웹).
2. 좌측에서 **카메라·소스 선택**(실카를 보고 있어야 실카가 움직인다).
3. 라이브 영상 위에서 **가고 싶은 지점을 마우스로 클릭** → **버튼을 떼는 순간(mouseup)** 그 지점이
   화면 중앙으로 온다.

내부 흐름(참고):
```
화면 클릭(정규화 0~1)  →  POST /calibrate/point
   → RealPtzSource.centerOnPoint
      → [보정 켜져 있으면] 클릭좌표 → undistort → ×게인 → 픽셀
      → 카메라 setcenter (ptz_centering)  → 그 지점이 중앙으로
```

- **보정이 꺼져 있어도 클릭 센터링은 된다.** 켜면 화면 **가장자리**를 클릭했을 때 특히 더 정확해진다
  (가운데 근처는 원래도 잘 맞는다).
- 드래그로 네모를 그리면 **박스 줌**(그 영역으로 확대)도 된다.

> 시뮬레이터 소스에는 보정을 걸지 않는다 — 시뮬은 이미 자기 표대로 정확해서 걸면 오히려 틀어진다.

## 5. 잘 안 될 때 (증상 → 처방)

| 증상 | 원인 | 처방 |
|---|---|---|
| `판정: incomplete` | 어둡거나 무늬 없음 | 밝을 때, 차량·주차선 쪽으로 카메라를 두고 재시도 |
| `측정 실패 — …너무 어둡고…` | 야간·저조도 | 낮에 다시 |
| `측정 실패 — …무늬가 없고…` | 하늘·빈 아스팔트 | 무늬 있는 방향으로 |
| `fetch failed` 반복 | 카메라를 다른 곳에서 동시 제어 | 그 카메라 점유 해제 후 단독으로 |
| 클릭해도 안 움직임 | 시뮬 소스를 보고 있음 / 소스 미선택 | 좌측에서 실카 소스 선택 |
| 401 Unauthorized | 자격증명 틀림 | `CAM_USER`/`CAM_PASS` 확인(카메라마다 다를 수 있음) |
| 켰는데 더 부정확 | 그 개체에 안 맞는 표 | 먼저 `MODE=verify` 로 `pass` 확인 후 켜라 |

## 6. 곡면율(방사왜곡) 표는 왜 안 켜나

이 컴포넌트는 곡면율 축도 잴 수 있지만(`MODE=distortion`), **실측 결과 이 PTZ 에서는 채택되지
않았다.** 회전-광류 측정이 카메라의 **팬축·광학중심 오프셋 시차**에 교란되어(와이드에서 큼), 순수
렌즈 왜곡을 분리하지 못했다. 컴포넌트가 A/B 검증에서 **스스로 "reject"** 를 냈다(안 맞는 표를
자동으로 켜지 않는 안전장치가 작동한 것). 그래서 **게인 보정까지만 쓰는 것이 현재 권장**이다.
자세한 내용: `SettingAgent/docs/20260725_123605_광각렌즈_곡면율_캘리브레이션_구현.md` §8.

## 7. 안전 수칙 (꼭)

- 캘리브레이션은 카메라를 **크게 움직인다.** 운영 중인 카메라·다른 사람이 쓰는 카메라로 하지 마라.
- 도구는 끝나거나 실패·중단돼도 **원래 PTZ 로 되돌린다.** 다만 도중에 남이 조작하면 그 복귀도 어긋난다.
- 표를 켠 뒤 **반드시 다시 `MODE=verify`** 로 잔차가 실제로 줄었는지 확인하라.
- 되돌리기: `data/lens_calibration.json` 의 `enabled` 를 `false` 로 하거나 파일을 지우면 즉시 원복.

## 부록. 명령 요약

**PowerShell (Windows)**
```powershell
cd SettingAgent
$env:CAM='real-camera-2'                           # config 에서 host·자격증명 자동 로드

npx tsx realLensVerify.ts                          # ① 접속 확인(안 움직임)

$env:MODE=''                                       # 모드 해제(다시 ①만 하려면)
```

**bash / Git Bash**
```bash
cd SettingAgent
export CAM=real-camera-2                    # config 에서 host·자격증명 자동 로드

npx tsx realLensVerify.ts                   # ① 접속 확인(안 움직임)
MODE=verify     npx tsx realLensVerify.ts   # ② 검증 3분 — pass 면 끝
MODE=distortion npx tsx realLensVerify.ts   # (참고) 곡면율 스윕 — 현재 reject
```

③ 켜기: data/lens_calibration.json 에 {camIdx, model:"cam-001", enabled:true}
④ 웹:  http://<서버IP>:13020/ 에서 영상 클릭 → 그 지점이 중앙으로
